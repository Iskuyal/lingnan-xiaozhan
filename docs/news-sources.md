#### 模板与校园动态不同构（关键结论）

实测 `/tw/djxf/tqsd` 的列表与文章页，**不能复用现有解析规则**：

| 位置 | 校园动态（现有解析器） | 通知公告（实测） |
| --- | --- | --- |
| 列表容器 | `<ul class="list list-intro">` | `<ul class="newsList">` |
| 条目标题 | `<div class="title">` 下 `<a class="tit" href title>` | `<li>` 直挂 `<a href title>`，**无 `a.tit`**；`title` 形如「标题：… 点击数：… 发表时间：…」 |
| 条目日期 | `<div class="con">` 下 `<span class="date">` | `<li>` 直挂 `<span class="date">` |
| 文章标题 | `<h1 class="title">` | `<h2 class="title">` |
| 文章元信息 | `div.article-hd > div.meta` 的「发布时间：」，回退 `name="PubDate"` | `<div class="property"><span>发布时间：…</span>`，**无 PubDate 回退** |
| 正文容器 | `<div class="article-content"> … <div class="article-fd">` | `<div class="printArea" data-power-area='content'>` |

实测样本：列表页 `/tw/djxf/tqsd`，文章页 `/tw/djxf/tqsd/content_32355`（2026-09-18）。两站同属一套站群 CMS（页面含 `data-power-*` 属性），分页写法与页脚「共 N 条 / 共 M 页」一致。

据此，Ticket 04 若要纳入团委通知公告，**需新增一套列表与正文解析规则及对应测试**，而不是改一个栏目 URL。

#### 解析实现与实测结果（2026-09-18，Ticket 04）

已实现：`cloudfunctions/newsSync/parse.ts` 的 `parseAnnouncementList` / `parseAnnouncementArticle`，由栏目记录的 `NewsTemplate`（`xyxw` / `newsList`）经 `parseList` / `parseArticle` 分派；真实片段 fixture 为 `tests/fixtures/news/tw-list-page-1.html` 与 `tw-article-32355.html`（均带来源 URL 与抓取日期注释），测试见 `tests/news.test.cjs`。

对当日抓取的原始页面跑编译后的解析模块，实测结果：

- 列表第 1 页 10 条**全部**解析出标题与日期，日期区间 2026-09-18 ~ 2026-03-06，与 page 页脚「共155条信息/共16页」吻合；条目 ID 为 `content_<数字>`。
- 标题取 `<a title>` 中「标题：」之后、「点击数：」之前的部分（该属性实测为「标题：… 点击数：… 发表时间：…」三段）；日期优先 `li` 直挂的 `span.date`，该节点缺失时才用 `title` 属性里的「发表时间」，且只在该字段内部解析日期（避免标题里的年份被当成日期）。
- 必须**先定位 `ul.newsList` 容器**：侧栏 `ul.menuList`（通知公告 / 焦点新闻 / 外媒报道 / 获奖情况）同样使用 `<li>`；`<li class="split">` 这类分隔条没有锚点，被跳过。
- 文章页 `/tw/djxf/tqsd/content_32355`：`h2.title` 标题、`div.property` 内的「发布时间：2026-09-18 17:48:25」、`div.printArea` 正文 26 段。正文容器里混着整段脚本、`div.property` 与 `h2.title`，因此先按右边界（`div.userControl` / `div#relativeInfo` / `</article>`）截断，再剔脚本与这两个块；结尾署名只有「终审：团委」一行，按既有的尾部署名规则剥离。
- 正文大量用 `<span>`/`<font>` 按字形切分文字（例如把「2026」拆成 `<span>202</span><span>6</span>`）：剥离行内标签时**删除而不替换空格**，否则会写出「202 6 年 9 月」。这条规则对校园动态模板同样生效。
- 该模板**没有** `<meta name="PubDate">`，日期只认 `div.property` 里的「发布时间」（容器缺失时才退回整页搜索同一文案），不引入页面以外的来源。
- 已知形态差异（不视为解析问题）：通知公告正文常以居中重复的标题开头（公文版式），详情页会同时显示标题与正文首段；解析按真实页面内容保留，不做去重。

## 解析依据（选择器与噪声）

列表页（`/xyxw/xydt`）：

- 条目容器：`<ul class="list list-intro">`，每条为其中的一个 `<li>`。整页 `class="tit"` 出现 51 次，其中只有 10 次在列表容器内；顶部导航 `div.topLink` 也用 `<a class="tit">`（含 `href="/xxgkw/xyjs/xxzcjzd/content_17924"` 这种同样形如 `content_<ID>` 的链接），因此**必须先定位列表容器再取条目**，否则会把「学院章程」等导航链接当成资讯。
- 标题：条目内 `<div class="title">` 下的 `<a class="tit" href="…" title="…">`；`title` 属性与锚文本实测一致，解析时优先用 `title` 属性、回退到锚文本。
- 日期：条目内 `<div class="con">` 下的 `<span class="date">YYYY-MM-DD</span>`。实测第 1、2、60、120、126 页的条目数与 `span.date` 数量完全相等（10/10/10/10/2），**未发现缺失日期的真实样本**；缺失日期属于容错分支，用裁剪过的真实片段验证，证据见 `tests/news.test.cjs`。

文章页（`/xyxw/xydt/content_<ID>`）：

- 标题：`<article class="article">` 内 `<h1 class="title">`。整页 `class="title"` 出现 8 次（导航下拉 `div.con > div.title`、分享区、页脚二维码说明），`<h1>` 共 2 个（`h1#logo` 与文章 `h1.title`），因此按钮是 `h1.title` 且需注意区分 `h1#logo`。`h1.title` 内含空的 `<div class="sub-title">`，解析时截断该节点。
- 日期：`div.article-hd > div.meta` 内的 `发布时间：YYYY-MM-DD HH:MM:SS`。回退依据：`<meta name="PubDate" content="YYYY-MM-DD HH:MM" />`（实测 7 篇文章均存在且与 `发布时间` 一致）。
- 正文：`<div class="article-content"> … <div class="article-fd">`，边界标记 `article-fd` 后紧跟分享按钮脚本区。另有 `<!-- 正文内容 S -->`、`<!-- 正文内容 E -->` 注释，但 `E` 在 `</article>` 之后、包含脚本，**不适合**作为正文右边界。
- 结构稳定性：抽查 2014/2023/2026 共 9 篇文章，`h1.title`、`div.meta`、`div.article-content`、`div.article-fd` 均恰好各出现 1 次。
- 正文含 `<img>`（图片 URL 为站内相对路径）、`&nbsp;` 实体（实测最多 16 处/篇）。当前只提取纯文本，**不提取图片**：远程图片域名需要在有 AppID 的小程序后台配置 downloadFile 合法域名，当前不具备该条件。
- 编辑署名行：官网在正文 `div.article-content` 末尾附一段编辑署名，实测形态为连续的
  `供稿：<部门>` / `初审：<姓名>` / `复审：<姓名>` / `终审：<姓名>`（`content_32118`、`32039`、`31144`、`30930` 等 12 篇），
  个别文章多一行 `摄影：…`（`content_30217`），`content_32039` 的复审行用全角分号写成 `复审；黄雅晴`。
  这些行不是文章内容，出现在详情页会误导读者，解析时按下面的规则剥离（规则写在 `parseArticleParagraphs`）。
- `<title>` 形如 `标题_校园动态_学院新闻_广东岭南职业技术学院`，可作为标题的最终回退，需截掉 `_校园动态_学院新闻_…` 后缀。

### 编辑署名行的剥离规则

- 只剥离**正文尾部连续**的署名行，判定前缀（行首锚定，冒号/分号可用半角或全角）：
  `^(供稿|初审|复审|终审|编辑|责编|摄影|撰稿|排版)[:：;；]`。
- 从最后一个段落向前逐段判断，遇到第一个不匹配的段落就停止：署名行之后若仍有正文，说明这些行属于正文内容，原样保留，不做任何宽松匹配（不按「包含关键词」或「短行」判定，避免误删正文）。
- 全部段落都是署名行时返回空数组；正文因此为空时不抛异常，详情页按「无正文」处理。
- 已知不覆盖的写法：2014 年 `content_4843` 结尾是 `（图/张文波 文/吴丹静）`，与本规则前缀不同，会被当作正文保留（本轮未处理，留待出现更多样本再定）。
- 页面上的图片说明文字段落（例如「中药学新生在药植园AI识别药植」）**保持现状**，不在署名行规则范围内，属于已记录的产品取舍。

## 解析的脆弱点

- 稳定字段：列表条目的 `href` / `title` 属性、`span.date` 文本、文章 `h1.title`、`发布时间` 文本、`div.article-content` 容器，在 2014–2026 的模板中一致。
- 依赖 class 名（`list-intro`、`tit`、`date`、`article-content`、`article-fd`）与「发布时间：」文案；官网改版会让解析返回空值（不抛异常，页面显示空态或缺失提示）。
- 标题回退用 `<title>`「截掉后 3 段下划线分段」；若标题自身含下划线可能被多截。实测第 1 页 51 个 `tit` 标题都不含下划线。
- 标签剥离使用 `<[^>]*>`：属性值里如果出现 `>` 会提前结束标签匹配。抽查 13 个真实页面的属性值，未发现含 `<` 或 `>` 的情况（正文图片的 `alt` 里出现过 Windows 路径，不含尖括号）。
- 日期只识别 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年MM月DD日`；其他写法返回空字符串，页面显示「日期待核实」。实测 126 页列表与 13 篇文章都是 `YYYY-MM-DD`。
- 正文里的 `<img>` 只保留其说明文字段落，图片本身与附件（PDF/Excel）不提取。
- 未处理：相关文章推荐、视频、列表页的「共 N 条 / 共 M 页」分页信息（本轮只解析条目，分页留给 P3-2）。

## 去重键与标识

- 去重键：**原文绝对 URL**（`https://lnc.edu.cn/xyxw/xydt/content_<ID>`）。同一 URL 重复出现时保留首次出现的条目，顺序不变。
- 条目 ID：原文 URL 的最后一段路径（如 `content_32118`），用作页面间传参。同一篇文章在不同栏目/分页下 URL 相同，因此 URL 与 ID 一一对应。

## 学校公众号能否作为第二个数据源（2026-09-18 核查）

负责人提出：官网部门信息可能过时，能否直接查阅学校公众号，取 2025-2026 的信息流。为此做了两轮核查，结论与依据分别见：

- [公众号文章作为资讯数据源的可行性核查](reference/wechat-mp-access-research.md)：抓取与发现通道的实测记录。
- [小程序使用他人公众号内容的规则边界](reference/miniprogram-mp-content-rules.md)：平台规则与合规边界。

结论（要点）：

| 事项 | 结论 |
| --- | --- |
| 枚举某公众号的文章列表 | **做不到。** 无面向第三方的官方接口；搜狗微信索引对匿名访问已失效（学校各号最新条目停在 2023）；Bing/百度/360 零收录；`profile_ext` 已封。唯一可用的「合集」通道需号主自行归类，且学校是否建合集无法从外部判定 |
| 服务端抓单篇正文 | **技术可行**（完整链接 + 浏览器 UA），但 `mp.weixin.qq.com/robots.txt` 为 `Disallow: /`，文章页不在允许路径内 |
| 抓取后入库重排 | **不做。** 平台按侵权处理转载，官方口径为「标明来源不代表原创作者允许其转载」；且 `资讯-信息资讯` 类目只覆盖单一行业，扩展资讯范围涉及许可证 |
| 在小程序内打开原文 | **可以做。** `wx.openOfficialAccountArticle`（基础库 3.4.8+，本项目锁定 3.17.2），文档为「打开任意公众号文章」，需用户点击触发 |

据此决定：**P3 的自动数据源仍只有官网 `lnc.edu.cn`，不把公众号接入自动发现链路。** 公众号若要进入产品，只能走「人工登记链接 → 只存标题/日期/号名 → 用 `wx.openOfficialAccountArticle` 打开原文」，正文不入库；且在实现前需要负责人确认这条产品方向。

同时，本轮抓取证实**官网本身已覆盖 2025-2026 的信息流**：团委各栏目在 2026-03 集中补录了一批 2025 年 11-12 月的推文，2026 年 4-9 月持续更新。部门内容的重编排因此完全可以用官网完成，见 [部门资料来源](departments-sources.md)。
