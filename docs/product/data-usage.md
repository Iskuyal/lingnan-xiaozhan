# 数据使用说明（项目现状与试点待确认项）

核对日期：2026-09-24。适用范围：当前参赛原型的代码与已有验证记录。本页供团队和学校讨论数据边界，**不是已发布的用户隐私政策，也不代表学校已授权、第三方合同已核实或小程序已完成用户告知**。代码版本与部署边界见[当前状态](../status.md)。

## 数据从哪里来、去哪里

| 数据 | 来源与用途 | 当前去向 | 当前保存与删除情况 |
| --- | --- | --- | --- |
| 学校简介、学生组织资料 | 已核实的学校官网公开页面，用于首页和部门展示、部门问答依据 | 简介与部门资料随小程序包提供；来源链接见[学校](sources/school.md)与[部门](sources/departments.md)记录 | 随版本更新；校区、联系方式缺项如实显示。官网可访问不等于取得学校背书或转载授权 |
| 官网资讯 | `newsSync` 抓取选定官网栏目，供资讯列表和详情阅读 | 云数据库 `news_articles` 与同步状态 `sync_state`；页面标来源、日期和原文链接 | 同步与增量逻辑已实现；目标栏目的全量和定时效果待验。内容再利用范围须与校方确认 |
| 个人 Excel 课表 | 学生从微信聊天选择文件，上传后云函数解析为可校对草稿；确认后才保存课程 | 临时文件进入本人哈希路径下的云存储；课程、所属微信 `openid`、学期及课程原文等写入 `timetable_courses` | 解析路径尝试删除临时文件，异常路径另有尽力清理；删除是否成功必须看实际结果，不能承诺绝无残留。可在小程序删课程，但尚无完整账号数据删除流程 |
| 个人课表截图 | 学生拍照或选图，识别成可校对草稿 | 临时云存储 → `ai` 云函数按当前配置做图片内容安全检测 → 第三方模型中转；确认后课程写入 `timetable_courses` | 页面在识别结束或失败时尝试清理上传图；真实截图准确率和端到端保存仍待验。第三方保存期限及处理地区未核实 |
| 课表设置 | 学生填写学期、开学日、总周数和自定义节次时刻 | 云数据库 `timetable_settings`，记录所属 `openid` | 有保存与读取接口；合并后的 `main` 已重新部署且本人设置只读调用成功，真机修改、双账号隔离与完整删除入口仍待验证或实现 |
| AI 问答 | 学生提问；课表助手还把**整份当前课表文字快照**放进提示词，可能含课程名、教师、地点、周次 | 文字经内容安全检测后，由 `ai` 云函数发送到第三方模型中转；模型输出再检测 | `ai_usage_records` 记用户单向摘要、调用元数据、耗时、token、金额与失败分类；`ai_usage_monthly` 记月度汇总及限额窗口。代码未在这两集合写入完整提问或图片，但第三方平台及云日志保留情况未核实 |

个人课表数据由学生自行导入，当前代码不读取教务账号或密码。服务端课程和设置记录使用调用上下文的 `openid` 作为归属；数据库里的 `owner` 为原始 `openid`，临时上传路径只使用其哈希前缀。[课表类型](../../cloudfunctions/timetable/types.ts)、[上传与解析](../../cloudfunctions/timetable/index.ts)、[AI 用量契约](../../cloudfunctions/ai/usage.ts)、[课表助手提示词](../../miniprogram/services/timetable/assistant.ts)是上表依据。

## 对学生和学校必须说清的边界

- 课表截图和课表助手内容会发给**第三方模型中转**。当前文档记录供应方为 CommandCode；实际服务主体、处理地区、留存期限、再训练或转委托条款，需取得并核对供应方书面说明后再形成正式用户告知。不能以“云函数内有密钥”推断学生数据仅留在微信云开发。
- 内容安全适配层默认使用微信接口，也支持第三方或关闭；当前部署配置须在验收时读回，不能只凭代码默认值宣称每次请求都完成了微信检测。
- 学生可以查看和手工删除课程；这**不是**“删除全部个人数据”。课程设置、AI 用量记录、云日志和可能失败的临时文件目前没有统一的用户自助删除与保留期限说明。
- [安全审计](../review/pr-57-security-audit.md)发现的 SEC-01/02 已有[代码整改](../review/security-remediation-2026-09-24.md)；当前云端版本是否包含整改仍待读回与端上验证。代码修复不等于线上已受保护。
- 仓库内的[真实课表测试夹具](../../tests/fixtures/timetable/README.md)包含教师姓名等原始信息。参赛包或向校方分享源码前，须逐份决定脱敏、替换或取得相应使用许可，不能把现有仓库直接视为可公开素材包。
- 公开官网资料应保留来源；使用校名、校徽、正式部门名义、官网正文的再利用方式和试点推广范围，需按校方给出的具体授权记录。校方授权不代替学生个人信息处理所需的告知与选择。[个人信息保护法](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)可作为告知、最小必要和第三方提供问题的核对依据。

## 转为真实学生试点前需形成的材料

1. 明确小程序运营方、学校参与角色、联系人、试点校区与期限；逐项确认学校资料及标识的使用范围。
2. 核实模型中转合同或条款，决定课表助手是否仍需发送整份课表，并写出向用户展示的具体字段、接收方、保存期限及删除方法。
3. 修复 SEC-01/02，验证不同微信号隔离、临时文件清理、课程及设置删除；补用户可见的告知入口与对应设计图。
4. 仅在上述事项有可核查结果后，将本页的事实转成正式隐私文本；在参赛材料中分别写“已完成”和“计划中”。
