# 参赛 AI 主线规划：课程项目答辩陪练（文字版）

日期：2026-09-28。状态：**依据负责人“先合入，再选出符合参赛要求且不易被外部依赖卡住的内容，写入规划”的要求，选定本轮规划主线；尚未实施、未验收。** 先前讨论已由 [PR #71](https://github.com/Iskuyal/wx-match/pull/71) 合入。本文是规划选型，不代表新能力已经进入首版成果，也不直接启动开发、部署或招募学生试点。

2026-09-29 补充：[日常小工具与专升本／实习问答](ai-campus-expansion-2026-09-29.md)作为独立候选纳入规划；其建议编号 P2/P3 不改变本文已选主线或正式 P0–P6 开发阶段。PR #74 已合入内容安全修复，云端部署与复验仍按 V8 单独验收。

## 1. 选定结论

**新增主线选“课程项目答辩陪练”，首段只做文字版、个人练习、短材料、三轮问答和一次针对性重答。**

目标用户是已经有课程小项目、需要向老师或同学讲清作品的学生。用户主动粘贴自己的项目说明，AI 根据材料和回答追问，指出“讲得不清楚、与材料存在差异、还缺什么依据”，学生补充回答后看到前后变化。最终产出是可追溯的练习复盘，不是项目总结代写或自动生成一整篇答辩稿。

选择理由：AI 处理开放式回答、提出有针对性的追问并比较改进；一名学生即可走完流程；不需要学校后台、教师账号、全校知识库、OCR 密钥、向量数据库、语音服务或真实双边市场。复用现有文字模型、内容安全、限流记账和原生微信界面技术。**仍然依赖模型与审核服务可用，不能承诺零外部依赖。**

范围聚焦“项目讲解的完整性与依据”，不作专业资格认证、真实成绩预测，也不因学生尚未写出证据就断言其没有完成项目。真实代码正确性、实训操作安全、项目运行效果均不在首段自动判定范围。

新闻、部门、课表与部门动态 RAG 保留现有功能，不为新主线扩大抓取或改写课表数据。它们是已有底座，不能为了复用而限制选题；新主线也不依赖用户先导入课表。

## 2. 为什么在当下选它

以下为基于本仓库和三人团队约束的工程/产品判断，不是评委打分预测，也不是已经完成的用户研究。

| 候选 | AI 在结果中的作用 | 外部卡点与实现负担 | 本轮结论 |
| --- | --- | --- | --- |
| 通知/海报转课表与行动卡 | 识别和安排有价值，但主要围绕信息整理 | 单周例外、日程模型与冲突处理；与负责人希望摆脱新闻/课表主线的反馈不符 | 保留后续，不选主线 |
| 全学科学习诊断、出题复习 | 个性化反馈强 | 正确答案、学科题库和错因评价需要专业校验，范围容易失控 | 暂缓 |
| 专业实训陪练 | 职业院校特色强 | 需要可靠操作标准、专业复核，图片/语音/设备验收更重 | 暂缓，不用“文字版”掩盖专业标准缺口 |
| 作品全自动审查 | 能直接推动作品修改 | 多文件解析、代码运行或视觉评判成本高，结果正确性难验证 | 缩小为“讲解与依据”的陪练 |
| **课程项目答辩陪练** | **针对回答追问、指出依据缺口、比较重答变化** | **短文字即可；一个学生自带材料；新增有限状态流程和结构化反馈** | **选定本轮规划主线** |
| 失物招领/互助匹配 | 双向匹配直观 | 双边样本、认领、交接与内容治理 | 暂缓 |
| 报障/诉求处理 | 可归纳并推动处理 | 缺少实际处理人员时无法证明解决结果 | 暂缓 |

与泛聊天的区别不是模型名称，而是固定练习流程、逐项反馈依据、前后回答对照和可重复评价。竞品已有教学追问：Anthropic 官方的 [Claude for Education 介绍](https://www.anthropic.com/news/introducing-claude-for-education)描述了引导思考的 Learning mode（2026-09-28 查阅）。因此不能宣称“AI 追问”本身独创；本项目应验证校园课程项目场景的操作成本和练习效果是否改善。

## 4. 首段产品边界

### 必须做

1. **材料卡**：项目名称、解决的问题、本人负责的部分、方案、已完成内容与验证依据。用户可粘贴后按段校对；以原文为依据，不让 AI 自动补写缺项。
2. **三轮文字练习**：围绕“问题与目标”“方案及取舍”“验证与限制”三个维度，每轮一个问题。后续问题可针对前一回答调整，但最多三轮，不做无限对话。
3. **逐项反馈**：显示依据原句、为什么还需要说明、下一次可以补什么；结果只用“已说明 / 需补充 / 与材料待核对”。不输出百分制成绩或通过概率。
4. **一次重答**：学生选一个薄弱项重答，对比旧回答、新回答与新增依据；不把措辞变长当作真实能力提升。
5. **复盘页**：呈现三项结果及未解决事项；用户可主动复制自己的复盘文字。首段不开发云端历史库或长期学习画像。
6. **失败与退出**：模型不可用、审核拒绝、额度不足分别提示；失败不计作学生未掌握，保留当前页面输入供重试或复制；退出前提示本次会话不长期保存。

### 首段明确不做

- 语音识别、TTS、实时打断、数字人、摄像头表情分析。
- 上传 PDF/PPT/Word、图片 OCR、扫描整篇论文、外链抓取或代码执行。
- 全专业知识正确性评审、操作安全认证、学校评分预测、查重或代写完整作业。
- 教师端、学校账号、班级成绩单、公开作品广场、排行榜、多用户协作、订阅推送。
- 课表改动、自动排复习计划、独立向量库或第二套模型供应商。

这些删减是首段实现边界：保留可观察的 AI 反馈过程，同时避免把新服务、新权限和多模态性能变成关键路径。

## 5. 可演示的完整例子

先用团队自编的“校园活动报名小项目”说明作演示素材，并明确标注自编；它只是练习对象，不表示当前仓库已有活动报名功能。首段场景是课程小项目讲解，领域事实只依据提供的材料。

| 步骤 | 学生操作/材料 | 预期产品行为（待实现） |
| --- | --- | --- |
| 准备 | 材料写“有报名表，尚未测试重复提交”；选择本人负责的表单部分 | 展示原文段落编号并让学生确认；不自动改为“防重复已完成” |
| 第 1 轮 | 回答项目为谁解决什么问题 | 指出是否讲清对象与问题；引用回答原句 |
| 第 2 轮 | 回答“我们已经解决了重复报名” | 对照材料提示“与你提供的‘尚未测试’表述需要核对”，追问处理方式或验证依据，不断言学生撒谎 |
| 第 3 轮 | 回答“只测试正常报名，还没测连续点击” | 反馈“已经说明现状，验证依据仍有缺项”，让学生知道缺什么 |
| 重答 | 改为“正常报名已测；重复提交尚未验证，下一步用连续点击和重复请求核对” | 标明表达与材料一致性改善；仍保留“重复提交尚未验证”，不把测试计划算成测试成功 |
| 复盘 | 查看前后回答与三个维度结果 | 展示有依据的变化与剩余问题，不生成虚假的项目成绩 |

该例检验模型是否理解当前回答并跟进，能否区分已完成、未验证和下一步计划。正式效果评估还需覆盖不同材料与不同回答，不能只录这一条成功路径。

## 6. 实现方案与新增成本

### 可复用与必须新增

| 部分 | 当前基础 | 新增工作 |
| --- | --- | --- |
| AI 服务 | `cloudfunctions/ai/` 的文字调用、身份限流、成本记账、失败分类 | 新业务标识 `project-defense`，服务端固定提示纪律、请求/结果结构校验及超长拒绝；名称为规划提议 |
| 客户端 | `miniprogram/services/ai.ts`，既有聊天和错误呈现经验 | 独立陪练页面、材料卡、三轮进度、依据反馈和重答对照，不直接复制无限聊天界面 |
| 数据 | 已有个人身份与日志约束 | 会话只保存在页面内存，首段不新增业务数据库；云端仅保留现有脱敏用量元数据，禁止额外记录材料正文 |
| 评估 | Node 测试、CI、既有模型冒烟记录方式 | 自编材料与答案样本、人工评价表和真实调用记录 |
| 设计 | 已有设计令牌与 HTML → PNG 流程 | 材料、练习、反馈、复盘、失败/退出状态设计图，定稿后才能编码 |

实现仍沿用 [ADR-0001](../adr/0001-native-wechat-typescript.md)。[ADR-0002](../adr/0002-department-activity-rag.md)是部门动态的词面检索，不直接当作项目理解或答辩评判器。短材料整段传入即可，暂不引入通用 RAG。

### 受控流程

状态顺序为“材料确认 → 第 1 题 → 第 2 题 → 第 3 题 → 复盘 → 可选重答一次”。程序控制轮次、重复提交和状态转换，模型只提供当前阶段允许的内容。

- 开始时一次调用生成首题；两次中间调用各返回上一答反馈与下一题；第三题提交后一次调用生成反馈与复盘。**完整三轮基础流程最多 4 次模型调用**，可选重答增加 1 次。无自动重试风暴，重试同样计费。
- 暂定材料最多 2,000 字、每次回答最多 500 字；系统纪律、材料和历史组装后输入总量最多 12,000 字符，结构化输出最多 6,000 字符。均为待 PoC 核验的服务端硬限值，不能仅靠前端或提示词控制，也不能静默截掉用户材料。
- 原文分段编号、回答编号由程序产生。反馈仅能引用当前材料/回答中的编号，引用片段必须能在对应原文匹配；不存在的编号、错配片段或不合法阶段输出都按本次失败处理，不上屏伪反馈。
- 结构校验不能证明推理正确；“引用存在但结论不受支持”仍需人工评价。模型不能把材料中的“忽略规则”等文字当成系统指令；攻击样本纳入测试，但不承诺提示词能消除全部注入风险。
- 业务提示纪律由服务端控制；客户端传来的材料、历史和状态均视为不可信输入，不接受客户端自定义系统提示来覆盖该功能规则。沿用现有入口是否需要扩展字段，在实现票中固定契约；不另开绕过内容安全和记账的模型通路。
- 内容未写出时提示“材料不足/请补充”，不是“项目没有做”。复盘显示本人陈述的事实边界，不声称独立核验实物或代码。

复杂度估计为**中等**，比纯聊天增加状态、依据和评价，但比多模态实训或双边平台少外部依赖。没有完成 PoC 和设计前不承诺天数；排期用以下验收门槛推进。

| G0 基线与样本 | 核对上述关键依赖；团队自有/自编材料；预写三维评价规则 | 新模型通路能完整检测与计费；材料有使用依据；至少两个团队成员可独立判断材料一致性与反馈依据 |
| G1 文字 PoC | 先以脚本实现材料 → 三轮 → 重答的结构化流程，不先做页面 | 用第 9 节固定样本评测；能根据不同回答追问；不靠套话或复述代替反馈 |
| G2 设计 | `docs/design/project-defense/` 下的 HTML 与 PNG，含缺材料、失败、退出、重答等状态 | 依现有约定评审定稿；文字长短、依据展开和一次重答操作可理解 |
| G3 最小纵向实现 | 一名用户从输入到复盘，串起状态、服务端校验、额度与错误处理 | 自动化覆盖可观察行为；模型失败不改变学习结果、不丢当前输入；取消/重置清空会话关联 |
| G4 真实验收 | 固定材料与固定回答真实调用、开发者工具和真机流程、逐例人工评价 | 正常和失败路径可复现，关键评价门槛通过，耗时/成本按实际记录 |
| G5 参赛材料 | a–g 七项说明、约 2–3 分钟主线录屏、成本表、对照实验与边界说明 | Git/云函数版本一致；完成成果与未来计划分开；正式提交仍由负责人组织 |

可建议按内容/评价、工程、设计/验收分工，但本轮不指派真实队员。团队内部样本演练可先做；公开招募学生试点、学校协调和比赛提交不属于自动执行步骤。

**停止与缩减规则**：若经过两轮提示词/契约调整仍不能通过反馈依据与差异追问门槛，先缩到“单题回答 → 依据反馈 → 重答”的同一主线重测，不扩语音、图像或 RAG。单题版仍达不到门槛，就不把新增功能写入省赛已完成成果，保留现有已验证功能交付；不自动切换到另一个大方向。模型链路仍不稳定时可继续做本地契约/设计，但不能用录制输出冒充实时 AI。

## 9. 效果评估与成本口径

### 样本和独立判定

首轮准备 **4 份不同课程小项目短材料**（团队自有且可处理，或明确标注自编），每份预写 3 类回答：有依据的清晰回答、遗漏依据的模糊回答、与材料有差异的回答，共 **12 个基础会话样例**。先写判据再跑模型。另备 6 个异常样例：空材料、超长、缺少依据、无关回答、提示注入、格式/编号非法；模型超时和额度不足用自动化桩测试另覆盖。

再选 4 个薄弱回答测试重答，其中至少一个只润色措辞、不增加依据，必须仍保留缺口；不能只测“所有人都变好”。模型输出不是标准答案，由两位团队成员独立复核引用与结论是否对应，分歧单独记录并裁决。此方法只能评价材料内的一致性与练习反馈，不证明专业水平或长期学习效果。

### 拟定门槛（尚无实测结果）

| 指标 | 首轮继续条件 |
| --- | --- |
| 依据完整性 | 所有展示的编号/引用片段可回指；固定样本中不得捏造材料、回答或已验证结果 |
| 反馈有用性 | 12 个基础会话中至少 10 个同时满足：针对当前回答、指出可解释依据或缺口、给出可执行补充方向；两位评价者核对 |
| 差异追问 | 同一材料的 3 类回答在 4 份材料中均引出相应不同的追问/反馈，不是泛化模板 |
| 重答对比 | 4 个重答样例均正确区分新增依据与纯措辞变化，仍未解决的事项不消失 |
| 工程边界 | 超长、非法结构、未完整检测、无权限/额度与超时均明确失败；不变成负面学习结论或伪成功 |
| 性能 | 先记录每次耗时和失败；建议将文字调用 p95 ≤15 秒作为新主线 PoC 目标，按最近秩法对固定批次统计并注明样本量。没有实测/负责人确认，不覆盖 D1 的原规格关卡 |
| 成本 | 核对真实单价与用量后计算每次调用、完整会话、审核开销；月度仍共用现有 50 元上限，无单独预算扩张 |

12 个基础会话按每个 4 次模型请求计为 48 次，加 4 次重答为 52 次模型调用，不含异常测试与失败重试。**模型调用数不等于审核次数**：输入和输出可能分片，每次调用可消耗多次审核配额。G1 先测一条完整会话的实际审核开销，再决定分日批次；不能把现有文档记录的“每日 100 次”当成能跑 100 次对话。额度按实际服务读回确认，录屏/现场演示优先预留。

与固定检查表和通用 AI 进行同材料、同任务、相近时间预算的比较，尽量使用同一模型排除模型能力差异。通用 AI 对照给予合理的答辩陪练提示，不故意降低对照质量。记录完成步骤、定位依据是否方便、人工判定的有效建议数与完成时间；没有对照优势时如实保留结果，不能以主观“更像 AI”代替创新证据。

## 10. 落地与材料边界

短期触达假设是课程展示/项目答辩前，学生有一次集中准备需求；再次使用的理由是重答、补齐材料或下一次项目练习。真实需求与复用意愿尚未验证，团队测试和自编样例不能当作真实校园用户量。

后续正式发布后可考虑同学转发入口或仅分享无个人材料的练习模板；首段未发布、未实现分享，材料只写设计。运营由团队维护少量通用讲解标准和固定样例，不依赖学校专人录入全校知识。持续成本先用额度控制、短会话和真实计费评估，收费/学校采购均不列为已验证商业模式。

潜在宣传描述为：**“帮助学生把自己的课程项目讲清楚：有依据地追问，看到薄弱项，再练一次。”** 不宣称提高真实成绩、替代教师、验证代码正确或已有获奖效果。
