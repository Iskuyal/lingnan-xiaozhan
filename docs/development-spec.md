# 校园工具微信小程序开发规格

状态：P1 首页与入口、P2 学生部门、P3-1 资讯云端链路已实现并通过开发者工具验收；**课表改为导入制（原教务接入已取消）**，**AI 三个落点已定案**。正式作品名仍待定。

## 目标与用户路径

面向广东岭南职业技术学院普通学生，提供简洁的校园信息和服务入口；学生组织是展示内容的对象，首版不提供组织管理后台。学校公共简介覆盖官网已核实信息，涉及具体部门或课表的校区归属按数据标注，不能将某校区资料当作全校资料。

核心路径依次交付：打开首页了解学校并进入功能 → 查看学生部门（可就部门内容用 AI 追问）→ 阅读官网资讯 → 导入课表（教务系统下载的 Excel，或课表截图）→ 用 AI 查阅与增改课表。每段必须在微信小程序中可演示。

## 框架

使用 [ADR-0001](adr/0001-native-wechat-typescript.md) 定义的原生小程序 + TypeScript/WXML/WXSS；P3 起引入微信云开发。业务内容与页面分离，但不建设通用插件平台或多校平台。

## 功能范围

| 模块 | 本次规划的交付 | 暂不包含 |
| --- | --- | --- |
| 首页 | 学校名称、精简简介、来源说明、学生部门、课表与资讯入口 | 大型宣传轮播、复杂个性推荐 |
| 学生部门 | 列表、详情、职责、可核实联系方式与动态；缺失信息如实显示；**部门问答（AI）** | 部门账号、投稿、招新报名、内部管理 |
| 校园资讯 | 官网学校要闻/校园动态、列表与详情、日期、来源、更新时间 | 学生自由发帖、评论、点赞和消息社交 |
| 课表 | **导入**（教务系统下载的 Excel / 课表截图识别）、周课表、周次切换、课程时间地点；**AI 助手：自然语言查阅与增改** | 成绩查询、选课、缴费等教务扩展；**本人教务账号登录（首版明确不做）** |
| AI | **部门问答**、**课表图片识别（多模态）**、**课表助手的自然语言操控** | 将 AI 编程工具使用算作产品内 AI 能力 |

用户不需绑定教务账号即可浏览公开简介、部门和资讯；课表也不需要绑定教务账号，改为由学生自行导入。

## 首段页面与交互

首页使用短简介和清晰的功能卡片，不依赖校园图片才能完成首段。学校名称使用官网正式名称。首页“学生部门”“我的课表”各自进入独立页面；尚未完成时分别说明资料整理中、课表接入中，能够返回首页，不显示假的账号表单或虚构个人课表。

P1 不添加校园动态列表，留到 P3 完成真实内容链路；不要求先创建微信登录页。暂不引入底部多标签导航，已确定的入口足以满足首段路径。

## 内容与边界

- 学校简介：使用 [来源记录](school-sources.md) 中核实的简述，保留来源 URL 和核查日期。
- 部门内容：仅录入已核实部门，区分组织名称、所属校区、职责、联系方式、动态；不把学校行政部门直接等同学生会部门。没有真实资料时空态可验收，完整部门模块仍未完成。
- 资讯：由服务端读取已选官网栏目，统一提取标题、原文 URL、发布日期、正文；按原文 URL 去重。生产同步初始目标为每天一次，可由维护者手动触发；实际定时配置在 P3 验证。失败保留最后成功的数据并展示更新时间。
- 详情：以小程序自身页面展示清理后的正文，保留来源链接的复制入口；不依赖未经配置的 web-view 外链跳转。
- 课表：统一记录学期、教学周、星期、节次、课程名、教师和地点；具体学校节次、单双周规则以**导入的真实课表样本**为准（Excel 或识别后的截图，用户可校对修正）。
- 数据所有权：公开内容由维护者写入，学生仅读取；**个人课表属本人数据**，只存学生自己导入的内容，服务端按微信身份隔离，不接触教务账号。

首页、部门列表与详情、资讯页面及同步云函数已创建；课表导入与周课表已按本规格实现（云函数 `timetable` + 导入确认页 + 周课表页 + 手工增删改），**05 课表截图识别导入与校对（拍照/相册 → 压缩 → 上传 → `ai` 的 vision → 可编辑确认页）代码与本地测试已完成，两轴复核修复已合入**，**云函数部署与端到端验收待执行**；AI 侧已有云函数 `ai`（Ticket 01，统一模型调用 / 内容安全 / 用量与上限）与客户端封装 `services/ai.ts`，07 部门问答已接入（部门页对话框），**AI 云函数未部署、未配密钥，真实调用未验证**，06 课表助手待实现。

## 教务接入：已明确改为导入制（2026-09-18 负责人决定）

**课表数据来源由「本人教务账号自动获取」改为「学生自行导入」**，导入方式两种：

1. **Excel 导入**：学生先在教务系统下载课表文件，再在小程序里选择该文件导入。
2. **课表截图识别**：学生拍照或上传课表截图，由多模态模型识别成结构化课表，并提供人工校对。

这是一次**显式提出的方案变更**，符合本节原先「手动/文件导入只能作为明确提出的新方案，不能静默代替」的要求。因此：

- **P4-A（教务登录接入可行性调研）不再需要**，从开发计划中移除；不是「未完成」，而是**目标已变更**。
- **P4-B 改名为「课表导入与 AI 助手」**，不再依赖教务接入成功。
- 密码不进入聊天、Git、日志或持久化数据库——这一条继续有效（导入制下压根不接触账号密码）。

### 两个必须在实现前想清楚的约束

**一、小程序不能浏览手机本地文件。** 小程序只能通过 `wx.chooseMessageFile` 从**微信聊天记录**里选文件。所以 Excel 导入的实际路径是：学生在教务系统下载 → 发到微信（如「文件传输助手」）→ 在小程序里从聊天选择。这一步的引导文案必须写清楚，否则用户会以为「选不到文件」是 bug。

**二、截图识别要过内容安全。** 用户上传的图片属 UGC，需过微信的图片内容安全接口；识别结果在入库前应让用户确认，识别错的行要能手工改。

### 已确认：独立手工编辑与失败降级（2026-09-18 负责人确定）

**独立于导入流程的手工新增、修改、删除入口纳入首版**，由 Ticket 03 交付（含保存与用户隔离验收），05、06 复用同入口。因此：

- 05 的识别失败引导 = 重试 + 引导 Excel 导入 + **手工录入兜底**，三者都要可走通。
- 06 的模型不可用降级 = 明确告知、已保存课表仍可查看，并验证 03 的编辑入口可用（不再依赖「引导重新导入」这一条）。
- 03 的验收相应增加新增、修改、删除三项路径与用户隔离。

### 导入文件版式：真实样本与解析策略（2026-09-18）

教务导出的课表是**网格矩阵**，不是一行一课的平表：

- 前几行是元信息（学校、学年学期、院系班级）；表头行是「星期一 … 星期日」；
- 表头之后每行是一个大节，行标为「一~六 / 1-6」，对应起始节次（一 = 1-2 节 … 六 = 11-12 节）；
- 每个（星期 × 大节）单元格的原文形如
  `课程名 学分 教师 [周次]周 起-止节 楼-房间-用途 校区 场地编号`，
  例如 `使用JSP开发Web应用系统 4 ××× [2-6,8-17]周 1-2节 博雅楼-B602-… 清远校区 38`；
- 一格可能有多门课，两种已实测变体：**单换行分隔**（换行前后是不同周次的课）与**空行分隔**（多课同格）。

解析策略：按上述结构识别网格，单元格原文解析出课程名/教师/周次/节次/地点；**识别不出的只标记不猜**，交给导入前确认页由学生裁决；周次不认识、节次倒置越界等都保留原值并标警告，不擅自修复。

真实样本已入库：`tests/fixtures/timetable/` 含 4 份真实教务导出（标准版式、单换行多课、多课同格，以及另一班级样本），Ticket 03 的验收必须用它们跑，不得用手写样例代替。

**解析在云函数侧执行（2026-09-18 负责人确定）**：学生选中的文件先上传到**本人 openid 下的云存储路径**，云函数下载后用 `xlsx` 解析为草稿返回，确认页确认后才写库；解析阶段不写任何课表记录，临时文件随后删除。这样主包不因 SheetJS 增加约 0.9MB（小程序单包上限 2MB），解析器也能用现有 Node 测试框架直接测；代价是导入必须联网。

**课表的存储与隔离**：个人课表只存学生自己导入的内容，**读写都在云函数内按调用上下文的 openid 过滤**，客户端不直连数据库，集合权限取最严格预设。周课表按**节次**展示（如「第 1-2 节」）；样本不给时刻、学校作息表尚未核实，不臆造具体时间。

**来源约束**：解析做法参考负责人提供的既有课表实现，但**仓库、代码与参赛材料中不得出现该项目的名称、标识或字样**，也不得把它的代码整段照搬；本仓库按本规格自行实现。

## AI 功能：已定案（2026-09-18 负责人确定）

模型选型：**DeepSeek V4.1 Flash** 与 **Qwen 3.8 Flash**，走第三方中转（CommandCode），低成本并支持多模态。

首版包含以下三个 AI 落点，与负责人确认的 MVP 及 Ticket 05、06、07 一致：

| 落点 | 形态 | AI 为什么不可替代 |
| --- | --- | --- |
| **部门问答** | 部门选择后进入详情，可就该部门内容追问 | 需要把已核实的部门资料作为依据回答，而非凭空生成 |
| **课表图片识别** | 课表截图 → 结构化课表 | 版式千变万化，规则解析写不完；多模态是唯一务实解 |
| **课表助手** | 自然语言查阅与增改，如「第三节有课吗」「周三加一节课」 | 自然语言 → 结构化查询/变更，是 AI 而非表单 |

**首版不做、后续视需要再添加**：校园诉求与提案的归纳、进度追踪（原候选 B）。这是负责人的显式取舍——候选 B 的证据最强，但首版先交付部门与课表。

实现时必须遵守（这些是硬约束，不是建议）：

- **内容安全**：AI 生成的文字与用户上传的图片都要过内容安全检测，否则审核会被打回。接入方式（2026-09-18 负责人确定）：**以微信官方内容安全接口为主，同时支持接入第三方审核 API（OpenAI 与 Anthropic 两种接口格式）**，实现为可切换的适配层。Ticket 01 先探测未认证状态下微信接口是否可用并记录结论；不可用时切第三方，兜底方案一并写进验收。
- **降级路径**：模型不可用时明确告知，已保存课表仍可查看；独立手工录入与编辑**已确认纳入首版**（见上），06 的降级要验证 03 的编辑入口可用。三类失败提示必须可区分：**「模型不可用或超时」「内容被安全策略拒绝」「额度或配额用尽」**，文案各自独立、不合并成一句。
- **模型不可用于编造**：部门问答必须基于已核实资料作答，资料里没有的要明确说「官网未公布」，这与全项目「不编造」的纪律一致。
- **成本与评估**：记录单价与调用量，**月度成本上限 50 元**，Ticket 01 必须提供累计用量查询，接近阈值时告警或拒绝调用。成功指标采用**分层达标线**：课表截图识别字段准确率 ≥90%，课表问答与部门问答各 10 题 ≥80% 正确，**防幻觉 100%（编造一次即不达标）**，单次响应 ≤2 秒；每条评估记录预期、实际、判定、耗时与成本。

### 微信生态能力（2026-09-18 负责人确定）

首版使用**登录（openid 身份）+ 分享**：课表按微信身份隔离存储，资讯可转发（分享是 Ticket 08 未登录单页模式验收的前提）。**不做订阅消息提醒**，课表展示不使用订阅消息。

## 测试与完成标准

P1 已建立 TypeScript 类型检查、可重复构建和页面行为测试；优先在页面可观察行为、功能服务输出层验证，不测试内部方法调用次数。首页以开发者工具操作记录和截图验收。P3 对真实页面脱敏/公开样本做提取、重复同步和失败保留测试；P4 对周次、单双周、空课表、**导入解析与识别结果校对**测试。

CI 执行当阶段实际存在的检查。命令行构建通过不等同于微信运行通过，模拟数据通过不等同于真实导入样本通过；**课表测试要使用真实的教务导出文件与真实截图**。AppID 和设备可用后，记录微信真机核心流程；P6 必须完成实际体验验证与七项材料。

阶段任务、依赖与分工见 [开发阶段](development-phases.md)。
