# 岭南小栈作品说明

团队 Inlux　广东岭南职业技术学院　C组　3人团队

材料日期 2026年11月17日　版本 latest-20261117　最新代码基于 main

岭南小栈是一款面向在校学生的微信原生校园助手。学生导入并核对课表后，可以查看今天与每周安排，核对班群通知中的调课范围，并围绕目标安排学习。涉及课程写入时先展示提案并等待确认；公开资料保留出处，没有依据的信息明确说明缺失。

本文覆盖项目场景、微信与AI能力、创新点、技术实现、成果、历史说明和落地规划。提交包是本地准备成果，不代表已经完成学校上报或赛事提交。

## a 项目说明

学生日常需要在课表、班群通知和校园网页之间切换。岭南小栈以个人课表为主线，把查看安排和确认改动放在微信内完成。课表由学生自行导入，不要求提供教务系统账号或密码；解析结果先进入草稿，核对后才保存。

四个主入口为今天、课表、学习和校园。今天页显示下一节课与今日安排，未知作息、无课表、今日无课和读取失败分开处理。课表页提供周与日视图、完整12节、课程维护和导入校对。学习页集中目标日、学习计划、项目讲解练习、升学问答与体测参考。校园页提供有来源的学校、部门和资讯内容。

导入路径为：将教务系统导出的Excel发到微信聊天，在小程序选择该文件或上传截图，核对课程名、教师、星期、节次、周次和地点，再确认保存。可以修改任意课程草稿，或放弃本次导入。最终确认前会提示整表替换将覆盖已有课程，包括手工新增和修改。

调课路径为：粘贴通知，核对原文及逐项差异，只对指定周次确认时间或地点变更，保存后查看对应周的变化；在有效窗口内整项撤销。部分成功时只重试未完成项，不重复写入已成功课程。

项目以团队维护校园信息与个人课表的使用背景为出发点，尚无新增真实学生试用样本和量化增长数据，不能据此推断全校需求或学习效果。当前是学生参赛原型，不代表学校正式运营服务。

## b 微信与AI能力说明

| 能力 | 业务作用 | 处理边界 |
| --- | --- | --- |
| 原生页面与文件选择 | 从微信聊天选择Excel、选择或拍摄截图，完成校对和确认 | TypeScript、WXML、WXSS；不代登教务系统 |
| 微信云开发 | 保存本人课程和设置，读取公开资讯，统一调用AI | 课程身份来自微信上下文，不由客户端指定归属 |
| 课表截图识别 | 将图片转为可编辑课程草稿 | 无法识别的字段交给学生校对，草稿不是已保存课表 |
| 助手与通知解析 | 查询课程，生成新增、修改或限定周次提案 | 确认前不写课，范围不明时要求澄清 |
| 部门问答 | 在已收录资料和动态内回答并展示来源 | 不补猜报名时间、联系方式或未收录进度 |
| AI学习约束 | 提取时长、频次、弱项和不可用时段，并附原话 | 学生核对后才规则排程；该落点不发送整份课表 |
| 升学问答与答辩练习 | 有限资料解释、引用核对、三轮作答和一次重答 | 不判断录取资格，不授予学校成绩或能力等级 |

AI减少转录、理解通知和查找资料的负担，但不绕过学生确认。学习计划由模型理解情况，日期、空档和冲突交给确定性规则；换排、保存和重开不重复调用模型。

今日简报、目标日、校历和体测计算属于规则工具，不计作模型能力；使用AI编程工具也不计作产品内AI能力。AI经服务端连接第三方模型与审核服务，不能宣称所有处理都留在微信云开发。统一网关处理限流、内容安全、用量记账和失败分类；内部预算与估算金额不等于服务商结算。

## c 创新点与取舍

通知先落到明确的课程范围。普通聊天回答容易把“仅第11周”混成整学期修改。本项目把通知转为逐项提案，核对周次、时间和地点；服务端一起保存原课、拆课和稳定操作编号。重复请求不重复拆课，撤销前再次核对课程是否被后续修改。

模型理解与排程分开。学生可以说明“每次半小时、周四没空”等情况，模型输出带连续原话依据的约束草稿。学生核对后，规则检查日期、过去时段、课程冲突和时长。无法理解的限制先澄清，不静默放宽；换排继续复用已核对约束。

结果回到后续使用的位置。调课后定位对应周并标记课程，已保存计划在课表中独立列出，不增加正式课程数。练习记录可主动复制已有原答、已返回反馈、复盘和重答；反馈没返回时仍保留原答，不补写不存在的评价。

问答保留资料范围。部门与升学回答展示来源、年份和适用范围，资料不足时说明缺失，无法核对时退回原文。这有助于核查回答，但不能消除所有误答，独立质量和时延仍按真实题集评估。

这些是校园课表与资料场景的具体处理，不作“首创”或优于所有同类产品的宣称。当前没有真实用户对照研究，不能把流程设计直接写成效率提升比例。

## d 技术实现

客户端为微信原生TypeScript、WXML和WXSS，服务端为微信云开发。页面处理输入、校对、状态反馈与导航，业务模块处理课程、日期、约束、引用和练习状态；dist只作生成目录，不作为手工修改入口。

| 模块 | 主要职责 |
| --- | --- |
| timetable云函数 | Excel解析、本人课程和设置读写、限定周次事务、幂等重试与撤销 |
| ai云函数 | 内容审核、模型适配、有限资料检索、输出守门、额度和记账 |
| newsSync云函数 | 同步已配置官网公开栏目，保留来源、日期和同步状态 |
| 客户端规则模块 | 日期、周次、节次、空档、冲突、计划排程与本机保存 |
| 公共导航桥 | 四个真实tab及一次性跨tab意图，不自动发送AI请求 |

限定周次调课沿用课程结构：部分周次改时间或地点时，原课程保留其他周次，拆课只含本次周次；覆盖全部周次时原位修改。课程和重试凭据一起事务保存，服务端按微信身份、原快照和操作编号校验，不接受客户端更换归属。

学习计划先处理带原话的约束，再读取当前课程并规则排程。计划只存本机；目标删除、过期、新课程冲突或无法对应学期时保留快照和提示，不自动重排。普通课程与计划分开展示。

失败按模型不可用、内容拒绝、额度不足和内部错误分别反馈。客户端使旧请求失效；修改通知后，迟到响应不能恢复旧提案。应用通知期间锁定原文和重新识别入口，防止解析与写入交错。

本地需要Node.js 22或以上。完整仓库使用npm ci、npm run typecheck、npm test和npm run docs:check；开发者工具导入构建后的dist。云端能力还需要团队AppID权限、云资源和服务端环境变量，本地构建不等于部署。

参赛源码子包排除真实课表夹具、私人配置、密钥、依赖和缓存。子包独立验证安装、类型与构建；完整1025项回归在仓库执行，不承诺在未附完整tests的子包中复现。

## g 落地规划

近期以稳定使用个人课表为目标，继续验证导入校对、整表替换提醒、限定调课和失败恢复。试点前确认告知、数据接收方、保留期限、删除途径和学校支持范围，不自动招募真实学生。

后续可由团队成员演示，从导入课表这一明确任务进入，观察校对耗时、手工修正、再次使用意愿和失败原因。目标日与计划提供重复使用入口，但当前没有实测转化或留存数据，不预填增长比例。

AI优化应重新冻结未用于修补的新题，分别观察正确性、引用支持、降级、耗时和成本。预算、审核配置和实际账单分别记录，不能通过删除失败样本或放宽口径提升分数。

当前没有验证付费模式。可持续性先从规则工具承担高频读取、减少不必要模型调用、统一额度及维护有限资料范围入手。推广、运营或收费由实际试点、权限和成本结果决定。
