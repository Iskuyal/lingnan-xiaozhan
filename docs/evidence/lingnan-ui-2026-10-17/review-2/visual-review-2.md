# 当前原生界面独立视觉复查

评审版本：`739ca1a5ab81e9c82bbf6795ce7cb2946a5bdf18c3fd2d915703846bc339a426`。

本次使用 `critic-prompt.md` 的固定评审提示，只依据当前 `visual-brief.md`、`manifest.json`、30 张 `screenshots/` 原生静态截图及 8 张 `narrow/` 浏览器布局辅助 PNG。38 张图片均已逐张查看，未读取源码、其他评审或历史产物。

原生截图证据是微信开发者工具的 390×844 模拟器，内容区 390×753，含工具缩放；320×568 的 8 张图是实际渲染树和 WXSS 的 Chrome 排版辅助，不能证明 320px 微信原生布局、原生控件或键盘行为。示例课程、目标日、资讯和反馈按简报识别为夹具，不将示例身份或示例反馈重复本身判成真实业务问题。

1. 总体判断

最强的设计决定：原比例的学校横版校徽、岭南红主操作和纸白正文形成统一的校园资料与日常工具身份，首页以“我的课表”为第一入口，资料页又能保持出处和未知信息的可见性（原生 01、10–17、19–25）。

最关键的不足：高频任务的工作区让位于多层说明和控件，课表首屏只能看到前半天，而材料阅读器在 320px 辅助图中几乎没有首屏正文空间；视觉系统已经一致，信息空间分配仍影响直接完成任务。

3. 改进建议，按用户影响排序

**① P1｜我的课表：把课程内容提前到首屏主体。**

- 观察事实：原生 `02-timetable.png` 中，学期提示、课表设置、周次切换、课程统计、三枚管理按钮、未设作息提示及视图切换共同占据页面上半部；网格从图片约 y=462 开始，首屏只能看到第 1–8 节区域。`03-timetable-right.png` 保留了右端周末，但课程块在横向边缘被截取；`02`、`09c` 的长课程名在很窄的格子里多次换行，地点继续省略。辅助 `02` 呈现相同的空间分配。
- 用户或视觉影响：进入最常用页面后，学生要先越过管理信息，再纵向查晚课、横向查周末；格内标题密度也使“今天上什么”难以快速扫读。已经有“列表”替代入口，这是有价值的保底，当前没有该视图的截图，不能据此确认其完整表现。
- 具体修改：将学期与周次组织成紧凑的一组，把管理、导入、新增收为一个明确的管理入口；把未设作息保留为一行提示加设置入口，将详细解释放入可展开区。保留七天横向查看和列表切换，为网格优先分配高度；课程块优先显示课程名及地点，把“布局示例”等说明留在页面级示例标识和详情中。
- 如何复查：重拍 390px 和 320px 原生的初始课表、右端周末、晚间课程与列表视图；确认初始视口显露更多下午课程，晚课存在性有可见提示，横向移动后节次仍可对照，详情继续保留完整名称和来源。没有作息设置时继续不显示猜测时刻。

**② P1｜练习材料阅读器：减少固定索引对正文空间的挤占。**

- 观察事实：原生 `22-defense-reader.png` 的标题栏下方有 12 个条目按钮，分三行常驻在正文上方；当前定位到 F5 后可见正文卡片，定位意图明确。辅助 `08-defense-reader.png` 在 320×568 的首屏内先呈现标题、三行索引、材料边界提示和底部返回按钮，正文第一张卡片只露出边缘，尚没有可读条目正文。
- 用户或视觉影响：阅读器的核心是核对具体条目，但窄视口中首先看到的是索引和提示，实际核对内容被推离首屏。截图不能证明条目不可滚动或不可到达；这里确认的是可见阅读空间不足。
- 具体修改：把三行常驻按钮改为“当前条目 F5 ＋ 跳转条目”控件，点击后展开索引，选中后收起；保留当前条目编号和标题，使定位反馈明确。材料身份与边界压成简短摘要，完整说明可展开；保留底部返回当前练习入口。
- 如何复查：在 390px 与 320px 微信原生分别打开 F1、F5、最后一条，首屏应同时看见条目标题和一段可核对正文；录制展开索引、跳转、滚动、关闭后的过程，另行检查返回原轮或重答草稿。静态截图只能验正文可见性，不能验草稿保持。

**③ P2｜课程编辑：将两种周次编辑方式和可选外观设置分层。**

- 观察事实：原生 `06-course-weeks.png` 同时显示起止周、全学期／单周／双周／自选四种模式、全选／清空／取奇／取偶四个操作、20 枚周次按钮及合并算法说明。辅助 `03-course-edit.png` 的整页截图高 2155 像素，颜色和迷你课表预览继续位于保存按钮之前；页面说明明确写着起止周和自选周是同一周次的两种改法。
- 用户或视觉影响：普通新增一节课也要穿过全部高级周次与外观控件，用户需要理解两个编辑入口如何共同作用；不连续周次本身应保留，但当前同时展开的呈现增加操作负担。
- 具体修改：默认显示当前周次摘要及模式选择；选择范围时显示起止周，选择自选时显示周次网格和快捷操作，并在切换处明确保留或转换当前选择。将颜色与迷你预览合为默认收起的可选区域，保存留在主要表单之后，避免把外观设置变成每次提交必经内容。
- 如何复查：分别截图并实际走通全学期、范围和不连续周次三个任务，确认任一模式都能看到最终周次摘要；在 390px、320px 原生和键盘展开状态检查保存入口、错误提示和焦点内容。现有静态图没有证明这些编辑行为或校验已经通过。

**④ P2｜部门问答标题行：避免窄屏标题出现单字落行。**

- 观察事实：辅助 `06-department-qa.png` 中，“部门答疑”与中间的资料边界说明、右侧“收起”按钮共享一行，标题显示为“部门答”下一行“疑”。原生 `12-department-qa.png` 在 390px 详情页内的对应标题没有此问题；两图对应不同容器，不能把浏览器现象直接认定为 320px 原生缺陷。
- 用户或视觉影响：关键组件名称被单字拆开，标题的视觉锚点和收起控制的整齐关系被破坏，也暴露出标题行对可用宽度不够稳健。
- 具体修改：标题与收起按钮保持同一行，为标题保留完整短语宽度；把“只依据官网已核实资料回答”移到下一行，作为独立的说明文本。让输入区继续保留独立发送按钮，不用进一步压缩输入文字来补偿标题布局。
- 如何复查：先在同一 320px 辅助图确认完整标题不再单字落行，再取得部门名录页内问答和详情页内问答的 320px 原生截图，并补一张输入键盘展开图；不得用浏览器结果代替平台验证。

4. 总体评分与证据缺口

**整体评分无法判断。** 原定范围包含窄屏，当前 320px 只有 8 个页面／状态的浏览器排版辅助图，尚不足以判断 16 条在用页面在微信原生窄屏的完整表现。当前 390px 原生静态范围加所附 320px 浏览器排版的**局部暂评分为 7.7 / 10**：校园身份、任务命名、来源边界和失败恢复入口已经成熟，课表、材料阅读器及周次编辑的空间分配仍有能直接定位的改善余地。

对当前图片中的视觉观察置信度较高，对完整平台体验的置信度中等偏低。明确缺口如下：

- 320px 微信原生截图未取得；浏览器辅助还没有覆盖资讯正文、目标日、校历、体测结果、升学降级、练习反馈／复盘等页面和状态。
- 没有键盘展开、原生选择器及输入校验状态，无法确认输入时的可见区域、遮挡与恢复。
- 部分长页面只见一个原生视口，未见原生课表列表视图、课程保存区域、导入底部保存区域、体测完整结果和练习复盘后续操作；辅助长图只对其覆盖的页面提供排版补充。
- 没有动态片段，不能判断七天横向查看的手势、条目跳转、关闭阅读器后的滚动与草稿保持，也不能从按钮和关键帧推断路由或功能通过。
- 当前为开发者工具与内存夹具；本报告不证明真机、辅助技术、真实云端读写、数据持久化或真实模型反馈质量。

本次未发现能仅凭这些图片确认的流程阻断；上述分数和建议是对当前可见设计的判断，不是对交付的批准。
