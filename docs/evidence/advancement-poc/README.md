# 升学 / 实习问答 PoC（Issue #93）

## 结论（先说能不能做）

**条件性 go**：检索与守门这一层，20 道固定题都能回到官方原文、并且能按规则澄清 / 拒答；
但 **模型回答这一层本轮没有验**（内容安全当日配额用尽是硬约束，见「没有测什么」）。
所以：

- ✅ **可以**做「本地演示」：界面只展示**检索到的官方原文段落 + 出处**，加固定话术澄清/拒答，**不接模型**。
- ⛔ **先不要**做「模型作答」的产品化（Issue #94 的对话形态），直到满足两个条件：
  1. 拿到额度后跑完含模型回答的 20 题，逐题人工核对**引用是否支持结论**（本轮只验了「检索到的段落含关键事实」）；
  2. 用一批**没有参与调参**的新题复测 recall 与守门行为。

## 怎么跑

```bash
npm run poc:advancement
```

读 `corpus.json`（4 份官方材料 / 25 个段落，逐字摘录、每段带出处与核查日）与 `questions.json`
（20 道固定题 + 人工确认的标准答案），输出 `report.json` 与终端摘要。**全程本地确定性计算，不调用模型。**

两种策略对比：

| 策略 | 做法 |
| --- | --- |
| A 关键词检索 | 全语料 bigram + idf 打分，取 top-3（相当于「有语料但没有来源约束」） |
| B 来源约束检索 | 先判类别（判不出来就澄清），再按年份校验是否收录，最后只在**该类别**里排序；没有可用来源就拒答 |

## 结果（2026-09-29）

| 指标 | 策略 B（来源约束） | 策略 A（无约束） |
| --- | --- | --- |
| recall@1（13 道答案题） | **1.00** | 1.00 |
| recall@3（13 道答案题） | **1.00** | 1.00 |
| 引用支持结论（答案段含关键事实串） | **1.00** | 不适用 |
| 澄清 / 追问 / 拒答正确（7 道守门题） | **1.00** | **0.00**（它一定会「答」） |
| 平均耗时 | 1 ms | — |
| 模型调用 / 费用 | 0 次 / 0 元 | — |

守门题的 7 道构成：跨类型澄清 2（q14/q15）、类别不明澄清 1（q16）、年份未收录拒答 2（q17/q20）、
语料不含的数据拒答 2（q18 分数线、q19 实时岗位）。

**策略 A 在守门题上的表现是 0**：它没有澄清/拒答能力，7 道题全部给了一个「最相关段落」。
这就是「来源约束」要解决的问题，也是本票要证明的第一件事。

## 必须说清楚的局限（别把 1.00 当成真实水平）

1. **这 1.00 是在评测集上调参调出来的**：类别判定与守门规则是按同一批 20 道题反复改到全对的，
   属于在测试集上过拟合。换一批没见过的题，recall 与守门正确率都会下降。
2. **语料只有 25 个段落**：规模远小于真实语料，检索难度被显著低估。
3. **两种策略的 recall 相同**不代表等价：差别在守门题（上表最后两行）。
4. 报告 JSON 里 `limitations` 字段记录了同样这四条，改脚本时会一并更新。

## 没有测什么

| 项目 | 为什么没测 |
| --- | --- |
| **模型回答与引用摘录** | 内容安全检测有日配额（未上线小程序 100 次/天），本次运行期间已用尽且配额**不是按自然日 0 点重置**；没有额度就无法端到端跑「模型照着检索结果回答」 |
| 逐题「引用是否支持结论」的人工核对 | 依赖上一项：没有模型回答就没有可核对的结论 |
| 逐次调用耗时与费用 | 同上（本次只有本地检索耗时） |
| 学生真实提问分布 | 20 题是按验收要求设计的固定题，不代表真实分布 |
| 中高职贯通三二分段 | 与本校学生无关，已在来源目录里明确不收录 |
