## G1 怎么用这个包

1. 两份事实卡（`FC-1`、`FC-2`）**整体**作为项目说明给模型，用 `sources.json` 的 `evidenceMap` 追溯每条依据。
2. 两个问题：`samples-development.json` 的 `question`（课表流程）、`samples-heldout.json` 的 `question`（限制与介绍重点）。
3. 6 个开发样例与 2 个留出样例分别送评；**留出样例首次结果单列**，不并入开发样例通过率、不用于调参。
4. 逐例按 `rubric.md` 记录：引用核对、是否对应回答、追问针对性、待验证是否被保留、越界断言数、引用支持率、原始响应、判定。
5. 预算与失败处理按 `budget.md`。额度不清时只交付离线部分，并把真实评测如实记为未完成。

## 事实与依据

- `FC-1` 每条事实的仓库路径见 `sources.json` 的 `evidenceMap`；状态区分**已完成**（有代码或测试支撑）、**待验证**、**待核实**。
- `FC-1` 的「已完成」**不等于真机通过**：最近一次验收记录 `realDevice: false`（模拟器）。
- `FC-2` 无仓库证据，`D7`/`D8` 是**故意保留的未测试边界**；本包不用来声称已实现。

3. **F8-3 临时文件极端残留**：上传成功后小程序被直接杀死时可能残留，此时确认页「临时文件已删除」文案不成立。

5. **F9 三处文档与仓库现状不一致**（已独立复核，均待核实，不判定哪一方正确）：
   - `docs/evidence/p4-b/README.md` 记依赖 `xlsx@0.18.5`，而 root 与云函数 `package.json`、`parse.ts` 均为 **0.20.3**；
   - `docs/evidence/cloud-recheck/README.md` 称导入页「没有存在性兜底」，而 `miniprogram/pages/timetable/import/index.ts:174` 就是该兜底且有测试覆盖；

8. **留出样例只有 2 个**：按阶段方案的首批规模执行，样本量不足以支撑任何泛化结论。

## 离线校验

校验脚本：`node scripts/check-defense-g0.mjs`（不触网、不调用模型）。

检查项：事实卡与样例的 id 唯一性、`cardId` 与事实卡对应、可引用原句以存在的条目 id 开头且属于本卡、6 个开发样例 + 2 个留出样例的数量、留出样例 `tuningAllowed: false`、回答正文互不重复、`mustPreserveUnverified` 非空且非占位、冻结日期一致、正文字数上限。

**正文长度口径（重要）**：`<=1200` 按**可见正文字符**计，即去掉空白、Markdown 表格分隔符与强调标记后的字数。表格排版符号不计入内容，否则排版本身会顶掉正文额度。当前结果：`FC-1` **1117** 字、`FC-2` **668** 字。

**未引用条目警告是有意保留的**，共 4 条：`INV-1`、`INV-3`（材料性质声明，不是可引用的答辩依据）、`F9`（G0 自检发现，供维护者核对，不要求学生回答）、`D1`（FC-2 的目标陈述，无对应追问价值）。其余条目均被至少一个样例引用。这些不算验收失败，但已在下方 go/no-go 中记录。

## G0 go/no-go

**结论：G0 通过，可进入 G1**，同时带以下限定：

| 检查项 | 结果 |
| --- | --- |
| 每条事实有依据或显式「待验证」/「待核实」 | 通过 |
| 引用 id 正确（校验脚本 0 错误） | 通过 |
| 自编材料不冒充真实学生 / 不冒充已有功能 | 通过（`FC-2` 标 `isFiction: true`） |
| 另一执行者可复查 | 通过（文件、冻结日期、判定理由、依据映射齐备） |
| 材料长度合规 | 通过（FC-1 1117 字、FC-2 668 字，上限 1200） |
| 首版不复制 MIT OCW 内容与品牌图片 | 通过（零复制） |
| 异常样例要求（空 / 超长 / 无关 / 注入） | 要求已写入 [abnormal-cases.md](abnormal-cases.md)；**样例与首次结果未完成**，须在 G1 补齐 |
| 真实模型可行 | **未完成**——G0 不做真实调用，G1 待配额与执行 |

**不得据此声称**：新功能已上线、真实学生效果已达标、教师已认可、教师评价已获得。这些都没有证据。
