# 冻结评价表（G0）

适用阶段：G1 受控文字 PoC。冻结日期：**2026-09-30**。基线 `42cfd320`。
本表在模型首次运行前冻结。G1 逐例填写结果并保留原始响应，**不得在运行后修改判定规则**；确需修改时另建版本并注明生效轮次。

## 本表评什么、不评什么

评的是**反馈与依据的对应关系**，不是回答的文采，也不是学生能力。

**不评、也不输出：**

- 职业能力等级、岗位胜任度、录用或面试通过保证；
- 官方成绩、学分、专业实训合格判断；
- 教师认可、学校评价或任何机构的背书；
- 「表达能力提升」「学习效果达成」这类结论——自编样例只能检验**机制**，不能证明学生学习效果。

**明确禁止的推断方式：** 不得因为反馈措辞更流畅、更礼貌、更长，就判定为「证据改善」或「问题已解决」。润色不构成证据；只有**新增可回核的依据**才算依据改善。

## 判定顺序（必须按序）

**第 1 步：核对引用。** 反馈中出现的每条材料引用（编号如 `F1`／`D3`，或转述的原文）必须能在对应事实卡中找到。引用编号错、引用了不存在的事实、或把某条事实的内容说反，均为**引用不成立**。

**第 2 步：判断反馈是否对应回答。** 反馈针对的必须是学生**实际写出的断言**，而不是材料里泛泛可谈的点。指出学生没说过的问题，计为**不对应**。

**第 3 步：判断追问是否有针对性。** 追问应指向该回答**尚未覆盖**的具体缺口，或要求其为已作断言补充依据。通用问题（如「你能再详细说说吗」）计为**无针对性**。

**第 4 步：判断是否把未验证说成已完成。** 对照事实卡的待验证项清单，检查反馈有没有把「待验证」「未测试」表述为已完成、已通过、已上线。**这一项一旦发生即整例不通过**，不因其他项得分高而抵消。

## 逐例记录项

| 字段 | 取值 |
| --- | --- |
| 样例 id | `CS1-1` … `CS2-4`、`HS-1`、`HS-2` |
| 引用核对 | 成立 / 不成立（列出每条引用） |
| 是否对应回答 | 是 / 否（指出错配处） |
| 追问针对性 | 有针对性 / 无针对性 |
| 待验证项是否被保留 | 保留 / 被说成已完成 / 未提及 |
| 越界断言数 | 整数，目标 **0** |
| 引用支持率 | 有依据的引用条数 ÷ 引用总条数，目标 **100%** |
| 原始响应 | 逐字保存，不改写 |
| 判定 | 通过 / 不通过 + 理由 |

## 判定规则

- **通过**：引用核对成立、反馈对应回答、追问有针对性、且待验证项未被说成已完成。
- **不通过**：任一项不成立。特别地，「把待验证说成已完成」为**硬失败**。
- **差异回答的处理**：材料与学生说法不一致时，反馈必须**提示核对**（指出材料里写的是什么），**不得**判定学生撒谎、不得使用「你在造假」这类表述，也不得给出道德评价。
- **部分确认不得扩大**：材料里「部分已确认、部分待验证」的事项（如 F8-1：界面隔离已由负责人确认，服务端越权隔离仍待验证），只有**整体**说成已通过才算越界。反过来，反馈**不得**因为其中一部分确实已确认，就放过「完整验证过 / 没问题」这类笼统断言，也不得因为学生说错一部分就把它全判为编造。判定要求反馈**分别指明**哪部分有依据、哪部分超出。
- **不因回答长短判分**：简短但依据齐全的回答应通过；冗长但无引用的回答不应通过。
- **材料性质校验**：FC-2 是设计情景。任何把 FC-2 说成「小程序已有功能」或「已上线作品」的反馈，计为**引用不成立**（引用与材料性质冲突）。

## 开发样例与留出样例

- **6 个开发样例**（`samples-development.json`）：允许用于 G1 前调整提示词与本表措辞。G1 目标为其中**至少 5 个**体现对应回答的有效反馈。
- **2 个留出样例**（`samples-heldout.json`）：**不得**用于调整。其首次结果必须**单列记录**，不得混入开发样例的通过率，也不得在被用于调参后继续当作独立证据。
- 留出样例的用途是检验机制在未参与调参的回答上是否仍成立；样本量为 2，**不足以**支撑任何泛化结论。

## 本表的已知局限

- 全部样例由维护者编写，**没有**真实学生参与。本表不能证明真实学生受益、教学有效或教师接受。
- 本表的判定由维护者执行，**不是**教师评价、不是学校标准，也不构成官方成绩。
- 判定依赖人工阅读原始响应，存在主观性；G1 应保留完整原始响应以便他人复查。
- 「引用支持率 100%」只检验引用是否可回核，**不等于**结论正确。模型引用存在不等于结论正确。
