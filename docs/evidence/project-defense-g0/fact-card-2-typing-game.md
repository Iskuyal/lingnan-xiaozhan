## 设计事实表

| id | 设计事实 | 状态 |
| --- | --- | --- |
| D1 | 练习者看到一句提示文本，在输入框里照打；程序实时比对本轮输入与提示文本，结束时给出本轮用时与正确字符数 | 设计 |
| D2 | 状态有三种：`待开始`、`进行中`、`已结束`。第一次键入进入 `进行中` 并开始计时；`已结束` 后输入框只读。**删除键（退格）允许，不单独计错**——这是把「修正」与「打错」分开的明确设计选择 | 设计 |
| D3 | 计时以**第一次键入**为起点，不是页面加载或点击「开始」的时刻。因此「点了开始但没打字」不产生用时 | 设计 |
| D4 | 当本轮输入与提示文本**逐字符相等**时判定完成。**不做大小写宽容，不忽略标点**。完成时展示用时、正确字符数、错误按键次数 | 设计 |
| D5 | 错误按键计数：每当本轮输入相对上一次发生变化、且新输入的最后一个字符与提示文本同位置字符不同时加一。**退格本身不加** | 设计 |
| D6 | 提示文本只允许来自一个**内置短句清单**；**不接受外部粘贴内容**作为提示文本。提示文本为空时按钮禁用，不进入 `进行中` | 设计 |
| D7 | **故意保留的未测试边界**：设计上希望按住一个键不放产生的连续重复输入**只计一次**错误按键，而不是每次重复都计一次。但「按住不放的重复输入」能否可靠区分于「同一键被连续敲多次」，**没有任何验证记录，实现方式也未定** | **未测试** |
| D8 | 其他未测试项：中途刷新或离开页面的行为未定义（是否残留 `进行中` 状态）；移动端软键盘遮挡输入的布局未验证 | **未测试** |
