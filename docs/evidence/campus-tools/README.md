## 本次没有验证到的部分（不勾选）

1. **真机**：全部证据 `realDevice: false`；字号、滚动与剪贴板在真机上的表现未测。
2. **非超级管理员视角的数据维护**：日期表是随包的人工核准数据，页面没有编辑入口，
   因此没有「维护者改一条日期」的路径可验；维护方式是改 `services/calendar/events.ts` 并重新提交。
3. **超过一天的日期推进**：倒计时按脚本独立算的「今天」核对（还有 74 天），没有实际等待跨天。
4. **设计图定稿**：`docs/design/exam-calendar/` 与 `docs/design/fitness-calc/` 仍是「待评审」，
   待拍板项见各自 README 的最后一节；本轮只证明「实现与设计稿的尺寸、状态覆盖一致」。

## 工具坑（本次新增）

- **改 WXML 后模拟器认旧结构**：给长跑提示加 `id="fit-run-hint"` 并 `npm run build` 后，
  模拟器里仍取不到这个 id（要重启开发者工具才生效）。验收脚本因此改成「按类名轮询等元素出现」，
  不依赖新加的 id；这条与 `docs/evidence/goal-days/README.md` 记的「改样式要重启工具」是同一类问题。
- **剪贴板断言要轮询**：点击复制后立刻读 `wx.getClipboardData` 可能读到空值，脚本改成最多三轮重试。
- **别并发开两个自动化客户端**：同一台机器串行跑；另外本次长跑后工具再次出现
  `timeout waiting for automator response`，重启工具即恢复（与 2026-09-25 记录一致）。
