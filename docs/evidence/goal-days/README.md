## 本次没有验证到的部分（不勾选）

1. **原生日期选择器的人机交互**：系统滚轮不在小程序元素树里，自动化点不到。脚本改用
   `page.callMethod('onDateChange', { detail: { value } })` 触发与选择器**同形状**的事件载荷，
   页面处理逻辑与真实选择走同一条分支；但「手指滚动选日期」这一步只能人工点一次。
2. **杀进程重启小程序**：脚本用 `mini.reLaunch` 重新加载页面并重新读本机存储来代表
   「退出重进」。真正杀掉小程序再进入仍是人工步骤（本票要证的是数据来自本机存储，不是内存）。
3. **真机**：全部证据 `realDevice: false`。字体、系统日期选择器样式、存储配额在真机上的表现未测。
4. **跨月 / 跨年 / 闰日的界面表现**：这些在 `tests/goals.test.cjs` 里由确定性测试覆盖
   （含 2028-02-29、跨年、昨天/今天/明天），模拟器里没有顺时间走一遍。

## 工具坑（本次实测，写下来省下一次排查）

- **改 WXSS 后必须重启开发者工具**：只 `npm run build` 不重启，模拟器仍在用上一次编译的样式。
  本次实测：加了 `flex:none` + `max-width` 后重新量测，按钮宽度仍是 161px；重启工具后才变成 61px
  （= 设计值 119rpx）。这与 `docs/evidence/p3-2` 记的「共用模板编译产物被缓存」是同一类问题，
  但这次是**页面自己的 WXSS**，所以「改样式就重启」应作为默认动作。
- **原生 `button` 在模拟器里锁 184px 内在宽度与水平 auto 外边距**，页面 WXSS 写的 `width` / `margin`
  不生效（`flex` 相关属性、字号、背景、内边距都正常）。处理办法与课表页一致：
  成对的小按钮改用 `view`（`aria-role="button"`），整宽按钮在 wxml 里写
  `style="display:block;width:100%;max-width:none"`（与首页主入口同一种写法）。
- **不要同时开两个自动化客户端**：`verify-wechat.cjs` 与本脚本并发连接同一个模拟器时，
  页面会被对方的 `reLaunch` 打断，表现为「部门列表未渲染」这类与功能无关的失败。串行跑。
- **长跑后退化**：一次 `verify-wechat` 跑到资讯阶段出现元素取不到（`Cannot read properties of null`），
  单跑同一步骤正常。与 2026-09-25 记录的现象一致，重开工具即恢复。
- **内容安全配额**：本轮 AI 相关检查拿到「内容安全检测的额度已用尽」的降级提示。
  本票不接 AI，不受影响；但同一台机器上跑 AI 相关验收前要先确认当日配额。
