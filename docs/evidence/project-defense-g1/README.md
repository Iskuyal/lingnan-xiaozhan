## 四、脚本与命令

维护者脚本 `scripts/poc-project-defense.cjs`，走**既有** `ai` 云函数的 chat 动作（既有内容安全 / 限流 / 记账链路），**不新建旁路、不直连模型中转**。

| 命令 | 作用 | 花费 |
| --- | --- | --- |
| `npm run poc:defense`（= `--plan [--emit-runs=<file>]`） | 离线装配自检：装配三批请求并逐条守门，写 `runs.json` 骨架 | **0**：不触网、不调用模型、不消耗内容安全配额与个人日额度 |
| `npm run poc:defense:usage`（= `--usage`） | 维护者只读动作读回当月累计 | **0**：服务端只做 `assertAdmin`，不消耗个人日额度、不触发内容安全 |
| `npm run poc:defense:session`（= `--session`） | 完整三轮 + 复盘 + 一次重答（5 次请求） | 真实计费；需 `--allow-spend` |
| `npm run poc:defense:samples`（= `--samples`） | 6 开发样例 + 2 留出样例逐例首评（8 次请求，**同一批**，保证留出首次结果早于任何调参） | 真实计费；需 `--allow-spend` |
| `npm run poc:defense:dev`（= `--samples --set=development`） | 调参后**只重跑开发样例**（6 次请求），不重复消耗留出样例 | 真实计费；需 `--allow-spend` |
| `npm run poc:defense:abnormal`（= `--abnormal`） | `AX-1`…`AX-6`（6 次请求） | 真实计费；需 `--allow-spend` |

**记账用 feature：`defense-practice`**（可用 `--feature=` 覆盖）。不复用 `advancement-qa`——那会触发升学问答的服务端约束与语料检索。

**三重防误花**：① 真实调用必须显式给 `--allow-spend`，否则直接退出；② 真实调用前先跑一次完整离线自检，自检有错就拒绝发起；③ `--max-calls` 上限锁死为每批 12，超过即报错。

调用形状与产品页面一致：`wx.cloud.callFunction({ name: 'ai', data: { action: 'chat', feature: 'defense-practice', system, messages } })`，由**小程序端**触发（控制台 / CLI / HTTP / 云函数互调必然 `-501001`）。自动化桥对单次 `evaluate` 约 10 秒上限，故沿用 `scripts/lib/mini-connect.cjs` + `scripts/eval-advancement-model.cjs` 的**发起后轮询**写法。

## 九、PoC 对 G2 / G3 的结论

**离线契约层：可行。** `ai` 的 `chat` 上限（20000 字 / 20 条 / 单条 8000 字）、内容安全分片规则与失败分类都能在**本地**精确建模并守门，装配结果可重复。G2 可以据此写结构化契约。

**需要改 / 需要在 G3 决策的（本次实测出来的输入）：**

1. **内容安全分片是真正的瓶颈，不是个人日额度。** 全量 19 个请求预计消耗 **约 71 次**检测（未上架期日上限 **100 次**，且与升学问答、10 月 8 日现场演示共用同一份额度）。一次完整评测就吃掉当天约七成。G3 若做多轮会话，必须在页面上做轮次与篇幅预算，或先申请上架把配额放大到 4000/分钟、200 万/天——**否则演示当天按 100 次倒排的余量会被吃掉**。
2. **两把闸互相独立**：个人日额度（服务端 `AI_USER_DAILY_LIMIT`，默认 30/天）与内容安全日配额（微信侧 100/天）分别拦截，先撞哪一个取决于当日其它用途；排障时**先查 `45009`**，不要往模型或密钥方向找。
3. **输入余量看起来大、其实靠"材料只有两份"撑着**：`system` 已占 3848 字（= 纪律 + 两份事实卡），三段式单例输入约 4000 字，带三轮上下文的 `R4` 是 4843 字。一旦 G3 把更多材料或多轮历史带上，会快速逼近 2 万字；客户端既有的 `HISTORY_INPUT_BUDGET = 16000` 自剪规则应直接复用，且**服务端只认总字数**，超窗是 `invalid_request` 而不是截断。
4. **「重答」需要真实学生输入**：G1 只能用同一份冻结回答代替重答（脚本已显式标注）。产品上必须保证重答是学生新写的文本，否则「前后对照」没有意义，也不构成任何效果证据。
5. **四节结构化输出适合做 G3 契约雏形**（引用核对 / 是否对应回答 / 待验证保留 / 追问），但**不能只靠提示词**：引用编号的存在性可以本地机检（脚本已实现 `checkCitations`），「内容说反」「未验证说成已完成」仍需服务端或人工关卡。模型引用存在**不等于**结论正确。
6. **建议把 G1 的样例在用于调参后降级为回归题**：一旦对开发样例改了提示词，它们就不再是未见样本；留出样例的独立性必须留到下一次真实首评。

**不可行的部分：未发现机制层面的不可行。** 但「真实模型可行」这一条**仍未验证**，不能用本次的离线结果替代。
