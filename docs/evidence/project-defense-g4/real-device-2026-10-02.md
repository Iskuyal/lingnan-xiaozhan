## 0. 与清单原计划的差异（如实记）

清单里写的是「本环境无法操作物理设备，需负责人扫码回传」。**这一条已被推翻**：负责人连接真机并开启 USB 调试后，本轮**由执行端用 `adb` 直接驱动真机**走完了全程，负责人只需把手机连上。

关键突破点有两个：

1. **执行端模型支持图像输入后**，可以用 `adb shell screencap` + 读图形成「截图 → 判断 → 点击」的闭环；在此之前 `uiautomator dump` 对微信**和小程序**都只回 1 个节点（微信自绘 UI，不暴露无障碍树），等于蒙眼。
2. **中文输入用剪贴板解决**：`adb shell input text` 只支持 ASCII，而 scrcpy 会把电脑剪贴板同步到手机 ⇒ 电脑 `Set-Clipboard` → 手机上长按输入框 → 点「粘贴」。**三轮 + 重答的中文答案都是这样进去的**，已实测稳定。

## 4. 时延（真机实测）

以提交时刻与反馈上屏截图时刻计（我的等待时间本身是 45–48 秒，所以只能给上界）：

| 轮次 | 提交 | 已看到反馈 | 结论 |
| --- | --- | --- | --- |
| 第 1 轮 | 13:13:46 | 13:14:32 | ≤ 46 秒 |
| 第 2 轮 | 13:15:23 | 13:16:09 | ≤ 46 秒 |
| 第 3 轮 | 13:16:45 | 13:17:30 | ≤ 45 秒 |
| 重答 | 13:18:01 | 13:18:49 | ≤ 48 秒 |

⇒ **真机每轮 ≲45 秒**，与模拟器换第三方审核后的 ≈35 秒同量级，**远高于页面承诺的 12–23 秒**。

### ⚠️ 真机上也印着过期文案

等待态截图明确显示：「**实测需要 12–23 秒**，比普通问答慢」／「**通常 12–23 秒**」，而实际 ≲45 秒。**这不是模拟器特有现象，真机同样如此** ⇒ G2 设计稿与 G5 演示口径都必须改。

## 5.1 真机失败路径（补测，本轮新增）

原记录写「真机只跑成功路径」——**已补**。补测时网络可编程开关（`svc wifi disable` / `svc data disable`，用 `dumpsys connectivity` 确认 `Active default network: none`）。

### ① 断网（**真断网**，不是 mock）——✅ 正确收口

- 关掉 Wi-Fi 与移动数据后提交（460 字回答），**保持断网**：
  失败态文案「**这次没能发出去**」／「**AI 服务响应超时，请稍后重试**。你的回答还在下面，可以直接重试。」
- **460 字回答完整保留**、给「重试这一次核对」入口、**不显示任何半截反馈**。
- 截图：[screenshots/realdevice-06-offline-fail.jpg](screenshots/realdevice-06-offline-fail.jpg)。
- ⚠️ **但要等约 60 秒才出结果**：断网后页面一直停在等待态（实测「已等 50 秒」仍未失败），**没有快速失败**。这与模拟器那次「mock reject → 立刻失败」**不是同一件事**——模拟器测的是 promise 立刻 reject，真断网是等客户端超时。**这一条要记进 G2/G5：断网时学生会盯着「已等 N 秒」看一分钟。**

### ② `citation_unverified`（**意外触发的真实闸门**）——✅ 正确收口

第一次尝试时我在 12 秒后就恢复了网络，请求最终送达服务端，**被服务端引用校验闸门拦下**：

- 文案「**这次反馈没有通过引用核对**」／「服务端发现反馈里的引用对不上材料，已拦下，**不显示半截内容**。你的回答还在，可以重试。」
- 回答完整保留、可重试。
- 截图：[screenshots/realdevice-07-citation-rejected.jpg](screenshots/realdevice-07-citation-rejected.jpg)。
- ⇒ **G3 加的 `verifyDefenseAnswer` 闸门在真机上确实生效**，且前端对它的处理正确（不显示半截）。

### ③ 额度 / 四节不齐

- **额度**：真机未单独制造（当天额度此前已在模拟器实测过 `quota_exhausted`，见 [README.md](README.md)）。
- **四节不齐**：需要**客户端 stub**，真机上做不到（那正是模拟器里用 stub 测的），**真机不适用**——如实记。

## 6. 未覆盖 / 不得据此声称

- **小程序基础库版本未读到**：试了「设置」页与「开发版」资料卡都拿不到 ⇒ 记「**未核实**」，**不编造数值**。
- **返回手势未取得结论**：试了一次，结果是**退出小程序并打开微信扫一扫**，不是干净的状态验证；**不再盲试**（那是用户日常在用的微信，误触可能发消息）。⇒ 记未覆盖。
- **「扫一扫→相册」那条路本轮也没验证成**：进了扫一扫，但点相册没打开图库（坐标或权限问题）。**用户此前已成功用它打开过小程序**，所以那条指引是有效的——但**本轮没有留下截图证据**，如实记。
- **真机失败路径只补了「断网」与「`citation_unverified`」**：**额度**未在真机单独制造；**四节不齐**需要客户端 stub，真机不适用。**模拟器上的失败路径仍然是 13/13 条断言的出处**，两者不可互相替代（真断网比 mock reject 慢约 60 秒，见 5.1①）。
- **截图是执行端自己点的**，不是负责人手点：本轮真机是**自动化驱动**，与「负责人手动体验」不是同一件事。
