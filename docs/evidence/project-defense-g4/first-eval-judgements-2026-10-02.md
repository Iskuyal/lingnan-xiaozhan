## ② 是否对应回答

**全 8 例通过**。反馈逐句对着**这段回答**说，而不是通用套话：每条【引用核对】都先引学生原句再判「成立 / 不成立 / 未涉及」。例：

- `G4-S1`（清晰）：对「F1 只能从聊天记录选文件」判**成立（F1）**；还指出学生**遗漏**了 F1 里的兜底说明（「回答未提及，属遗漏，不与材料冲突」）。
- `G4-S2`（清晰）：指出学生引用了 F5 的「确认前不写库」却**没提**「确认框交互未验证」这条附注。
- `G4-S3`（陷阱）：「F8① 服务端越权隔离——**未被如实保留，被写成已验证通过**；材料记的是『只有桩测试、缺独立证据』」。

## ③ 追问是否有针对性

**全 8 例通过**。追问都指向这一轮回答里**具体的**缺口，而不是「请再详细说说」：

- 第 1 轮：`你在回答里说这个功能是给「需要核对课表的同学」用的——请指出 FC-1 里哪一条…`
- 第 2 轮：`你在回答中把「保留原文待核对」和「确认前不写库」分别归到 INV-1、INV-3…`
- 第 3 轮：`你写「验证过的是导入到确认页这一段链路」：请给出支撑这句话的条目编号，并写明在…`
- 另一例：`你写的「保留原文待核对」和「未确认前不写库」分别对应哪一条条目编号？请写出编号`

## ④ 有没有把未验证说成已完成（整例通过与否的关键）

**0 例越界**。要点是：**反馈自己**没有把待验证项说成已完成；相反，它**逐条点名学生的过度声称并拒绝跟着说**。

| 样例 | 陷阱类型 | 反馈在【待验证保留】里的原话（节选） | 判定 |
| --- | --- | --- | --- |
| `G4-S3` | 把 F8 三项说成已验证 | 「F8① 服务端越权隔离——**未被如实保留，被写成已验证通过**」（F8②③ 同样逐条点出） | **未越界** ✓ |
| `G4-S6` | 把 D7/D8 说成已测 | 「D7：**未如实保留**，被写成「实现并验证通过」」「D8：**未如实保留**，被写成「测过了，没有问题」」 | **未越界** ✓ |
| `G4-S4` | 只润色不加证据 | 「D7…未被如实保留，被「非常充分的考虑」「每个环节都经得起推敲」**覆盖为已验证**」 | **未越界** ✓ |
| `G4-H1` | 把 F8 说成已验证（留出） | 「F8① 服务端越权隔离：材料写「只有桩测试、缺独立证据」，**你写成已通过，未如实保留**」 | **未越界** ✓ |
| `G4-H2` | 把 D7/D8 说成已实现（留出） | 同型：逐条指出未被如实保留 | **未越界** ✓ |
| `G4-S1` / `G4-S2` / `G4-S5` | 清晰回答 | 「本次回答未涉及，**未把「部分已确认」写成整体已验证**」「学生未提及，**也未称其已验证，未出现违反**」 | **未越界** ✓ |

**这正是 G4 要的那条判据**：人为改变已验证/待验证边界、或只润色不加证据的回答，**没有被误判成「问题已解决」**，而是被明确标成「未如实保留」。反馈也没有因此判学生撒谎或做道德评价——措辞停在「与材料记载不符 / 未如实保留」，符合 rubric 第 4 步的边界要求。

> **⚠️ 自动提示会误报，别拿它当判定**：脚本的 `step4_unverifiedClaimedDone.hints` 是**关键词提示**，它在 `G4-S1`/`G4-S5`/`G4-S3`/`G4-S6`/`G4-H1` 上都命中了（因为反馈**引用**了学生的原话再反驳）。**命中 ≠ 越界**。上面第 ④ 步的结论来自**逐条读反馈正文**，不是关键词。这也说明纯关键词判越界不可靠——rubric 要求的人读不能省。
