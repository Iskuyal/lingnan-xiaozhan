# G4 · 对照实验：固定检查表 vs 通用 AI 提示（2026-10-02）

- 对应 [Issue #115](https://github.com/Iskuyal/wx-match/issues/115)；脚本 `scripts/verify-defense-g4-comparison.cjs`。
- 原始记录：[comparison-2026-10-02.json](comparison-2026-10-02.json)（已入库，可复核）。
- ⚠️ **通用提示两轮失败的原始返回（`artifacts/verify/armB-raw.json`、`armB-raw2.json`）在仓库内不可复现**：它们落在 gitignore 的 `artifacts/` 下，**未入库**（键结论已逐字抄进本页，可直接引用；要重跑请执行本页开头的脚本命令）。**不链该目录**——链出去在 CI 的干净检出里会 404。
- **对照设置**：同一份材料（`FC-1`）、同一段回答、**同一个模型**（`deepseek/deepseek-v4.1-flash`）、同一套安全配置。两臂唯一的差别是**提示词形态**。

## 结果

| | A 臂：固定检查表（本功能） | B 臂：通用 AI 提示 |
| --- | --- | --- |
| 提示词 | 服务端下发纪律提示词，要求四节格式 | 「以评委身份点评，给出讲清楚/没讲清楚/改进建议」 |
| 输出预算 | 服务端默认 | 限到 1200 token（与 A 臂四节约 600–900 token 可比） |
| **结果** | **成功**，四节齐全 | **失败 ×3**：`model_unavailable` |
| 耗时 | 34.3 / 36.3 秒（两次） | 18.1 / 21.2 / 16.6 秒后失败 |
| 产出长度 | 933 字符 | **0 字符** |
| 安全检测 | `allowed=true` ✓ | `allowed=true` ✓（B 臂安全层是通的，不是被拦） |

B 臂三次的原始 detail 完全一致：

```text
模型返回内容为空（OpenAI 兼容格式）；choices=1；finish_reason=length；
content=string；reasoning_content=present；error=missing；usage=present
```

即：**模型把输出预算全花在 `reasoning_content` 上，`finish_reason=length`，正文一个字符都没吐**。这是 G1 阶段就遇到过的同一个毛病（「客户端 maxTokens 实测无效，只能由负责人改环境变量」），与本次换的第三方审核**无关**——B 臂的安全检测是 `passed=true`。

**我做了两次**：第二次把提示词改成「请直接输出点评内容，不要展开思考过程」这种真人会用的说法，仍然同样失败。**没有故意弱化对照**（材料、回答、模型、安全配置全同）。

## 结论

1. **可对比的只有「可用性 / 稳定性」，不是「内容质量」**——B 臂根本没有产出，所以无法比较建议条数、定位依据是否方便等质量维度。这一点必须如实说明，**不能**把「B 臂拿不到输出」包装成「固定检查表更懂内容」。
2. 在这套**模型 + 配置**下，**结构化提示词（固定检查表）是产出可用结果的必要条件**：同样的模型，自由发挥的提示词进不去正文，四节格式的提示词稳定出结果。这对 G2/G5 有直接影响——见下。
3. **A 臂本身的质量是好的**：它的四节输出逐句引学生原句判「成立/不成立/未涉及」，还指出了学生遗漏的条目（F1 的兜底说明）与不符之处（F8① 的分项记载），并给出针对性追问。

| 人工评分项 | A 臂 固定检查表 | B 臂 通用提示 |
| --- | --- | --- |
| 完成步骤 | 4/4（四节齐全） | 0（未产出） |
| 定位依据是否方便 | 方便：每条都带编号，可直接回核 | 不适用 |
| 人工判定的有效建议数 | 见 A 臂正文（逐条带编号） | 0（无输出） |
| 完成时间 | 34.3–36.3 秒 | 失败前 16.6–21.2 秒 |

> 「有效建议数」需要人逐条读并计数；本页只给 A 臂正文与结构，**具体条数留待复核人填**，脚本不自动打分。

## 对 G2 / G3 / G5 的影响

- **G5（10-08 演示）**：通用聊天提示在这套模型上**不可靠**（3/3 拿不到输出）。演示若要用 AI 点评，**必须走有固定格式的落点**，不要让现场即兴输入自由文本提示词。
- **G5（时延）**：A 臂 34.3–36.3 秒，比 G1 记的 12–23 秒更慢。两个原因叠加：① 第三方审核每次多 1.7–2.9 秒；② 模型本身更慢。**12–23 秒的口径在换审核后已不成立**，演示脚本要按更宽的时间预算排。
- **G3**：服务端固定纪律提示词不是「锦上添花」，而是**让模型产出正文的必要条件**——这一点本轮拿到了直接证据，建议保留并写进设计说明。

## 局限

- **单次运行**，每臂样本量小；B 臂 3 次全失败虽然一致，但没有扫描更多提示词写法。
- 本批次安全路径为**第三方审核**，与线上默认 `wechat` 不一致（见 [safety-provider-switch-2026-10-02.md](safety-provider-switch-2026-10-02.md)），时延数字含这层开销。
- 对照实验**不证明**本功能能提升学习效果；它只说清了「同样条件下哪种提示词形态能产出可用输出」。
