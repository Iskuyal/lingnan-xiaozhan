# 分段开发与验收

这是正式开发的 P 编号，替代此前访谈中的 P0–P5 设定编号。比赛提交时间仍由 [比赛工作流](workflow.md) 管理，不按工作日/周末限制任务。

当前状态：P0 文档决策、P1 首页入口、P2 学生部门与 P3 资讯栏目（不含云端同步）已完成并通过开发者工具验收，见 [P2 / P3 验证记录](evidence/p2-p3/README.md) 与 [P1 验证记录](evidence/p1/README.md)。P3 云端同步、P4–P6 及真机预览仍未完成。

## 阶段总览

| 阶段 | 可独立验证的交付 | 真正依赖 | 完成条件 |
| --- | --- | --- | --- |
| P0 框架与规格 | 开发规格、架构决策和分段计划 | 现有项目设定 | 平台、框架、边界、依赖与验收均有记录 |
| P1 首页与入口 | 可运行的微信小程序首页，部门及课表入口可跳转 | P0 | 构建通过，开发者工具能导入，简介准确，两个入口和返回正常 |
| P2 学生部门 | 真实部门列表和详情 | P1 + 核实后的部门资料 | 职责、联系方式、动态或缺失提示正确，所属校区清楚 |
| P3 官网资讯 | 官网内容经后台同步后在小程序列表与详情展示 | P1 + 云环境可用 | 真实数据可读，来源和日期准确，重复同步不重复，失败保留旧内容 |
| P4-A 教务研究 | 脱敏样本、登录路径、接入可行性结论 | 本人账号可用的验证环境 | 验证真实取课表路径或记录可复现阻塞，不依赖 P2/P3 完成 |
| P4-B 个人课表 | 本人账号获取并展示真实周课表 | P1 + P4-A 成功 + 服务环境可用 | 登录、同步、周次切换、失效提示和个人隔离可验证 |
| P5-A AI 方案定案 | 有真实材料支持的能力选择与评估标准 | P0 + 代表性校园资料 | 负责人确定功能、收益指标与成本上限 |
| P5-B AI 功能 | 选定能力贯穿来源、服务与界面 | P5-A + 对应数据链路（资讯方案依赖 P3） | 正常/错误/缺失信息案例通过，结果可追溯，记录耗时和成本 |
| P6 比赛交付 | 体验版、录屏、七项材料和参赛包 | P2/P3/P4-B/P5-B + 赛事与团队信息确认 | 核心流程真机验收、材料对应版本、包可复现、实际提交有回执 |

若决定缩减课表或其他最终功能，需显式更新规格与 P6 依赖；不能因为外部接入失败就将原目标标为完成。

## P1：当前应先执行的任务

### P1-1 学校简介与两个入口

- [x] 创建原生 TypeScript 小程序、npm 锁文件、构建脚本及项目配置；产物统一写入 dist。
- [x] 提供 `npm run typecheck`、`npm run build`；README 说明微信开发者工具导入路径、AppID 配置位置及运行步骤。真实 AppID 未提供时明确测试配置的能力范围。
- [x] 首页显示学校正式名称、简短简介和来源；按简洁实用风格呈现两个功能卡片。
- [x] 部门与课表各有独立状态页，点击进入、返回首页正常；不呈现已可登录或已有课表的假象。
- [x] 通过类型检查和构建，在开发者工具验证首屏、点击和返回，保存截图与环境信息。

本任务把初始化与真实首页一起交付，不另建只含空目录的“脚手架完成”任务。

## P2：学生部门

### P2-1 部门资料到列表和详情

- [x] 核实学生会部门资料、所属校区和信息日期，保持出处。
- [x] 本地内容服务返回部门数据，页面显示列表与详情；资料缺失时说明缺失，不编造负责人或联系方式。
- [x] 验证部门选择、返回、未知部门和空列表；至少用核实的真实部门演示完整路径后才完成模块。

## P3：官网资讯

### P3-1 一篇真实官网文章贯穿云端和页面

- [ ] 验证 AppID 与云环境关联、数据库权限和云函数调用。
- [ ] 实现维护者导入/同步一篇真实文章、服务端读取、小程序列表与详情、来源信息。
- [ ] 验证标题日期正文对应原文、无登录可看公开资讯、普通客户端不能写公开内容。

云端同步部分仍被 AppID 与云环境阻塞：不依赖云端的部分（列表与正文提取、按原文 URL 去重、随包快照、资讯列表与详情页）已交付并通过开发者工具验收，见 [P2 / P3 验证记录](evidence/p2-p3/README.md)；云环境关联、数据库权限、云函数调用与部署仍需在本票内补做。

### P3-2 栏目同步与更新

依赖 P3-1。

- [ ] 抓取选定栏目并按原文 URL 去重，处理文章更新；维护者可触发同步，再配置每日定时。
- [ ] 首页增加最近资讯入口与条目；列表支持逐页加载。
- [ ] 使用公开页面样本验证重复同步、缺失日期、无正文和抓取失败；失败仍能查看最后成功内容并识别更新时间。

## P4：课表

P4-A 是研究任务，输出可行性记录后再写 P4-B 的实现细票。需明确学期/周次/节次样本和真实认证流程，未验证之前不提供虚假的通用账号接口。

P4-B 成功路径：进入课表 → 本人授权登录 → 同步本学期 → 查看当前周 → 切换周次 → 退出/重新同步。验收覆盖单周、双周、多时间段课程、无课日期、会话失效及不同用户访问隔离。

## P5：AI

P5-A 是产品决策任务，不标记成可无人值守实施。输入来自学校真实材料；输出需写出用户收益、无 AI 的对照、成功指标、来源追溯、错误案例及预算。
P5-B 的页面和接口取决于 P5-A，定案后另补完整实施票。AI 密钥在服务端，失败时仍能阅读原始资讯。AI 能力未落地前不关闭赛事 AI 要求。

## P6：联调与交付

- [ ] 回归首页、部门、资讯、课表与 AI 的核心流程，修复阻断问题。
- [ ] 在实际微信设备记录环境、结果与演示视频，配置可访问的体验版。
- [ ] 完成 [提交清单](submission.md) 七项内容与包检查，保留第三方来源和历史说明。
- [ ] 人工确认报名、组别与赛事冲突问题，在实际入口提交并保存回执。

## 与现有 GitHub 任务的关系

现有 #1 为赛事与资源核实，#2 为选题验证，#3 为 MVP 与技术验证，#4 为实现总任务，#5 为验证总任务，#6 为材料提交。
本轮不关闭这些任务，也不把需要外部验证的 P4/P5 标成 ready-for-agent。细票发布时按上述真正依赖关联，并链接本规格；当前范围不要求新增重复的总任务。
