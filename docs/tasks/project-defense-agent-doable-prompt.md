## A. agent 能独立完成的（按建议顺序）

### A1. 修 CI 的 `npm audit` 失败（**最独立、最有价值**）

**现状**：`main` 的 CI 常红，失败步骤是「审计锁定依赖」：`wx-server-sdk@4.0.2` → `@cloudbase/node-sdk` → `axios` 命中两个新公告
（`GHSA-9fr6-4gfg-395g`、`GHSA-x97p-jq2-jp4f`，`npm audit --audit-level=low` 因此退出码 1）。
**这条不挡功能，但会让所有 PR 都红，容易淹掉真问题。**

**要做**：评估并落地一个修法（升级 `wx-server-sdk` 到 axios 已修补的版本 / 用 `overrides` 锁 axios / 换依赖），**选一条并说明代价**。
**判据（缺一不可）**：
- `npm audit --audit-level=low` 对三条云函数目录都过；
- `npm test` 全绿、`npm run typecheck` 通过；
- **`ai` 云函数仍能真实调用**（改依赖可能影响云函数运行时 ⇒ 必须重新部署并**发一次真实请求验证**，不能只看测试）；
- **不改任何安全配置**（不得关 `AI_MODERATE_OUTPUT`、不得动 `AI_SAFETY_FAIL_MODE`）。

⚠️ 这是**依赖升级**，`wx-server-sdk` 的大版本升级是破坏性变更。**先本地全量回归，再部署，再真实验证**；失败就回滚并如实记录。

### A2. 修 `docs:check` 的盲点（小工具改进）

**现状**：`scripts/check-docs.mjs` **只看目标文件在磁盘上是否存在**，因此**查不出指向 gitignore 目录**（`artifacts/`、`dist/`）**的链接**——本地绿、CI 干净检出里 404。
PR #127 的 CI 就是这样被拦下的（我当时链了 `artifacts/verify/*.json`）。

**要做**：让检查**同时校验「链接目标是否被 git 跟踪」**。实现提示：`git ls-files -z`（**必须用 `-z`**：默认输出会把非 ASCII 文件名转义成 `\xxx`，中文文件名会误报）。
**判据**：`npm run docs:check` 仍绿；**故意加一个指向 `artifacts/` 的链接时必须报错**；补一个测试锁住这个行为。

### A3. 补客户端超时（契约缺口，**别照字面抄 30 秒**）

**现状**：设计契约要求「超过 30 秒未返回，按 `model_unavailable` 结束并保留输入」，但**代码里根本没实现**——`miniprogram/services/defense/index.ts` 与 `services/ai.ts` **零 timeout**，真机断网实测**约 60 秒**才失败。
**而 30 秒对现在的时延已经偏低**（正常 20–45 秒）⇒ **照字面实现会砍掉正常请求**。

**要做**：加一个**阈值高于实测上界**的客户端超时（建议 ≥75 秒），超时后进入 `model_unavailable` 的失败态并**保留草稿 + 给重试入口**；**同步更新设计契约**（删掉/改写那条 30 秒）。
**判据**：超时后失败态文案正确、草稿保留；契约与实现一致；有测试；**不改变正常路径的行为**（20–45 秒内的请求必须仍成功）。
