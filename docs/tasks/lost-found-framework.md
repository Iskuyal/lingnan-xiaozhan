# 失物招领模块实施框架（提案）

> 状态：待评审，尚未纳入已确认开发范围  
> 文档用途：定义失物招领主线的范围、闭环、技术边界、验证方法与决策关卡  
> 实施状态：仅完成框架文档，未完成设计图、业务代码、模型评测或上线验证  
> 最近更新：2026-09-27

## 1. 背景与文档边界

评审建议优先展示“失物招领双向匹配”：用户发布丢失或拾获信息，AI 从照片和文字中寻找候选线索，解释相符点与冲突点，隐藏可用于冒领的特征，最后由双方人工核验并结案。

当前项目基线仍以 [`CONTEXT.md`](../../CONTEXT.md)、[`development-spec.md`](../development-spec.md) 和 [`development-phases.md`](../development-phases.md) 为准，其中已经固定三个 AI 落点：院系问答、课表截图识别、课表自然语言助手。失物招领属于新增业务域和新增 AI 能力，不能由本文件自动替换既定范围。

因此，本文件是实施提案，不代表以下事项已经确定：

- 失物招领作为第四个 AI 落点，还是替换现有一个 AI 落点；
- 首次交付采用许可样本演示，还是直接开放真实用户发布；
- 正式功能名称、模型供应商、成本上限和评测阈值；
- 真实认领、线下交接、运营审核和数据保留规则。

## 2. 成功标准

模块完成不能只以“生成了分类或描述文案”为准。最小成功闭环必须同时满足：

1. 用户能够发布丢失或拾获信息，并明确同意图片和文本用于匹配。
2. 系统能够从相反类型的帖子中返回候选线索，而不是只做物品分类。
3. 每个候选结果都展示可核验的相符点和冲突点，不将模型分数包装成事实。
4. 系统不公开用于证明所有权的隐藏特征，也不自动判定物品归属。
5. 认领人提交隐藏特征后，由发布者人工核验；双方确认交接后才可结案。
6. 无候选、低置信度、模型超时或模型不可用时，基础发布与人工检索仍可使用。
7. 使用经许可的成对样本、相似干扰样本和负样本完成离线评测，并保留可复查结果。
8. 输入校验、越权访问、冒领防护、内容安全和状态流转测试通过。

## 3. 范围决策关卡

### D1：与现有三个 AI 落点的关系

必须在业务代码开发前选择一种方案，并同步更新权威范围文档：

| 方案 | 含义 | 收益 | 代价 |
| --- | --- | --- | --- |
| A：新增第四落点 | 保留现有三个 AI 落点，增加失物招领匹配 | 展示面更完整，不打断既有计划 | 开发、评测、成本和运营范围显著增加 |
| B：替换一个落点 | 以失物招领替换一个尚未完成的 AI 落点 | 更聚焦评审建议，总范围可控 | 必须明确放弃项，并修改比赛与开发文档 |
| C：独立验证原型 | 只用许可样本完成匹配与认领演示，不接真实用户 | 最快验证 AI 价值和防冒领流程 | 不能作为真实上线功能或用户成效证据 |

在 D1 确认前，建议按 C 进行设计和评测准备，不接入生产数据、不承诺上线范围。

### D2：首版数据来源

- 许可样本：由项目成员或授权参与者提供，需记录授权范围、授权时间和删除方式。
- 真实用户内容：需要同时具备隐私说明、内容审核、举报处理、数据删除和运营责任人。
- 不允许抓取未知来源的校园群图片作为训练、评测或演示数据。

### D3：AI 成本与评测阈值

在模型接入前确定：

- 单次发布允许的模型调用次数、图片压缩规格和月度预算；
- 候选数 `K`、候选召回率、误匹配率、延迟和失败率目标；
- 低质量图片、信息不足、敏感内容和重复发布的处理规则；
- 模型版本、提示词版本和评测集版本的绑定方式。

以上数值在真实基准测试前保持“待定”，不得用模拟结果替代实测结论。

## 4. 用户与权限

| 角色 | 可执行操作 | 明确禁止 |
| --- | --- | --- |
| 发布者 | 创建、编辑、关闭自己的帖子；查看候选；核验认领信息；确认交接 | 查看其他用户私密特征；修改他人帖子 |
| 认领者 | 浏览公开信息；提交认领申请；补充核验信息；确认交接 | 获得完整隐藏答案；绕过发布者确认结案 |
| 审核员 | 处理举报、违规内容和争议记录 | 代替双方判断所有权；将审核数据用于其他目的 |
| 系统 | 内容安全检查、候选召回、相似度解释、状态约束 | 自动裁定归属；公开联系方式或私密核验特征 |

用户身份必须由云函数从可信上下文取得 `openid`，不得相信前端提交的用户标识。

## 5. 最小业务闭环

```text
发布丢失/拾获信息
        ↓
输入与内容安全检查
        ↓
公开特征入库 + 私密核验特征隔离保存
        ↓
规则过滤相反类型、时间、地点和类别
        ↓
AI 对照片与文字做双向匹配
        ↓
候选线索：相符点 + 冲突点 + 不确定性提示
        ↓
认领者提交隐藏特征或其他证明
        ↓
发布者人工核验，必要时补充沟通
        ↓
双方确认交接
        ↓
结案并停止继续匹配
```

首版不把私聊系统作为必要条件。更简单的实现是采用结构化认领表单和脱敏交接说明；它降低了实时通信和内容治理成本，但沟通灵活性较低。若后续增加私聊，需要单独评审消息留存、举报、骚扰防护和联系方式泄露风险。

## 6. 功能范围

### 6.1 首版必须包含

- 丢失、拾获两类帖子的创建、草稿、发布、编辑和关闭；
- 物品类别、时间范围、地点范围、公开描述、图片和私密核验特征；
- 公开列表、筛选、详情和“我的发布”；
- 规则召回与照片/文字双向候选匹配；
- 候选结果的相符点、冲突点和不确定性说明；
- 认领申请、补充材料、接受、拒绝、取消和交接确认；
- 内容安全、举报入口、审计事件和数据删除入口；
- 模型失败时的重试、人工检索和明确降级提示。

### 6.2 首版不包含

- 人脸识别、校园监控接入或人员轨迹分析；
- 基于 AI 的自动归属裁决；
- 自动公开手机号、微信号、精确宿舍或实时位置；
- 支付、悬赏托管、物流、快递或校外交易；
- 未经授权的数据抓取、模型训练或跨用途复用；
- 复杂即时聊天、群聊和社交推荐。

## 7. 状态模型

### 7.1 帖子状态

| 状态 | 含义 | 允许的下一状态 |
| --- | --- | --- |
| `draft` | 未公开草稿 | `open`、`closed` |
| `open` | 已公开并接受匹配 | `matching`、`verifying`、`closed`、`suspended` |
| `matching` | 候选计算中 | `open`、`verifying`、`closed`、`suspended` |
| `verifying` | 至少一个认领申请待核验 | `open`、`resolved`、`closed`、`suspended` |
| `resolved` | 双方已确认交接 | `closed` |
| `closed` | 发布者主动关闭或结案归档 | 无 |
| `suspended` | 因内容安全或举报暂停 | `open`、`closed` |

状态变更必须在服务端校验；前端不得直接写状态字段。

### 7.2 认领状态

| 状态 | 含义 | 允许的下一状态 |
| --- | --- | --- |
| `pending` | 已提交，等待发布者核验 | `needs_more_info`、`accepted`、`rejected`、`cancelled` |
| `needs_more_info` | 需要补充证明 | `pending`、`rejected`、`cancelled` |
| `accepted` | 初步核验通过，等待交接 | `completed`、`cancelled`、`disputed` |
| `rejected` | 核验不通过 | 无 |
| `cancelled` | 申请人或发布者取消 | 无 |
| `completed` | 双方确认交接 | 无 |
| `disputed` | 交接或归属存在争议 | `completed`、`cancelled` |

## 8. 页面与交互框架

任何页面代码修改前，必须按 [`docs/design/README.md`](../design/README.md) 在 `docs/design/lost-found/` 先完成 HTML 设计图并渲染 PNG。PNG 是评审件，HTML 中的尺寸和状态是实现依据；设计图通过评审后才能进入代码实现。

建议设计以下页面和关键状态：

| 页面 | 核心内容 | 必画状态 |
| --- | --- | --- |
| 失物招领首页 | 丢失/拾获切换、筛选、发布入口、结果列表 | 正常、空列表、加载失败 |
| 发布向导 | 基本信息、图片、公开描述、私密核验特征、授权说明 | 无效输入、图片审核失败、草稿恢复 |
| 帖子详情 | 公开特征、模糊地点/时间、状态、认领入口 | 自己发布、他人发布、已关闭 |
| 候选线索 | 候选卡片、相符点、冲突点、不确定性、反馈 | 有候选、无候选、模型不可用 |
| 认领核验 | 结构化问题、证据补充、发布者操作、风险提示 | 待处理、需补充、拒绝、通过 |
| 我的失物招领 | 我的发布、我的认领、待办提醒 | 各状态组合、空状态 |
| 交接与结案 | 脱敏交接建议、双方确认、争议入口 | 单方确认、双方确认、争议 |

设计时不得在候选卡片上展示全部私密特征，也不得用“AI 已确认是你的物品”等确定性文案。

## 9. 领域模型与数据隔离

以下是建议模型，最终字段需在领域文档和数据 ADR 中确认。

### 9.1 `lost_found_posts`

公开和业务状态数据：

- `postId`、`ownerOpenId`、`type`（`lost` / `found`）；
- `category`、`title`、`publicDescription`、`publicImageFileIds`；
- 模糊化的 `timeRange`、`locationArea`；
- `status`、`createdAt`、`updatedAt`、`closedAt`；
- `contentSafetyStatus`、`matchStatus`；
- 数据版本和软删除标记。

### 9.2 `lost_found_post_private`

仅发布者和授权云函数可访问：

- `postId`；
- 颜色细节、划痕、编号局部、内部物品等 `verificationTraits`；
- 原始精确时间/地点（确有必要时）；
- 授权记录、删除计划和访问审计引用。

私密表不得由小程序端直接查询，候选解释也不得原样回传其中内容。

### 9.3 `lost_found_matches`

- `sourcePostId`、`candidatePostId`；
- 规则过滤版本、模型版本、提示词版本；
- 结构化相符点、冲突点和置信区间；
- `rank`、生成时间、失效时间；
- 用户反馈（有帮助、无关、误导）和失败原因。

### 9.4 `lost_found_claims`

- `claimId`、`postId`、`claimantOpenId`；
- 结构化核验回答和证据文件引用；
- `status`、双方确认时间；
- 发布者反馈、争议状态和审计引用。

### 9.5 `lost_found_audit_events`

记录关键状态变更、敏感数据访问、审核、举报和模型调用元数据。审计记录不保存不必要的完整图片、完整提示词或模型密钥。

## 10. 服务与云函数边界

遵循 [`ADR-0001`](../adr/0001-native-wechat-typescript.md)：原生微信小程序 + TypeScript，业务服务按功能拆分，模型密钥只保存在云端。

建议的服务端能力：

| 能力 | 职责 | 关键校验 |
| --- | --- | --- |
| `createLostFoundPost` | 创建草稿或发布 | 字段白名单、长度、枚举、图片归属、授权、内容安全 |
| `updateLostFoundPost` | 编辑本人帖子 | 所有权、状态、乐观锁、敏感字段隔离 |
| `listLostFoundPosts` | 返回公开列表 | 只返回公开字段、分页上限、筛选白名单 |
| `getLostFoundPost` | 返回公开详情或本人完整数据 | 字段级权限、已删除/暂停处理 |
| `requestLostFoundMatches` | 触发或获取候选 | 所有权、频率限制、幂等、预算和超时 |
| `submitLostFoundClaim` | 提交认领申请 | 不得认领自己的帖子、防重复、证据格式和频率限制 |
| `reviewLostFoundClaim` | 发布者处理申请 | 帖子所有权、合法状态流转、理由记录 |
| `confirmLostFoundHandover` | 双方确认交接 | 双方身份、已接受申请、幂等 |
| `reportLostFoundContent` | 举报内容或行为 | 举报类型、去重、频率限制、审计 |
| `deleteLostFoundData` | 用户请求删除可删除数据 | 身份、保留义务、关联状态和审计 |

所有写操作都应使用幂等键或版本号，防止重复点击造成多条申请、重复结案或状态回退。

## 11. AI 匹配框架

### 11.1 两阶段方案

1. **候选召回**：先按丢失/拾获相反类型、类别、时间范围和模糊地点做规则过滤，控制成本和无关候选。
2. **多模态重排**：对候选照片与文字做双向比较，输出结构化依据，而非自由文本结论。

建议结构化输出：

```json
{
  "candidatePostId": "string",
  "similarities": ["公开且可核验的相符点"],
  "conflicts": ["已发现的冲突点"],
  "uncertainties": ["缺失或无法判断的信息"],
  "confidenceBand": "low | medium | high",
  "needsHumanVerification": true
}
```

模型输出必须经过 JSON Schema 校验、候选 ID 白名单校验和敏感信息过滤。解析失败时不得把原始模型文本直接展示给用户。

### 11.2 AI 安全边界

- AI 只排序和解释候选，不确认所有权，不决定认领结果。
- 输入模型的数据遵循最小化原则；无关身份信息和联系方式不进入提示词。
- 私密核验特征只用于服务端受控比较或人工核验，不作为公开解释。
- 每次结果绑定模型、提示词和评测集版本，支持回归比较和回滚。
- 设置超时、重试上限、每日调用限额和熔断；失败时回退到规则检索。
- 用户能反馈“无关”或“解释有误”，但反馈数据在再次使用前需明确用途和授权。

## 12. 输入校验与安全基线

实现顺序遵循“先写无效输入和越权测试，再让测试通过”。至少覆盖：

- 空标题、超长描述、非法枚举、时间范围反转、非法文件类型和超量图片；
- 伪造 `openid`、修改他人帖子、读取私密表、处理他人认领申请；
- 重复提交、重放请求、并发结案和非法状态跳转；
- HTML/脚本内容、提示词注入文本、恶意文件名和异常模型输出；
- 高频发布、高频认领、批量遍历帖子 ID 和候选刷取；
- 公开描述中主动填写手机号、微信号、精确宿舍等敏感信息；
- 删除后仍可通过候选缓存或日志读取原数据；
- 图片违规、举报成立和账号被限制后的访问行为。

隐私与防冒领原则：

- 默认模糊时间和地点，不公开完整联系方式；
- 发布时引导保留至少一个未公开特征；
- 同一用户的认领次数和失败次数受限，异常行为进入审核；
- 结案前至少由发布者确认，正式上线方案建议双方确认；
- 对贵重物品提示线下安全交接和校方渠道，不承诺平台担保。

## 13. 评测方案

### 13.1 固定评测集

评测集至少包含：

- 成对正样本：同一物品的丢失描述与拾获描述；
- 相似干扰样本：同类、同色、同品牌但不是同一物品；
- 明确负样本：类别、时间或地点明显冲突；
- 信息不足样本：模糊照片、极短描述、缺失时间地点；
- 安全样本：包含联系方式、敏感图像或提示词注入文本。

每个样本记录来源、许可、期望候选、关键相符点、关键冲突点和不可公开特征。评测集与演示数据分开管理。

### 13.2 指标

在 D3 决策关卡确定具体阈值，至少测量：

- `Recall@K`：正确对象是否进入前 K 个候选；
- 干扰样本误排率：相似但错误的物品是否被高排；
- 解释完整率：关键相符点和冲突点是否被覆盖；
- 隐私泄漏率：是否输出隐藏特征或联系方式；
- 中位数与 P95 延迟、超时率、解析失败率；
- 单次发布平均调用成本和月度预算推算；
- 模型失败后的基础流程可用性。

不得只展示成功案例。评审材料需包含至少一个相似干扰样本、一个无候选样本和一个降级案例。

## 14. 分阶段实施与验证

| 阶段 | 实际产物 | 验证方式 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| LF-0 范围决策 | D1–D3 决议、负责人、成本与数据许可方案 | 权威文档评审；检查冲突项已同步 | 范围和数据来源获确认 |
| LF-1 领域与安全 | 领域词汇、状态机、权限矩阵、威胁清单、无效输入测试 | 文档评审；测试先失败并能复现风险 | 状态与权限无未决冲突 |
| LF-2 界面设计 | HTML 设计图、PNG 评审件、文案和状态清单 | 运行 `node scripts/render-mockups.mjs`；人工评审 PNG | 设计图定稿 |
| LF-3 非 AI 基线 | 发布、列表、详情、认领和结案的服务端闭环 | 类型检查、单元/集成测试、开发者工具和真机验证 | 无 AI 时闭环可用 |
| LF-4 AI 原型 | 固定评测集、召回与重排、结构化解释、降级 | 离线评测；成本/延迟实测；隐私泄漏测试 | 达到 D3 阈值 |
| LF-5 受控演示 | 许可样本端到端演示、审计、举报和删除 | 完整场景走查；失败案例与恢复验证 | 证据可复查且无阻断风险 |
| LF-6 上线准备 | 运营责任、隐私说明、保留策略、监控与回滚 | 发布检查表、真实配置核验、真机回归 | 仅在真实用户方案获批准后上线 |

## 16. 完成定义

只有同时满足以下条件，才能报告“失物招领最小闭环已完成”：

- [ ] D1–D3 已有明确决议，并同步到权威范围文档；
- [ ] 领域模型、权限矩阵和状态机经过评审；
- [ ] `docs/design/lost-found/` 的 HTML 和 PNG 已定稿；
- [ ] 无效输入、越权、状态流转和冒领风险测试先建立并通过；
- [ ] 无 AI 时的发布—认领—交接闭环可用；
- [ ] AI 返回真实候选匹配结果及相符点/冲突点，不是预置文案；
- [ ] 固定评测集达到已批准阈值，成本和延迟有实测数据；
- [ ] 模型失败、无候选和内容审核失败均有可用降级路径；
- [ ] 隐私、删除、举报、审计和限流流程经过验证；
- [ ] 微信开发者工具与至少一台真机完成主流程回归；
- [ ] 演示材料清楚区分模拟数据、许可样本和真实运行结果。
