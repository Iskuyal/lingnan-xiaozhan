# 07：部门 AI 问答

**What to build:** 学生进入部门模块后有一个对话框，AI 主动问「你想了解什么部门」并给出可点的选项；点进去是对应部门界面；有疑问可以继续追问。答案必须建立在已核实的部门资料上，资料里没有的要说「官网未公布」。

**Blocked by:** ~~01（AI 服务端基础设施）~~ 已合入 main（2026-09-18）

**Status:** in-progress（代码与本地测试完成，2026-09-18；PR 两轴复核（Standards + Spec）发现的问题已在本分支修复并补测；2026-09-19 在 `feat/department-qa-guard` 上移植 PR #29 的防幻觉守卫、详情页问答面板与开发者工具验收检查（原作者 SU5114）；开发者工具三路径、真实模型问答评估与真机仍未执行）

## 两轴复核后的修复（2026-09-18，仅本地）

复核指出的问题已按下面几条修掉，逐项证据见 [P5-B 验证记录](../../evidence/p5-b/README.md)：

1. **失败文案由服务端说了算**：`services/ai.ts` 的 `userMessage` 改为服务端 `message` 非空时优先，
   本地表只在服务端没给文案时兜底（负责人在云函数环境变量里改措辞要能立刻生效）。
2. **`safety.checked` 透传**：`AiCallResult` 带回 `safety`/`warnings`；`checked !== true`
   （含字段缺失）时对话里加提示行、页脚补一句「本轮回答未经内容安全检测」，测试锁定该提示。
3. **进入即主动问话**：部门页 `onShow` 自动展开一次对话框；用户收起后写本地持久标记，
   本次会话与下次进入都不再自动弹，之后由用户主动打开。
4. **传输层映射去重**：新增 `services/cloud.ts`（`requireCloud` + 三条技术性错误正则），
   `services/ai.ts` 与 `services/timetable/index.ts` 都改为调用它，`messageOf` 的既有行为不变。
   `services/news/index.ts` 的同名检查**未**一并改：改它需要动一个无关票的 vm 测试上下文，收益不足。
5. **`failureClass` 联合类型**：与 `cloudfunctions/ai/types.ts` 同步一份清单，
   测试比对两边（服务端改名会在测试里暴露），未知分类收敛成空串、不冒充已知分类。
6. **`invalid_request` 文案**：改为「AI 服务无法处理这次请求（例如内容过长或格式不支持）」，
   不再说成「请求没有送达」。
7. **「不编造」的后置检查**：回答里出现语料之外的联系方式记号（手机号 / 座机 / QQ / 微信号 / 邮箱）
   时在这条回答上加提示。**这是后置标记，不是「不会编造」的保证**：只覆盖联系方式一类，
   其余编造（负责人、招新时间等）仍靠提示词纪律与人工评估。
   → 2026-09-19 在 `feat/department-qa-guard` 上与 PR #29 的守卫合并成同一套 `guardAnswer`（见下）。

## PR #29 移植（2026-09-19，分支 `feat/department-qa-guard`）

队友的 [PR #29](https://github.com/Iskuyal/wx-match/pull/29)（分支 `feat/department-ai-qa-verified`，作者 **SU5114**）
是同一票的另一份实现。它因为基线过旧、整体合并会回退 main 上的复核修复而被关闭，其中三样更好的东西
已移植到 `feat/department-qa-guard`：

1. **更强的确定性防幻觉守卫**（`pages/departments/qa.ts` 的 `guardAnswer`）：命中任何一条就**整条替换**
   成如实回答（不是只在回答下加一行提示）。联系方式一路与 main 既有的记号扫描
   （`CONTACT_RULES` / `scanContacts` / `findUnverifiedContacts`）**合并成同一套规则**，不留两份同类检查。
   - **能发现**：语料外的联系方式记号（手机号 / 座机 / QQ 号 / 微信号 / 邮箱）；没有否定表述的
     联系方式关键词（「联系方式」「联系电话」「办公地点」「公众号」等）；没有否定表述的人员称谓
     （「负责人」「指导老师」「秘书长」「站长」「队长」）；语料不支持的校区名（能认出回答在讲哪个
     部门时更严：该部门资料写明未标注校区，任何校区名都算）；「成立于 / 创办于 / 组建于 / 成立时间」
     后面的非语料年份；资料外的网址。
   - **不能发现**（不写成「不会编造」）：不带上述关键词的编造——直接写出的负责人姓名
     （「张三负责值班」）、招新时间（「9 月 1 日开始招新」）、活动细节、对资料的错误转述；
     把 A 组织的号码安到 B 组织上（号码本身在语料里）；校区名写法不在「广州 / 清远 / 广清 + 校区」
     之内时（如「南校区」）也认不出来。命中只按关键词与记号判断，**分不清「引用资料」与「编造」**，
     可能拦下「可以联系该组织的负责人了解」这类建议式说法。
   - **替换只作用于展示给学生的回答**：模型原话留在轮次的 `modelText`，下一轮送进模型的历史用原话
     （`historyMessages`），守卫不改写模型的上下文。
   - 已知盲区写进了单元测试（「拦不下什么必须如实写在测试里」一项），评估时不得因有守卫而放宽防幻觉判定。
2. **部门详情页的问答面板**：详情页现在也有对话框（部门提示语 + 4 条追问建议 + 输入框 + 回答气泡 + 降级说明），
   与列表页共用一份模板与样式（`pages/departments/qa.wxml` / `qa.wxss`）和一份按部门分开的会话
   （返回列表后对话不丢、可直接接着问）。交互按 main 的既有约定：**进入自动展开一次、可收起、
   关过之后（含下次进入与详情页）不再自动弹**，用户可主动点开；持久标记与列表页共用同一条
   `departments-qa-dismissed`。
3. **开发者工具验收检查**：`scripts/verify-wechat.cjs` 新增 4 项（提示与 5 个可点选项、点选项进详情页追问、
   AI 不可用时资料仍在且降级说明齐全、返回列表后对话不丢并能继续追问）。断言按「**有回答或降级提示
   都算通过**」写（模型不可用时页面显示降级提示同样通过），降级时必须找到 `#qa-offline` 且写明「仍可正常查看」；
   不把「有回答」当唯一判据。
   **这 4 项未在本分支的开发者工具里执行过**（需要人工开工具）；通过结论由脚本运行后写入
   `artifacts/verify/verification.json`，仓库里不预置。

## 一个必须先承认的现实

部门语料只有 5 个组织、约两千字。**这一票的 AI 发挥空间有限**，它撑不起「AI 能力融合」那 20 分——那部分的论据主要来自 05 与 06。把它做好，但不要在材料里把它写成 AI 的核心价值。

## 验收标准（2026-09-19 按实际证据标注）

> 与模板结构断言）；**它不等于开发者工具或真机验收**。`scripts/verify-wechat.cjs` 的 4 项新检查已经写好
> 但**尚未在开发者工具里执行**，真实模型问答仍未配置密钥——这两类证据产出前，下面的结论只按本地测试口径读。

- [x] 进入部门模块后有对话框，AI 提示「你想了解什么部门」并给出可点的选项（桩测试 + 模板结构断言；开发者工具待跑）
