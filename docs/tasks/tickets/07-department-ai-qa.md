# 07：部门 AI 问答

**What to build:** 学生进入部门模块后有一个对话框，AI 主动问「你想了解什么部门」并给出可点的选项；点进去是对应部门界面；有疑问可以继续追问。答案必须建立在已核实的部门资料上，资料里没有的要说「官网未公布」。

**Blocked by:** 01（AI 服务端基础设施）

**Status:** **in-progress（2026-09-19）**——页面、服务层、测试与文档已完成；`npm run typecheck` 通过，`npm test` 228 项全过（本票新增 17 项），开发者工具 18 项检查通过（本票新增 4 项）。**真实模型回答未验证**：`ai` 云函数已部署可调用，但 Ticket 01 的人工步骤 B（配置 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL`）未完成，追问只能得到分类失败；因此「回答与资料一致」与「防幻觉 100%」两条达标线仍待密钥配好后按评估表实测。

**成果位置**：服务层 `miniprogram/services/departments-qa.ts`（提示词与语料注入、历史裁剪、云函数调用、失败映射、防幻觉守卫、按部门的会话状态、视图组装）；页面 `miniprogram/pages/departments/index.*`（进入模块即有对话框：提示 + 5 个可点选项）与 `miniprogram/pages/departments/detail/index.*`（就当前部门追问），共用模板与样式 `miniprogram/pages/departments/qa.wxml` / `qa.wxss`；验收脚本 `scripts/verify-wechat.cjs`；测试 `tests/departments-qa.test.cjs`；证据 [Ticket 07 验证记录](../../evidence/p5-b/README.md) 与 [10 题评估表](../../evidence/p5-b/department-qa-eval.md)。

## 一个必须先承认的现实

部门语料只有 5 个组织、约两千字。**这一票的 AI 发挥空间有限**，它撑不起「AI 能力融合」那 20 分——那部分的论据主要来自 05 与 06。把它做好，但不要在材料里把它写成 AI 的核心价值。

## 实现要点

| 关注点 | 做法 |
| --- | --- |
| 只调一个入口 | 只调 `ai` 云函数（`action: "chat"`、`feature: "department-qa"`），不直连模型、不持密钥；模型调用、输入输出内容安全、失败分类与成本记账全在云函数侧（Ticket 01） |
| 接地 | 提示词把该部门**已核实资料整段**交给模型：介绍、下设部门、校区（有依据才写，否则写未公布）、联系方式、成立时间、动态列表、核查日期与来源 |
| 不编造 | ① 提示词要求资料里没有的一律回答「官网未公布」；② `guardAnswer` 确定性复核模型输出，命中未公布字段上的断言就整条换成如实回答，并把命中原因记进返回值（便于评估时统计） |
| 追问的上下文 | 只送最近 12 条消息（云函数上限 20 条）且以 user 起头；失败提示不进模型上下文；每个部门保留最近 10 轮，更早的丢弃并在界面标注「较早的对话已省略」 |
| 失败可区分 | 云函数返回的 `failureClass` 与 `message` 原样使用（三类文案各自独立）；调用没到云函数时按 `FUNCTION_NOT_FOUND` / 权限 / 超时分别映射，且每条都带「部门资料仍可正常浏览」 |
| 状态 | 对话按部门存在内存里（模块级会话），页面间跳转不丢；退出小程序即清空，不落本地存储 |
| 复用方式 | 列表页与详情页共用一份 `<template>` 与一份 WXSS（`qa.wxml` / `qa.wxss`），交互逻辑在服务层，页面只做编排 |

## 已知限制与未覆盖

- **防幻觉守卫覆盖的是「未公布字段上的显式断言」**（联系方式、负责人、校区、成立年份、来源链接），不覆盖自由文本里的任意编造。被拦下时整条换成如实回答，措辞有损失但语义成立——这是为「防幻觉 100%」这条硬指标做的取舍。
- **有校区的组织只做弱校验**：青年志愿者联合会资料里有「广州校区、清远校区」，因此不会拦它提到校区（提到别的校区也不会被拦）。
- **守卫不区分「引用资料」与「编造」的位置**：关键词附近没有否定表述就判定为断言，可能拦下「你可以联系该组织的负责人了解」这类建议式表述，代价是一句措辞。
- **轮数与长度上限**：每部门 10 轮、单条提问 200 字、送模型单条 1200 字，超出部分的行为（丢弃/提示）由测试覆盖，未做长对话的真实体验验证。
- **真实模型行为未验证**：回答质量、是否符合提示词、耗时是否 ≤2 秒，都要等 Ticket 01 配好密钥后按 [10 题评估表](../../evidence/p5-b/department-qa-eval.md) 记录。
- **真机未测**：`realDevice: false`。

## 验收记录中的操作发现（对后续验收有用）

1. 开发者工具**缓存共用模板文件的编译产物**：只跑 `npm run build` 不会让 `qa.wxml` 的改动生效，验收前必须重启开发者工具（症状是选择器命不中，页面本身正常）。
2. 开发者工具**两次验收之间不重启小程序**，模块级会话保留；脚本按绝对气泡下标判定会读到上一次运行的内容，已改成「先清空对话 + 按助手气泡数量增量判定」。
3. 「正在回答」气泡与回答气泡同类，模板给真回答加了 `qa-answer` 标记，测试锁住该标记防止脚本数错。
