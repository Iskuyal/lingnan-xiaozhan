# 05：课表截图识别导入与校对

**What to build:** 除了 Excel，学生还可以直接拍课表或从相册选一张课表截图，由多模态模型识别成结构化课表；识别结果先给学生逐项确认和修正，确认后才保存。保存后复用 03 已有的周课表展示与周次切换。

这一票是「AI 在本产品里真实不可替代」的第一处：课表截图版式千变万化，规则解析写不完，多模态是唯一务实解。

**Blocked by:** 01（AI 服务端基础设施，已合入 main）、03（课表存储与展示，代码已合入、云端部署未完成）。识别失败后的引导方式已于 2026-09-18 确定：**重试 + 引导 Excel 导入 + 手工录入兜底三者都可走通**（手工编辑已纳入首版，由 03 交付）；写入 [开发规格](../../development-spec.md)。

**Status:** in-progress（代码与本地测试完成，2026-09-18；按 01 已发布的 vision 契约与 03 的确认/保存链路实现界面）。**2026-09-19：用三张真实课表截图跑通端上链路的前半段**（入口 → 压缩判定 → 文件头判格式 → 上传 → 内容安全 → 模型），**并实测了模型不可用时的失败出口**。**模型这一环还没打通**：负责人加了 `AI_EXTRA_BODY_JSON`（关思考）与 `AI_TIMEOUT_MS=13000` 之后，**合成小图的链路冒烟已通过**（`npm run smoke:ai:vision`：`ok=true`、9.98s，证明模型支持图片），但**真实课表截图仍超时**（模型拿到 11.4 秒预算仍不够；缩到 1000px 宽也一样，说明卡的是固定时延而非图片大小）。**把三个超时抬到 60/50000/40000 之后，真实识别仍然不够**：模型拿到 40000ms 预算仍未返回（`elapsedMs=43336`）。量到的模型画像是**固定约 11 秒 + 约 86 token/秒 + 每门课约 300 完成 token**，外推一份 45 门课的课表要 170 秒以上（最紧凑格式也要 80–90 秒）——**超过 60 秒云函数上限，一次调用识别整张表在当前模型上不成立**。因此字段准确率评估仍无法执行。**2026-09-19 第四轮：改为「服务端分带并行识别」**（分支 `feat/vision-banded-recognition`）——按节次把整张表切成若干带并行调用模型，**图片只下载一次、只过一次内容安全**（配额是硬约束，客户端切块会让 `imgSecCheck` 按带数翻倍），带数由服务端按自己的超时预算算（客户端下发 `bands: 'auto'`）；越界课程按 `startSection` 确定性过滤，节次识别不出的只在第一带保留，任一带失败的节次写进 `problems` 与告警。按当前配置（`AI_TIMEOUT_MS=40000`）预算为 **6 带 / 每带 2 节 / 每带预计约 39 秒**，落在 60 秒上限内。**本地 `npm test` 315 项全过（含新增 14 项：预算数学、分带覆盖、合并过滤、图片只检一次、部分失败降级、上限优先）**，但**并发是否被中转接受、真实截图的分带耗时、模型是否遵守带范围指令都未实测**。**2026-09-19 第五轮：按两轴复核修掉三处真问题**——① 节次识别不出的课程在第一带失败时会被静默丢弃（改为「第一个成功的带」保留，并把轮不到保留的计数写进 `problems`）；② 每带输出上限沿用按整张表设的 2048，装不下 8 门课的中位输出（2400 token）会被截断而看起来像模型失败（改为按本带课程数抬高，并在 `finish_reason=length` 时告警）；③ 预算连 11 秒固定开销都装不下时仍切 6 带（默认 `AI_TIMEOUT_MS=8000` 正好命中，白花 6 倍调用），改为退回单带。另把 `bands` 补进云函数契约表、注明「一次 `vision` 记 N 条模型账」。**2026-09-20：分带并行已在云端验证通过**——`ai` 重新部署后（12 文件 / 52.4 KB），单带与 `bands: 'auto'`（6 带并行）**两条都 `ok=true`**，**6 个并发模型请求全部成功**（中转接受并发，这是最大的未知数），6 带的模型阶段 3571ms（串行会是它的 6 倍）。三条原本未验证的假设里，**并发与「分带确实压住墙钟时间」都成立**，「模型只报本带」在合成小图上成立。另：模型已换成 `deepseek/deepseek-v4.1-flash`，画像常数（11 秒 / 86 token/秒 / 300 token/门）描述的是旧的 qwen，`auto` 因此偏保守多切带（安全方向）。**真实课表截图与字段准确率评估仍未做**，本票保持 in-progress，逐项依据与复测命令见 [P5-B 验证记录](../../evidence/p5-b/README.md#2026-09-20-第六轮云端实测通过分带并行在真实链路上成立)。
