# 05：课表截图识别导入与校对

**What to build:** 除了 Excel，学生还可以直接拍课表或从相册选一张课表截图，由多模态模型识别成结构化课表；识别结果先给学生逐项确认和修正，确认后才保存。保存后复用 03 已有的周课表展示与周次切换。

这一票是「AI 在本产品里真实不可替代」的第一处：课表截图版式千变万化，规则解析写不完，多模态是唯一务实解。

**Blocked by:** 01（AI 服务端基础设施）、03（课表存储与展示）。识别失败后的引导方式已于 2026-09-18 确定：**重试 + 引导 Excel 导入 + 手工录入兜底三者都可走通**（手工编辑已纳入首版，由 03 交付）；写入 [开发规格](../../development-spec.md)。

**Status:** ready-for-agent（规格可执行；实现前须等 01、03 完成）

- [ ] 学生可拍照或从相册选课表截图
- [ ] 图片**先过内容安全检测**再送模型；被拒时给出可理解的提示而不是静默失败
- [ ] 识别结果以**可编辑**的形式呈现，学生逐项确认或修正后再保存
- [ ] 识别部分失败时明确标出未识别内容，允许重试；已识别结果可人工校对。**未识别部分可走 Ticket 03 的手工录入入口补上**
- [ ] 保存后复用 03 的周课表展示与周次切换，不另建一套
- [ ] 用**真实课表截图**验证并记录识别准确率（字段准确率 ≥90%，按 [开发规格](../../development-spec.md) 的分层达标线），样本中至少包含一个识别失败的案例
- [ ] 模型不可用时明确告知，并给出两个出口：引导到 Excel 导入，以及 Ticket 03 的手工录入入口；两者都要实际可走通
- [ ] `npm run typecheck`、`npm test` 通过；开发者工具验证截图到校对到展示的完整路径
