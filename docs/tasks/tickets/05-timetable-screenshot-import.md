# 05：课表截图识别导入与校对

**What to build:** 除了 Excel，学生还可以直接拍课表或从相册选一张课表截图，由多模态模型识别成结构化课表；识别结果先给学生逐项确认和修正，确认后才保存。保存后复用 03 已有的周课表展示与周次切换。

这一票是「AI 在本产品里真实不可替代」的第一处：课表截图版式千变万化，规则解析写不完，多模态是唯一务实解。

**Blocked by:** 01（AI 服务端基础设施，已合入 main）、03（课表存储与展示，代码已合入、云端部署未完成）。识别失败后的引导方式已于 2026-09-18 确定：**重试 + 引导 Excel 导入 + 手工录入兜底三者都可走通**（手工编辑已纳入首版，由 03 交付）；写入 [开发规格](../../development-spec.md)。

**Status:** in-progress（代码与本地测试完成，2026-09-18；按 01 已发布的 vision 契约与 03 的确认/保存链路实现界面）。**2026-09-19：用三张真实课表截图跑通端上链路的前半段**（入口 → 压缩判定 → 文件头判格式 → 上传 → 内容安全 → 模型），**并实测了模型不可用时的失败出口**。**模型这一环还没打通**：负责人加了 `AI_EXTRA_BODY_JSON`（关思考）与 `AI_TIMEOUT_MS=13000` 之后，**合成小图的链路冒烟已通过**（`npm run smoke:ai:vision`：`ok=true`、9.98s，证明模型支持图片），但**真实课表截图仍超时**（模型拿到 11.4 秒预算仍不够；缩到 1000px 宽也一样，说明卡的是固定时延而非图片大小）。**把三个超时抬到 60/50000/40000 之后，真实识别仍然不够**：模型拿到 40000ms 预算仍未返回（`elapsedMs=43336`）。量到的模型画像是**固定约 11 秒 + 约 86 token/秒 + 每门课约 300 完成 token**，外推一份 45 门课的课表要 170 秒以上（最紧凑格式也要 80–90 秒）——**超过 60 秒云函数上限，一次调用识别整张表在当前模型上不成立**。因此字段准确率评估仍无法执行，本票保持 in-progress。逐项依据与复测方式见 [P5-B 验证记录](../../evidence/p5-b/README.md#ticket-05-课表截图识别端上真实截图验收2026-09-19未通过模型这一环)。
