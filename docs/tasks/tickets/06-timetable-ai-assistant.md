# 06：课表 AI 助手（自然语言查阅与增改）

**What to build:** 导入课表后，学生用日常说法就能查阅和修改课表——问「周三第几节有课」，或者说「周三加一节课」。助手把自然语言变成结构化的查询或变更，改动前让学生确认，改完课表同步更新。模型不可用时明确告知，已保存课表照常可看；独立手工编辑入口尚待范围确认。

这是「AI 在业务流程中真实发挥作用」的第二处：把自然语言映射到结构化查询与变更，是表单做不到的事。

**Blocked by:** 01（AI 服务端基础设施，已合入 main）、03（课表存储与展示，代码已合入、云端部署未完成）。独立手工编辑已确认**纳入首版**（2026-09-18），降级时验证 03 的编辑入口可用；写入 [开发规格](../../development-spec.md)。

**Status:** in-progress（代码与本地测试完成，2026-09-18；PR 两轴复核（Standards + Spec）发现的问题已在本分支修复并补测；端到端与 10 题评估待 01/03 云端部署与真实模型）

## 两轴复核后的修复（2026-09-18，仅本地）

复核指出的问题已按下面几条修掉，逐项证据见 [P5-B 验证记录](../../evidence/p5-b/README.md)：

1. **修改分支真正走得通**：送给模型的课表文本里带上每门课的 id（`[id:tc_…]`，人类可读），
   提示词要求 update 时原样回填 `courseId`；页面仍拒绝未知 id。补了确认后真正调用
   `updateCourse` 的端到端测试。
2. **不再静默清空字段**：`buildChangeInput` 改为「读取当前课程 + 只应用这次真正指定的字段」——
   教师/地点/学分/校区/场地编号/备注/周次/来源/待核对提示在未指定时原样保留；
   云端 `updateCourse` 同步改为**部分更新**（只覆盖客户端显式给出的字段），
   两层共同保证「没被指定就不覆盖」（[云开发文档](../../cloud-development.md)）。
3. **确认框如实披露变化**：改为「当前值 → 变更后」逐条对比，只列会变动的字段并注明
   「其余字段保持不变」；与当前一致的方案不弹框、不写库，也不会有任何字段被清空。
4. **未知动作不再当成新增**：`action` 只接受 `add` / `update`，`delete` 或未知值一律按
   「不在能力范围」如实告知并指路课程列表的手工删除入口，不执行、也不展示模型的「已删除」。
5. **`safety.checked` 不再丢**：`checked !== true`（含字段缺失）时在对话里标出未检测；
   额度告警（`capWarning`）透传并在面板展示；未检测提示与判定和 Ticket 07 共用
   `services/ai.ts` 的一份。
6. **提示词带上当前周**：`buildSystemPrompt` 写入当前教学周与可切换总周数，课表文本逐门课
   按当前周标注「本周：上/不上」，回答「这周有几门课」不必再猜。
7. **去掉与 Ticket 05 的耦合**：`extractJson`、`MAX_HISTORY` 与消息形状挪到 `services/ai.ts`，
   05/06/07 共用一份；删掉重复的 `AssistantTurn` 与没人读取的 `PendingChange.message`。
8. **文档与数字**：本票的验证记录与测试数字按真实 `npm test` 重写；未验证项保持未验证口径。

硬性约束未放宽：改动仍需学生点确认才写库、`record.ts` 的整批校验保留、密钥只在云函数环境变量、
三类失败文案各自独立；模型输出不直接写库。

- [ ] 支持自然语言查阅，例如「周三第几节有课」「这周有几门课」；回答与课表实际数据一致
- [ ] 支持自然语言增改，例如「周三加一节课」；**改动前让学生确认**，确认后课表同步更新
- [ ] 指代不清或信息不足时**追问澄清**，不猜测后直接写入
- [ ] 超出课表范围的问题（例如问成绩、问选课）不强行作答，说明不在能力范围
- [ ] 模型不可用或超时：明确告知，已保存课表仍可查看，不返回假结果；**同时验证 Ticket 03 的手工编辑入口可用**（新增、修改、删除三项）
- [ ] 助手产生的文字过内容安全检测（复用 01）
- [ ] 记录每次交互的耗时，作为成本与体验的判断依据
- [ ] `npm run typecheck`、`npm test` 通过；开发者工具验证至少一条查阅与一条增改路径
