# 06：课表 AI 助手（自然语言查阅与增改）

**What to build:** 导入课表后，学生用日常说法就能查阅和修改课表——问「周三第几节有课」，或者说「周三加一节课」。助手把自然语言变成结构化的查询或变更，改动前让学生确认，改完课表同步更新。模型不可用时明确告知，已保存课表照常可看；独立手工编辑入口尚待范围确认。

这是「AI 在业务流程中真实发挥作用」的第二处：把自然语言映射到结构化查询与变更，是表单做不到的事。

**Blocked by:** 01（AI 服务端基础设施，已合入 main）、03（课表存储与展示，代码已合入）。两朵云函数 `ai` 与 `timetable` 已由负责人在控制台部署（2026-09-19，见 [P5-B](../../evidence/p5-b/README.md) 与 [P4-B](../../evidence/p4-b/README.md#2026-09-19-云端端上验收) 验证记录）。独立手工编辑已确认**纳入首版**（2026-09-18），降级时验证 03 的编辑入口可用；写入 [开发规格](../../development-spec.md)。

**Status:** in-progress（代码与本地测试完成，2026-09-18；PR 两轴复核（Standards + Spec）发现的问题已在本分支修复并补测；**2026-09-19 在开发者工具模拟器完成三条真实调用**——查阅与课表数据一致、增改取消不写库、确认后写入并同步更新（15 → 16，临时课程已清理），`npm test` 299 项全过；模型降级/超时、超出范围的问题被拒、真实调用里的 `safety.checked`、降级引导到 03 手工入口与 10 题评估仍未实测，见文末清单）

## 两轴复核后的修复（2026-09-18，仅本地）

复核指出的问题已按下面几条修掉，逐项证据见 [P5-B 验证记录](../../evidence/p5-b/README.md)：

1. **修改分支真正走得通**：送给模型的课表文本里带上每门课的 id（`[id:tc_…]`，人类可读），
   提示词要求 update 时原样回填 `courseId`；页面仍拒绝未知 id。补了确认后真正调用
   `updateCourse` 的端到端测试。
2. **不再静默清空字段**：`buildChangeInput` 改为「读取当前课程 + 只应用这次真正指定的字段」——
   教师/地点/学分/校区/场地编号/备注/周次/来源/待核对提示在未指定时原样保留；
   云端 `updateCourse` 同步改为**部分更新**（只覆盖客户端显式给出的字段），
   两层共同保证「没被指定就不覆盖」（[云开发文档](../../cloud-development.md)）。
3. **确认框如实披露变化**：改为「当前值 → 变更后」逐条对比，只列会变动的字段并注明
   「其余字段保持不变」；与当前一致的方案不弹框、不写库，也不会有任何字段被清空。
4. **未知动作不再当成新增**：`action` 只接受 `add` / `update`，`delete` 或未知值一律按
   「不在能力范围」如实告知并指路课程列表的手工删除入口，不执行、也不展示模型的「已删除」。
5. **`safety.checked` 不再丢**：`checked !== true`（含字段缺失）时在对话里标出未检测；
   额度告警（`capWarning`）透传并在面板展示；未检测提示与判定和 Ticket 07 共用
   `services/ai.ts` 的一份。
6. **提示词带上当前周**：`buildSystemPrompt` 写入当前教学周与可切换总周数，课表文本逐门课
   按当前周标注「本周：上/不上」，回答「这周有几门课」不必再猜。
7. **去掉与 Ticket 05 的耦合**：`extractJson`、`MAX_HISTORY` 与消息形状挪到 `services/ai.ts`，
   05/06/07 共用一份；删掉重复的 `AssistantTurn` 与没人读取的 `PendingChange.message`。
8. **文档与数字**：本票的验证记录与测试数字按真实 `npm test` 重写；未验证项保持未验证口径。

硬性约束未放宽：改动仍需学生点确认才写库、`record.ts` 的整批校验保留、密钥只在云函数环境变量、
三类失败文案各自独立；模型输出不直接写库。

## 端到端真实调用（2026-09-19，开发者工具模拟器）

维护者在微信开发者工具**模拟器**里对 `ai` 云函数（真实模型调用）与 `timetable` 云函数
（**真实云端课表**，负责人已导入 15 门课程）做了三条真实调用。以下引用是当次运行的原文。
完整记录与「本次未验证项」见 [P5-B 验证记录](../../evidence/p5-b/README.md#ticket-06-端上真实调用2026-09-19)。

**1. 自然语言查阅（对应勾选项 1）**：问「第 8 周星期二第 5-6 节有什么课？」→ 助手回答（原文）：

> 第 8 周星期二第 5-6 节有课：软件测试技术（基础）｜第 5-8 节｜第 3-6、8-17 周｜教师：方维亮｜地点：博雅楼-B604-前端H5创新应用中心。该时段属于这门课的第 5-8 节范围内，第 8 周也在它的周次内。此外星期二第 5-8 节没有查到其他课程。

周次、节次、教师、地点均与课表数据一致。

**2. 增改 + 取消确认（对应勾选项 2 前半）**：指令「在星期三第 11-12 节加一节课」，
在确认弹窗上**取消** → 助手回答（原文）：

> 已取消这次改动，课表没有变化。

课表计数 **15 → 15**（没有写库）。

**3. 增改 + 确认写入（对应勾选项 2 后半）**：同一指令，在确认弹窗上**确认** → 助手回答（原文）：

> 已按确认的内容更新课表。

课表计数 **15 → 16**；新增课程的字段与指令完全一致（`星期=3` `节次=[{start:11,end:12}]`
`教师=验收助手` `地点=验收教室`）；随后用云函数把这条临时课程删除，计数回到 **15**（临时数据已清理）。

**4. 与本票相关的标记改动（提交 `260ba8a`）**：课表助手的气泡原先只有 `qa-msg-ai`，部门问答用的是
`qa-answer`（`pages/departments/qa.wxml` 的注释写明「开发者工具验收靠它数气泡」）。本轮给助手气泡
补上同一标记，两个 AI 面板共用一套验收约定，并加模板断言防止被改掉。

**本轮未验证（不勾选）**：模型不可用 / 超时的降级（本条验收里那一项）、超出课表范围的问题被拒、
真实调用里 `safety.checked` 的具体取值、降级时引导到 Ticket 03 手工入口、追问澄清、逐次耗时与成本记录。
