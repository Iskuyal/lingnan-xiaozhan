# 04：扩大资讯同步范围并启用每日定时

**What to build:** 资讯不再只有「校园动态第一页 10 条」。按负责人选定的栏目与历史范围抓取入库，维护者可手动触发，之后每天自动同步一次；官网内容更新时已有文章被更新而不是产生重复条目，抓取出问题时保留上一次成功的内容。

**Blocked by:** 无。五项范围决策已于 2026-09-18 由负责人确定，结果与依据见 [P3-2 范围表](../p3-2-news-updates.md)：

| 决策 | 结果 |
| --- | --- |
| 首批栏目 | 校园动态 + **团委通知公告**（教务处暂缓：其通知正文多在微信公众号） |
| 历史范围 | 两个栏目全量（校园动态 126 页 / 1252 条，团委 16 页 / 155 条） |
| 增量更新 | 回看最近 3 页，按原文 URL 更新 |
| 请求与预算 | 间隔 1.3 秒、每批 ≤10 页；首次全量约 15 批 |
| 定时 | 每日 06:00，时区 Asia/Shanghai |

**选题理由**：实测校园动态 8/8 无学生行动项（事后报道性质），团委通知公告含公示与通知（真行动项）。依据见 [AI 资讯可行性实测](../../reference/ai-news-poc.md) 5.1 节（来源 Issue #16）。

**Status:** ready-for-agent

**新增模板适配是本票的主要工作量。** 团委通知公告的列表与文章模板**与校园动态不同构**：列表是 `<ul class="newsList">` + `<li>` 直挂 `<span class="date">` 与 `<a title>`（无 `a.tit`），文章是 `<h2 class="title">` + `<div class="property">` + `<div class="printArea">`（无 `h1.title`、无 `div.article-content`、无 PubDate 回退）。实测记录见 [官网资讯栏目与提取记录](../../news-sources.md) 的「通知公告类栏目」一节。

## 两个已实测的硬约束

- **官网限速**：lnc.edu.cn 的 WAF 明写「每秒不能多于 1 个页面请求」，超过会返回 403 并冻结 IP 数分钟以上，且继续重试会延长冻结。**必须按分批多次调用设计**，不能靠调大云函数超时一次抓完。
- **云函数超时 20 秒**（已从默认 3 秒调大）：单次调用能容纳的请求数有限。

## 验收标准

- [ ] 按选定栏目与历史上限抓取入库，按原文 URL 去重
- [ ] **为团委通知公告新增列表与正文解析规则**（`ul.newsList` + `<span class="date">` + `<a title>`；文章 `<h2 class="title">` + `div.property` + `div.printArea`），并为两套模板各留测试；团委栏目第 1 页条目全部解析出标题与日期
- [ ] **外链条目按实际处理**：正文不在官网（如教务处的微信公众号链接、团委条目若有外链）时，只保留标题、日期与原文链接，不把外链内容抓回入库；在验收记录里写明处理方式
- [ ] 官网内容更新后，已有记录被更新而不是新增重复条目
- [ ] 抓取按官网限速分批进行；遇到限速返回的 403 时停止本轮并记录，**不反复重试**
- [ ] 单批控制在云函数超时内（≤10 页、间隔 1.3 秒）；跨批可续跑，中断后不会留下不一致状态
- [ ] 缺日期的文章仍可保留有效正文；缺标题、缺正文、HTTP 失败不覆盖该篇旧记录
- [ ] 全部失败与部分成功不推进「整批成功」时间；页面时间语义不宣称整批成功
- [ ] 配置每日定时触发器，**每日 06:00、时区 Asia/Shanghai**，记录时区与实际运行时间
- [ ] 定时触发至少实际成功一次，保存触发配置、日志时间与同步统计
- [ ] 维护者仍可手动触发；**普通客户端触发仍被拒绝**（`newsSync.invoke: false` 保持有效）
- [ ] `npm run typecheck`、`npm test` 通过
