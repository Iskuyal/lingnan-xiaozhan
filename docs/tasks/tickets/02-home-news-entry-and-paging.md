# 02：首页最近资讯入口与列表逐页加载

**What to build:** 学生从首页就能看到最近几条校园资讯、并进入完整列表；列表往下翻能持续加载更早的内容，加载中、失败可重试、已无更多这几种状态都能区分。用云端现有的 10 条数据即可演示完整路径，不需要先扩大抓取范围。

**Blocked by:** None (can start immediately)

**Status:** done（2026-09-18 验收达成；本地票的 `done` 等价于 Issue 的关闭，口径见 [Ticket 索引](README.md)）

**成果与证据：** 实现见本次提交；开发者工具 12 项检查通过，截图与原始结果见 [Ticket 02 验证记录](../../evidence/p3-2/README.md) 与 [verification.json](../../evidence/p3-2/verification.json)。

- [x] 首页展示最近若干条资讯，含真实标题、发布日期与来源
- [x] 首页有进入资讯列表的入口，且不与现有「学生部门」「我的课表」入口冲突
- [x] 列表逐页加载：加载中 / 有数据 / 空 / 读取失败可重试 / 已无更多，五种状态可区分
- [x] 相同发布日期下顺序稳定；连续加载无重复条目、无遗漏条目
- [x] 加载下一页失败时保留已加载条目，不清空；重试成功后不重复追加
- [x] 分页读取全部走云端数据库，不引入随包静态快照
- [x] 列表与详情之间可往返，直接打开详情后也能返回
- [x] `npm run typecheck`、`npm test` 通过；开发者工具验证首页到列表到详情及分页路径

**验收说明（勾选口径）：**

- **「五种状态可区分」的证据分层**：五种状态在页面结构上可区分，并由 `npm run test`（58 项）覆盖分支行为；开发者工具本次只走到「已无更多」这一末页状态，因为云端现有 10 条小于单页 20 条。**没有**在真实工具中触发过翻页、重试与空态。
- **「分页路径」的实测边界**：验收脚本断言了页脚状态文案（「已经到底了」或「加载更多」二选一），未断言翻页本身。真实多页要等 [Ticket 04](04-expand-sync-and-daily-schedule.md) 把数据量扩到超过一页后补验；本条按「末页状态已实测、翻页逻辑由桩测试覆盖」勾选，不宣称多页实测通过。
- **顺序稳定**取 `date` 倒序后补 `id` 倒序，只保证不重不漏，不表达发布先后。
- **已知边界：并发的插入或改期会让 `skip` 偏移漂移。** 翻页期间若 `newsSync` 写入新文章或更新文章日期，页边界随之移动，可能漏掉少量条目；重复条目已按 `id` 去重。同步是手动或每日一次，与浏览重叠的概率低，故本票按偏移分页交付；数据量扩大（Ticket 04）后如需更严格，可改为按 `(date, id)` 游标分页。
- **整页边界行为**：条目数恰为单页整数倍时会多发一次空请求并短暂显示「正在加载更早的资讯…」，随后进入「已经到底了」。不影响正确性。
- **本次顺带修复**（原票未要求，一并说明）：资讯列表与详情在正常状态原本没有页内返回入口，详情直接打开时无法返回，已补齐；列表页的「返回首页」按钮同时解决从分享直达列表后无处可回的问题。
