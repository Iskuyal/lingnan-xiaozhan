# 03：课表 Excel 导入与周课表展示

**What to build:** 学生把从教务系统下载的课表文件导入小程序，导入前能看到解析结果并确认，保存后看到自己的周课表、可以切换周次，退出重进数据还在，且只看得到自己的课表。这条路径完全不依赖 AI，是课表模块的骨干——先把它做通，课表就有了可演示的底子，后续的截图识别（05）与 AI 助手（06）都复用它。

**Blocked by:** 无。P4-B 范围已于 2026-09-18 确定：解析策略、真实样本与手工编辑归属均写入 [开发规格](../../development-spec.md) 的「课表导入」一节。此票不依赖 AI；无 AI 依赖不等于无决策阻塞。

**Status:** ready-for-agent

**解析对象是网格矩阵，不是一行一课的平表。** 真实导出为：元信息行（学校 / 学年学期 / 院系班级）+ 表头行「星期一…星期日」+ 大节行（行标「一~六 / 1-6」对应起始节次）；每个（星期 × 大节）单元格是一串
`课程名 学分 教师 [周次]周 起-止节 楼-房间-用途 校区 场地编号`。
一格多课有两种已实测变体：单换行分隔（不同周次的课）与空行分隔（多课同格）。

**识别不出的只标记不猜**：周次写法不认识、节次倒置或越界时保留原值并标警告，交导入前确认页由学生裁决；行标识别不出时不要按行序猜节次。

**手工编辑已纳入首版**：本票交付独立于导入流程的新增、修改、删除入口与保存、用户隔离；05、06 复用同一入口。

- [ ] 学生能选择课表文件并导入。**注意小程序不能浏览手机本地文件**，只能从微信聊天记录选择，因此页面必须写清引导文案（例如「先在微信里把文件发给文件传输助手，再从这里选择」），避免用户以为「选不到文件」是缺陷
- [ ] 解析出学期、教学周、星期、节次、课程名、教师、地点，字段与 [开发规格](../../development-spec.md) 一致
- [ ] 按网格结构解析：表头行识别星期列，大节行标映射起始节次，单元格原文解析课程串
- [ ] 一格多课两种变体都能解析：单换行分隔与空行分隔；同一门课跨大节重复出现时去重，不并列占两格
- [ ] 解析不出的内容**只标记不猜**：在确认页标出待核对项，学生可修正或删除
- [ ] 导入前展示解析结果供学生确认，可放弃且不写入任何数据
- [ ] **支持独立于导入的手工新增、修改、删除**，保存后与导入数据同等展示；三项路径各自可用
- [ ] 保存后展示周课表，可切换周次
- [ ] 退出后重新进入，课表仍在
- [ ] 不同学生只能看到自己的课表（按微信身份 openid 隔离，不依赖教务账号）
- [ ] 解析失败（格式不符、空文件、非课表矩阵）给出可理解的提示，不写入半成品数据
- [ ] **使用 `tests/fixtures/timetable/` 的真实教务导出文件验证**，不是手写样例；四份样本（标准版式、单换行多课、多课同格、另一班级）全部跑通，其中非标准版式至少一个
- [ ] `npm run typecheck`、`npm test` 通过；开发者工具验证导入到展示到周次切换的完整路径
