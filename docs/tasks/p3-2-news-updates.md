## 问题与目标

P3-1 已实现校园动态云端同步与列表、详情，但用户尚不能从首页进入资讯，列表仅单次读取 20 条，同步仅手动抓取栏目第 1 页。P3-2 要让用户能从首页发现资讯、继续浏览较早内容，并使选定栏目按日更新。

依据：[开发规格](../development-spec.md)、[开发阶段](../development-phases.md)、[云开发现状](../cloud-development.md)。本文件是后续执行任务，不代表功能或线上验收已完成。

### 2026-09-18 新增的硬约束（影响扩大抓取）

- **官网限速**：lnc.edu.cn 的 WAF 明写「每秒不能多于 1 个页面请求」，超限会返回 403 并冻结 IP 数分钟以上。扩大抓取**必须按分批多次调用设计**，不能靠调大云函数超时一次抓完。
- **云函数超时 20 秒**：单次调用能容纳的请求数有限，与上面两条共同决定每批的条数。

## 范围

- 首页显示最近资讯及进入资讯列表的入口，保留现有部门与课表入口。
- 列表支持逐页加载，明确加载中、失败可重试、空列表和已无更多内容；失败不清空已加载条目。
- 按已确认栏目和历史范围抓取，按原文 URL 去重，支持已有文章更新。
- 保留维护者手动触发，再配置每天一次的定时同步；记录触发时区、运行时间和验证结果。
- 抓取失败或解析出无效标题/正文时保留旧记录；部分成功不得冒充整批成功。
- 验证维护者调用、客户端只读以及同步时间的展示语义。

不包含：课表、AI、学生投稿、组织后台；不默认导入全部历史或全部栏目，也不默认增加正文图片、离线快照和新的公开状态集合。

## 验收标准

- [ ] 从首页可进入资讯列表、打开详情并返回；最近资讯有真实标题、日期与来源。
- [ ] 分页在相同发布日期下有稳定顺序；连续加载无重复、无遗漏，末页有结束状态。
- [ ] 下一页请求失败保留已有条目；重试成功不重复追加；空数据与请求失败可区分。
- [ ] 对已确认的同步范围连续执行两次，不新增重复 URL；官网内容更新后可更新已有记录。
- [ ] 缺日期仍可保留有效正文；缺标题、缺正文、HTTP 失败不覆盖最后成功内容；覆盖全部失败与部分成功。
- [ ] 页面时间准确表述当前文章的成功写入时间，不宣称整批成功；私有错误详情不公开。
- [ ] 普通客户端触发同步被拒绝，维护者手动调用成功，客户端仍可读资讯。
- [ ] 定时触发至少一次实际成功，保存触发配置、日志时间、同步统计与部署版本。
- [ ] `npm run typecheck`、`npm test` 通过；开发者工具验证首页至详情及分页路径。
- [ ] 记录真机和未登录单页模式的实际结果；尚未执行则明确未验证，不以模拟器结果替代。
