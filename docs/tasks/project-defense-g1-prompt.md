# 项目讲解与答辩练习：G1开始提示词

关联任务：[Issue #112](https://github.com/Iskuyal/wx-match/issues/112)：完成受控文字PoC与首次反馈评测（Blocked by [Issue #111](https://github.com/Iskuyal/wx-match/issues/111)）。

状态：供另一位执行者执行 **G1 受控文字 PoC 与首次反馈评测**。这是**真实模型调用**阶段，与 G0 的离线准备不同；但它**不是**页面开发或功能实现（材料→三轮→复盘→一次重答的生产流程是 G3）。阶段范围见[执行方案](../planning/project-defense-stages-2026-09-30.md)；素材依据见[联网研究](../planning/project-defense-examples-and-materials-2026-09-30.md)；素材与冻结样例在 [G0 素材包](../evidence/project-defense-g0/README.md)（其「G1 怎么用这个包」一节列了五步用法）。

以下整段可以复制给其他执行者：

```text
你在 wx-match 项目工作。现在只执行“项目讲解与答辩练习”G1：受控文字 PoC 与首次反馈评测。

前置与范围
- 前置是 G0（Issue #111）已被负责人验收；G0 产物在 docs/evidence/project-defense-g0/（PR #118）。
  若 #111 尚未验收，只做不依赖它的准备（脚本骨架、样例装载、离线校验）并如实报告阻塞，
  不要先花额度。
- 本阶段要真实调用模型，但只做受控 PoC 与首次评测：加一个维护者脚本，走**既有** ai 云函数的
  安全 / 限流 / 记账链路，不新建旁路。
- 不做：新增页面、实现生产流程（G3）、部署云函数、新增服务端 feature 约束。若 PoC 显示
  非改服务端不可，记成 G3 的输入并说明理由，不要现在做。

开工前
1. 核对当前分支、工作区与远端；保留无关改动；用独立 worktree 与 codex/ 分支，从最新 main 取。
   先报告基线 SHA 与现有未提交文件。
2. 读 AGENTS.md、docs/agents/issue-tracker.md、docs/README.md、CONTEXT.md、docs/product/spec.md、
   docs/planning/project-defense-stages-2026-09-30.md，以及 G0 素材包的全部文件
   （重点是 rubric.md、samples-*.json、abnormal-cases.md、budget.md）。
3. 读 docs/development/cloud/ai.md（尤其「内容安全适配层」「失败分类与默认文案」）与
   docs/development/local-setup.md。只追读本任务引用的必要文件，不全量加载历史日志。

额度与调用纪律（先查再调，不要假设有额度）
- 完整三轮最多 4 次模型请求，一次重答再加 1 次 ⇒ 一次完整会话最多 5 次。
  原文未写明每轮与请求数的精确映射，按实际请求数回填并在报告里说明口径。
- 每批最多 12 个云请求（含重试）。12 是上限，不是当天必有余额。
- 与升学评测共用个人限额、内容安全预算与月度 50 元上限。调用前用维护者 usage 动作读回当月
  累计，并确认当日剩余额度。
- 内容安全接口未上架期间只有 100 次/天；一次 AI 调用至少消耗 1 次检测，输出还要按片加
  （输入 2000 字/片、最多 10 片；输出最多 20 片），长回答会成倍消耗当日额度。配额用尽会
  fail-closed 拦掉当天全部 AI 调用（errcode 45009），此时先查 45009，不要往模型或密钥方向找。
- 另有个人日额度（2026-09-30 升学评测的记录是 30 次/天并用尽；真实值以读回配置为准）。
  **额度不足时只交付离线部分，把真实评测明确记为未完成**，不伪造结果、不为赶进度包装成功。
- 不调高限额、不关闭内容安全检测（尤其不得为省配额去关 AI_MODERATE_OUTPUT）、
  不改 AI_SAFETY_FAIL_MODE。本阶段不改环境变量。
- 逐次记录客户端端到端耗时、服务端耗时、token 与费用；未知不记成已知 0。

怎么调（关键约束）
- 内容安全必须由小程序端触发：控制台「测试」页、CLI、HTTP 触发、云函数互调都必然返回
  -501001，测出的是触发方式不对而不是接口不可用。复用 scripts/lib/mini-connect.cjs 与
  scripts/eval-advancement-model.cjs 的做法：连开发者工具，再在小程序里
  wx.cloud.callFunction({ name: 'ai', data: ... })。
- 前置：开发者工具已登录并启用 CLI 服务端口；dist 已构建；ai 云函数已部署且与本地构建一致。
  新版 ai 要与新版客户端一起发——旧客户端在长对话里会被“输入过长”拒绝。
- 给本次调用一个专门的 feature 值（如 project-defense），便于从记账里区分成本；不要复用
  advancement-qa（那会触发升学问答的服务端约束）。
- 开发者工具的已知坑：npm run build 后可能“视图层新、JS 旧”，用 cli cache --clean compile
  清一次缓存再跑；自动化桥对单次 evaluate 有约 10 秒上限，长调用要改成轮询取结果；
  mockWxMethod 必须传结果对象（传函数会弹出真对话框并把工具卡住）。

冻结与评测纪律
- 6 个开发样例、2 个留出样例与 rubric.md 已在 G0 冻结。开发样例允许用于调整提示词；
  **留出样例不得用于调整**，其首次结果必须单列记录，不并入开发样例通过率。
  冻结发生在模型首次运行之前，本阶段没有任何“冻结后调参”。
- 按 rubric.md 的四步顺序逐例判定：先核对引用 → 再判反馈是否对应回答 → 再判追问是否有针对性
  → 最后判有没有把未验证说成已完成（这一项一旦发生即整例不通过）。
  **不得以润色流畅度当作证据改善**；不输出职业等级、官方成绩、录用保证或教师认可；
  材料差异必须提示核对，不得判学生撒谎或给出道德评价。
- 6 个开发样例至少 5 个要体现对应回答的有效反馈；反馈中的引用编号与原句 100% 对应当前
  材料 / 回答。
- 异常样例（空 / 超长 / 无关 / 指令注入 / 索要成绩 / 模型不可用）的判据见
  docs/evidence/project-defense-g0/abnormal-cases.md。由本阶段实际构造并**单列记录**，
  不得并入 6 例通过率，也不得用它们调参后仍当未见样本。
- 逐例逐字保存原始响应，不改写；失败与空响应保留实际记录，不隐藏。

判定与收口
- 先跑一次完整三轮加一次重答，确认流程可运行，并记录实际请求数。
- 两轮调整仍不达标就缩为“单题 → 依据反馈 → 重答”重测；仍不行保留探索原型，
  不扩语音、图片、RAG 或评分来掩盖反馈问题。
- 产出放 docs/evidence/project-defense-g1/：逐例记录（原始响应、耗时、token、费用、判定）、
  额度与配置读回、go/no-go；首评与调参后复测分开统计。
- 跑 npm run docs:check 与 git diff --check；新增脚本要有离线自检。只有改了业务代码才补
  构建 / 行为回归；不要为了 PoC 部署业务代码。
- 中文提交、推送并开 PR，链接 Issue #112；附额度账、逐例记录与验证结果。

最后报告必须说清
- G1 的“真实模型可行”只在真实调用成功、且引用核对与越界判定达标时才成立；额度不足、
  只跑通桩或只有短文本成功时，保留未完成状态。
- 不得写成：新功能已上线、真实学生学习效果已达标、教师已认可或已评价。自编样例只能检验机制。
- 逐项说明：6 个开发样例通过几个、2 个留出样例的首次结果、异常样例的实际记录、
  实际花费与剩余额度、以及 PoC 对 G2/G3 的结论（可行 / 需改什么 / 不可行）。
```

- 若额度或部署条件在开工时已不满足，执行者应先交付离线准备并回报具体缺口，不要用桩输出填充“完成”。
