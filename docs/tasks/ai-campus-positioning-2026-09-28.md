# AI 校园选题再讨论：参赛约束与主线重审

日期：2026-09-28。状态：**讨论记录，不是实施任务、范围批准或已完成成果。** 本文承接[前两轮发散](ai-campus-ideas-2026-09-27.md)与[原优先级方案](ai-campus-priority-plan.md)。原方案保留历史推敲；最新判断以下文负责人反馈为准，尚无新的主线决定。

## 1. 负责人明确的约束与最新反馈

- 探索学校与 AI 融合的内容，当前不以取得学校授权、接入学校后台或校方人员参与运营为前提。
- **必须以符合参赛要求为前提**，不能只追求新奇、AI 视觉效果或功能数量。
- 希望结合已有成果发散思考，但没有批准新增功能或改变首版范围。
- 最新反馈原话：**“我觉得校园的动态新闻和课表的内容不足以体现出AI”。**

这条反馈意味着下一轮需要重新评估核心业务的 AI 价值；不能把此前推荐的“通知/海报 → 课表/行动卡”当作负责人已接受的最终方向，也不能仅以现有模块复用率决定选题。它不等于要求删除新闻、课表或否定现有成果。

## 2. 当前问题的讨论判断

现有三个 AI 落点是部门问答、课表图片识别、课表助手；首页主要入口为课表、部门、资讯。截图识别能够把非结构化材料变成数据，课表助手已有查阅、新增/修改提案及确认写入，属于实际能力。实现与验收证据的边界见[项目状态](../status.md)。

助手的分析是：AI 感不强既有可靠性、效果记录和展示完成度因素，也有产品主线因素。部门问答使用范围较窄，截图导入偏首次使用，简单查课可能不如直接看课表方便；继续补齐原功能不必然建立“学生为什么持续需要 AI”的理由。这是产品判断，不是用户研究结论，也不是赛事评分结论。

## 3. 参赛筛选标准

以下依据仓库现有[赛事要求](../competition.md)与[比赛工作流](../workflow.md)，本轮没有重新核验外部赛事规则。

| 维度 | 权重 | 候选方案需要回答的问题 |
| --- | --- | --- |
| 技术实现 | 25% | 核心流程能否真实运行并提供稳定性证据？ |
| AI 能力融合 | 20% | AI 对结果有什么贡献，怎样评估？ |
| 创新设计 | 20% | 相比现有做法或通用 AI，具体改善了什么？ |
| 场景落地与商业闭环 | 15% | 谁使用、如何触达、如何持续服务，成本如何承担？ |
| 产品体验与用户增长 | 10% | 首次价值、再次使用和合理传播路径是什么？ |
| 完整性与材料质量 | 10% | 能否稳定演示，完成七项说明并复现成果？ |

已记录要求强调微信生态、AI 与真实业务场景，未把学校系统接入或学校授权列为统一参赛前提；这不等于对具体数据使用、学校标识、公开发布或第三方内容作出许可判断。学校统一上报参赛作品与学校官方运营产品是不同事项。

采用学生主动提供、允许处理的材料，不假设自动读取微信群聊。商业闭环需要解释触达、价值、回访和成本，不应为材料硬加收费或虚构学校采购。当前预览演示、未发布的边界保持不变；分享增长、用户量和学校合作只能按实际证据表述。

## 4. 本轮已提出的候选点子

以下全部未实现、未验收；难度为相对现有项目的讨论估计。

| 候选 | 可观察的 AI 结果 | 难度与关键条件 |
| --- | --- | --- |
| 作业截图 → 执行计划 | 提取要求、截止时间和交付物，拆解任务并提出安排 | 中高；新增任务数据，耗时可纠正，课表空白不等于可用时间 |
| 通知变更 → 影响分析 | 找出课程变化影响的个人安排，预演并确认调整 | 高；单周例外、任务冲突和撤销机制 |
| 活动海报 → 是否参加与行动卡 | 分开识别报名/材料截止和活动时间，对照已知条件与课表 | 中；缺失条件追问，不代理报名 |
| 考试范围 → 空档复习计划 | 基于自带范围与小测反馈调整复习任务 | 中高；内容依据和学习效果评估 |
| 小组任务 → 协作启动包 | 分工草稿、交付检查单、会议议程与共同空档 | 中；可先由一人录入成员提供的空档 |
| 比赛通知 → 准备检查单 | 对照自填情况识别满足/缺失/待确认条件，倒排准备事项 | 中；资格结论必须有原文依据 |
| 办事指引 → 材料检查 | 识别缺项、地点时间和需追问的问题 | 中；绑定具体来源，不假设后台可查 |
| 实训前 AI 口头预演 | 根据获许可指导书提问，发现步骤遗漏并生成练习清单 | 高；专业内容验证，现有模块复用较少 |
| 校园沟通准备 | 把模糊诉求整理成事实、问题和消息草稿 | 低；适合作为辅助功能 |
| 多份通知 → 差异核对 | 比较时间、地点、对象与版本差异 | 中高；无可靠来源时不判真伪 |
| 教材照片 → 课程适配核对 | 核对版本、ISBN 与学生自带书单 | 中；先做个人核对，不直接建设交易平台 |
| 一周记录 → 个人复盘 | 从已确认任务和完成记录形成复盘与调整建议 | 中；依赖真实积累，不能编造行为 |

讨论时重点展开过三个方向：课表驱动的行动助手、变化后的安排预演、活动海报的个人相关性分析。通用资料问答、测验生成、任务拆解已有同类工具，单独提供这些功能不足以证明差异。参考：[Google 的基于材料的闪卡与测验介绍](https://workspaceupdates.googleblog.com/2025/09/flashcards-quizzes-reports-notebook-lm-google-education.html)、[Goblin Tools Magic ToDo](https://goblin.tools/ToDo)。这些链接仅支持竞品能力对照，不证明本项目需求或效果。

## 5. 此前建议及最新修正

助手此前建议“校园信息行动助手”：截图/海报 → 信息提取 → 个人课表冲突 → 确认保存。实现顺序曾建议先海报行动卡，再作业计划，最后处理变化后的重新安排；参赛范围建议则是只选海报和明确调课通知两类输入。两者都是不同层面的讨论建议，均未批准，不能作为既定实施路线。

失物招领、技能匹配、教材交易曾因双边参与和交接成本降级；报障、诉求处理因缺少实际处理方暂缓；实训陪练虽然复用少，但有职业院校场景特色。以上排序同样需要随最新选题目标重新比较。

**负责人最新反馈后，新闻和课表不足以承载主线的问题保持开放。** 下一轮应探索学习诊断、专业技能练习、作品改进或真实校园协作等更需要 AI 理解与反馈的任务；这些只是探索领域，尚未形成推荐结论。现有模块可以作为辅助背景，不把“必须围绕课表”当成选题限制。

## 6. 下一轮的可验证目标

1. 找到具体用户、具体困难及现有解决办法，区分学生需求与团队想象。
2. 描述一条完整路径：输入 → AI 判断/反馈 → 用户行动 → 结果核对，而不是只列模型能力。
3. 用同一任务比较人工/规则方法、通用 AI 与候选产品，预先定义可观察的改进指标。
4. 确认没有学校后台或处理人员时能否完成这条路径，是否能取得获许可样本与可靠评价依据。
5. 再按参赛六维度、交付成本和现有资产复用比较；负责人选定后才更新规格和拆分任务。

本轮仅记录讨论，不修改已确认产品范围、领域决策、验收状态或执行票，不宣称任何新能力已实现。
