## 四、坑（更新版，替代 G4 提示词第二节）

1. **`npm run build` 会让自动化桥失效**（`timeout waiting for automator response`、0 次云请求）。顺序：**build → `cli cache --clean compile` → `cli auto --project <dist> --auto-port <端口> --trust-project` → 再跑 node 脚本**。
2. **`cli auto` 在端口被占用时会自动换端口**：它输出的 `autoPort` 才是真实端口（本轮 9420 被遗留实例占用，实际绑到 **9421**）。脚本用 `WECHAT_AUTO_PORT` 指过去，否则**会连到旧构建还不自知**。
3. **不要用带 build 的 npm 脚本跑真实调用**（`npm run poc:defense:session` 等会先 build ⇒ 桥失效）。用 `node scripts/...` 直接跑。
4. **在 `mini.evaluate` 里 `await` 云函数调用会先超时**（长调用时表现为 `timeout waiting for automator response`，看着像桥坏了，其实是等得不够）。**正解**：先发出去、结果挂 `globalThis`、再轮询。`scripts/probe-ai-raw-response.cjs` 与 `verify-defense-g4-comparison.cjs` 已按这个写法修过。
5. **`--resume` 的跳过粒度是整段会话**，且判定"已判定"必须同时认 `feedback` **和** `review`（会话最后一轮停在 `review`）。本轮就是因为漏认 `review`，**白跑了 6 次调用**——修好了，但别再犯。
6. **被额度拒绝的请求也计数**（`consumeCounter` 先自增再判限）⇒ **反复试探只会让当天更早打满**。
7. **`AI_USER_DAILY_LIMIT=30` 与内容安全 100/天是两个不同的上限**，`failureClass` 都是 `quota_exhausted`，**但排障方向不同**：文案「内容安全检测的额度已用尽」+ `detail` 含 45009 → 微信侧配额；文案「今日 AI 调用次数已达上限」→ 服务端个人日计数。**别混。**
8. **答辩练习页面会把两种额度映射成同一句**「额度或当日检测配额已用尽」⇒ **从页面文案分辨不出**，必须读**原始返回**（用 `probe-ai-raw-response.cjs`）。
