# ADR-0004：限定周次调课使用课程拆分与服务端事务

日期：2026-11-10；2026-11-11续办。状态：已部署并完成一个真实业务样例，详见[最终证据](../evidence/notice-plan-loop-2026-11-10/README.md)。关联 [Issue #145](https://github.com/Iskuyal/wx-match/issues/145)。

## 背景与取舍

负责人要求补齐限定周次调课和计划保存后可见，并确认三张设计图。ADR-0003 的单周停课仍按周次集合剔除，本决策补充改时间、改地点。

客户端先改原课再新建课程，第二步失败或丢响应会留下半次调课；新增例外表又会改变所有读取和导入替换语义。选定保留现有课程结构，由服务端事务一起保存原课、拆课和重试凭据。影响范围覆盖原课全部周次时原位修改，不写空周次课程。

## 决策

1. `applyScopedChange` 接收课程id、明确周次、时间/地点、原业务快照和稳定操作编号。身份来自微信上下文；未知周次、范围内原本无课、快照已变更整项拒绝。
2. 原课保留其他周次，拆课只含本次周次。时间、地点、颜色、教师、学分和课程原文由服务端按原记录保留或规范化，不接受客户端更换归属或来源。
3. 编号属于提案，丢响应后重试不换编号、不重复拆课。编号对应另一份内容时拒绝。`undoScopedChange` 核对两部分都未再变更后原子恢复；已撤销操作不重放写入，避免覆盖后续手工修改。
4. 凭据使用 `timetable_courses` 中的 `notice-receipt-` 哈希文档，用 `receiptOwner` 而非课程 `owner` 字段归属，不混入列表，不返回其中快照。后续读取时尝试清理超过24小时的凭据，清理失败不影响课程读取。
5. 同课同范围的时间与地点调整合成一项。不同范围、重复或互斥字段先要求分段核对。“从第N周起”只选该课后续实际有课的周。
6. 服务端先定位本人文档，事务中只用 `doc`，不调用外部服务；核对批次及业务快照。已有批次标记参与事务写冲突保护，提交后再次核对批次；重新导入时以新课表为准并要求刷新。

接口依据：[CloudBase官方事务说明](https://docs.cloudbase.net/database/transaction)，并核对了本机锁定SDK源码。事务只放文档操作；每段通知仍逐项执行，不宣称整段通知拥有全局事务。

## 影响与验证

需要更新 `timetable` 及新模块 `scoped.js`，仅更新客户端不能启用真实云端接口。导入整份替换仍覆盖手工修改。计划继续只存本机，按实际日历日期对应周课表，不纳入课程数。

本地测试覆盖限定/全部周次、原子失败、响应丢失、幂等撤销、身份隔离、后续修改保护、每周课与30周字段长度。原生页面经自动化桥调用本机实际云函数入口，数据库和模型为夹具；不外推真实事务性能或模型理解率。

11-11补充：凭据查询结果带有数据库顶层 `_id`，写回前必须去除。首次真实撤销暴露这一点，已给夹具补同约束并先复现后修复；修复后真实事务、幂等与撤销通过，不能把修复前夹具结果描述成已通过真实平台限制。
