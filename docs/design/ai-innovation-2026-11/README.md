# AI 创新点与界面升级提案（2026-11）

状态：**已定稿并实现（2026-11-10）**。负责人（2026-11-10）拍板「全部实现」A/B/C/D 与界面升级后，设计与代码均已落盘，本目录只留设计依据。画面里的课程、时间、通知与计划块都是示例数据，不是运行截图；本轮**没有在微信开发者工具或真机实测**（CLI 访问令牌只有负责人能提供，本次未取得），验收止于离线构建与 866 项自动化测试。

## 为什么做

赛事评语（2026-11-10，负责人转述）：「校园类小程序同质化比较严重。用 AI 创建、修改课表是亮点。可以加入更多 AI 功能，同时优化应用界面。」

由此定两条原则：

1. **沿着已经被认可的亮点做深**。课表 AI 已被认可，新功能都围绕「课表是个人时间数据」展开，不再增加部门、资讯这类校园平铺入口。
2. **AI 要替学生完成一件事**，不只是聊天。每个新落点都要求输出结构化结果：时间线、变更提案或计划块，并能确认、追溯和撤销。

## 候选创新点（按投入产出排序）

| # | 名称 | 学生痛点 | AI 做什么 | 复用现有能力 | 估计工作量 |
| --- | --- | --- | --- | --- | --- |
| A | **通知一键调课**（02） | 班群里的调课、停课、补课通知要自己逐条改课表 | 把通知文本或截图解析成 *多条* 变更提案，并附原文依据、冲突检测，确认后写入，可撤销 | 课表助手的 change 提案与确认、截图识别（vision）、内容安全 | 中：把单条 `add/update` 扩为批量，并增加 `cancel`（单周停课） |
| B | **今日 AI 简报**（01） | 首页只有入口，打开后还要再点进课表 | 根据课表、作息和目标日生成一段 3 句话简报，同时给出今日时间线和空闲时段 | `services/timetable/now.ts`、目标日、作息设置 | 小到中：时间线可以纯规则实现，只有简报这一句由模型生成，可缓存一天（**实施时改为整段纯规则**，见下文） |
| C | **目标倒排计划**（03） | 四级、期末这类目标知道要准备，却不知道放在哪个时间段 | 读取目标日和课表空闲格，结合学生的一句话约束，生成每周学习块；学习块用金色虚线叠在周课表上 | 目标日、课表周视图、助手对话 | 中到大：需要新增「计划块」数据，并与正式课程分开存储 |
| D | 语音提问 | 走路时不方便打字 | 微信同声传译插件或录音转文字后交给课表助手 | 课表助手 | 小，作为 01 输入条上的附加入口（**实施时确认无转写通道，按钮只做诚实降级**，见下文） |

建议首轮做 **A + B**：A 最能直接回应「AI 改课表是亮点」，演示时有明显变化；B 改的是评委第一眼看到的首页，同时解决「同质化入口墙」的观感问题。C 做成第二阶段，或在演示中只展示设计图。（**实际执行结果**：负责人 2026-11-10 决定四条一起做，见下文「已拍板项与结论」。）

各方案的边界（实现时作为硬约束）：

- 写入课表仍然沿用「提案 → 学生确认 → 写入」，AI 不直接改数据；批量提案逐条可取消，冲突项默认不勾选。
- 简报中的每个事实都要来自已保存的数据；没有填写作息时不推算时刻，这条与 `now.ts` 的现有约定一致。
- 通知截图属于 UGC，要经过图片内容安全检测；个人日额度、月度 50 元上限和三类失败文案保持不变。
- C 的计划块不是课程，不参与「本周 N 门课」统计，也不影响导入时的整份替换。

## 界面升级方向：「校园手册 + AI 金」

在现有岭南红、纸白底和宋体标题的基础上，只增加一种语义色，用来区分 AI 内容（见 04）：

- **岭南红**：学生要做的动作，例如发送、应用、保存。
- **校徽金** `#a67f1c`（即现有 `--gold-deep`）：AI 产出，包括简报、提案和计划，统一配「AI ·」标签和依据条。
- **青绿** `--success`：已经生效或空闲的时间。

另外三处调整：首页从「入口墙」改成「今天」，入口收成一排四个小图标；首页常驻「问 AI」输入条，支持拍照、语音和文本；所有变更都显示前后对照，写入后给出 10 秒撤销提示条。新增的 `--ai / --ai-soft / --ai-line` 已加进 `miniprogram/app.wxss`，本目录的 `_tokens.css` 保持同名同值。

## 落地对照（2026-11-10）

负责人拍板「全部实现」，四条创新点与界面升级都已写进小程序。与上面设计图一致的部分不再重复，这里只记录**实现位置**和**有意偏离**：

| # | 落在哪 | 与设计图的差别（及原因） |
| --- | --- | --- |
| A 通知一键调课 | `services/timetable/notice.ts`（解析 + 提案 + 写入计划 + 逆操作）、`pages/timetable/` 的提案卡与撤销条 | ①不做截图识别入口：截图识别在「导入课表」页已有 vision 链路，本页只复制文字，页面上直接指路而非承诺两种输入；②「逐条修改」改为就地展开「将写入：…」，不跳到编辑页；③撤销只保留最近一次应用，不做多批历史 |
| B 今日简报 | `services/timetable/brief.ts`（纯函数）、`pages/home/` 首页改「今天」 | 简报**不调用模型**：每次打开都要显示，调用成本随打开次数增长且断网/超时空一块，而这几句只是把「已保存课表 + 目标日 + 作息设置」翻成人话。因此首页标签写「**今日简报**」而不是「AI 简报」，不替模型多认领功劳 |
| C 目标倒排计划 | `services/goals/plan.ts`（纯函数）、`pages/goals/plan/`、目标日列表的「AI 排计划」入口 | ①「加入课表」只把计划存本机（`study-plan/v1`），不往云端写伪造课程：云函数 `source` 只认 excel/manual/photo，写「计划课」会污染真实课表与导入替换；②迷你网格与计划块只落周一至周五；③节次换算分钟时，作息填了就按真实起止算，没填按每节 45 分钟并在页面上明说 |
| D 语音提问 | 首页输入条的麦克风按钮 | **未接入语音识别**：项目没有声明同声传译插件，云函数也没有 ASR 通道。按钮如实提示「语音输入暂未接入，先打字或拍照吧」，不假装录音或转写。文本与拍照两个入口可用 |
| 界面升级 | `app.wxss` 的 `--ai / --ai-soft / --ai-line`、`styles/ui.wxss` 的 `.ai-tag / .ai-src / .ai-card / .ai-note`、首页与三处页面 | 三色语义按 04 落地；`.ai-tag` 与 `.ai-src-item` 的文案写在 WXML 里，不用 CSS `content`（WXSS 不允许注释外出现中文，`tests/wxss.test.cjs` 会拦） |

## 已拍板项与结论

1. 首轮范围：**A + B + C + D 全部实现**（负责人 2026-11-10 决定），不做分期。
2. 首页从入口墙改为「今天」：**采纳**。入口收成主卡与两列，体测/升学/答辩仍留在首页「学习与成长」，没有做二级「全部」页。
3. A 的单周停课在数据层如何表示：**摊平进课程的 `weeks` 集合**，不新增例外记录。理由、比较与限制见 [ADR-0003](../../adr/0003-single-week-cancellation.md)。
4. 简报是否调用模型：**不调用**。规则模板已经能覆盖设计图里的三句话，同时省额度与时延（原因写在 `services/timetable/brief.ts` 文件头）。
5. 金色是否进全局令牌：**已加入** `app.wxss`，`_tokens.css` 同步为同名同值；课表助手与目标日的新入口已用 AI 标签/金框，部门问答保持原样（不为了统一而改与本次无关的界面）。
