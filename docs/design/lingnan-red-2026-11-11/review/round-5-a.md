# 岭南小栈独立产品视觉评审

证据版本：**LN-194315d53ea8b822**。本报告只评价本次提供的静态设计提案。

## 1. 总体判断

**最强的设计决定：**09 的原安排／新安排并列、仅第 11 周标记及其他周次说明，把一次 AI 调课建议真正需要核对的范围直接做成了界面；04、15、16、69、76 也用草稿、核对、预览和最终确认延续了这种清楚的责任边界。

**最关键的不足：**52 的错误页同时呈现可编辑输入框的样式与“返回编辑，修改字段”按钮，让用户不能仅凭画面确定究竟应在这里修正，还是必须返回上一页修正。

整体任务表达成熟：今天、课表、学习、校园的分工清楚，学习计划与正式课程分开展示；红色承担主操作和关键强调，青绿色与文字共同说明成功，米黄色与文字共同说明待核对。页面没有依靠装饰代替业务内容，校园门形图标和少量红色大块建立了辨识度，也明确声明这不是学校官方应用。

## 3. 改进建议（按用户影响排序）

### 1）P2：让校验错误在一个明确位置修正

- **页面／位置：**52“课程字段需要修正”，390px 单图及 `review/narrow/52-field-error.png`。
- **观察事实：**页面显示课程名称、上课周次、地点等输入框样式，名称和周次带错误边框与行内说明；底部又提供“返回编辑，修改字段”，上方保存按钮处于灰色状态。
- **用户或视觉影响：**错误原因已经讲清楚，但修正动作的发生位置不清楚。用户可能先点输入框，也可能先返回；这削弱了错误恢复原本应该最直接的一步。
- **具体修改：**采用原位修正：保留这些输入框，输入有效后将主按钮改为可用的“保存课程”；把“返回编辑，修改字段”改为明确的取消动作。不要同时用一组输入框和一个“去别处编辑”的按钮表达同一件事。
- **如何复查：**提供未修正、修正一项、全部有效三个 320px／390px 状态，确认每个状态只有一个明确的修正位置，已填写的地点仍可见，保存状态随错误数量变化。

### 2）P2：把手动不可用时段做成可确认的选择

- **页面／位置：**49“基础规则设置”的“其他不可用时段”，390px 单图及 320px 单图。
- **观察事实：**该页明确“不请求 AI”，星期通过选项选择，但“其他不可用时段”仍是一个普通文本输入框，示例填“周六、周日上午”；画面没有给出允许的输入格式或明确的时段选择。
- **用户或视觉影响：**用户不知道这里是否接受自由表述，也不容易确认这句话究竟排除了两个上午，还是整个周六加周日上午。手动兜底路径应比自然语言路径更确定。
- **具体修改：**将这一项改为“添加不可用时段”，用星期加上午／下午／晚间或节次选择生成标签；当前例子明确显示“周六上午”“周日上午”两个标签。不要求用户补出尚未填写的钟点。
- **如何复查：**在 320px 下分别展示添加、修改和移除一个时段后的画面；确认周四全天与周末两个上午能分别识别，确认前能完整看见所有排除条件。

### 3）P2：让今天页首屏给出全天的简短概览

- **页面／位置：**01“今天”的问候、下一节课卡与快捷入口；对照 `review/narrow/01-today.png` 和 `review/scroll/01-320-bottom.png`。
- **观察事实：**320px 首屏中，大问候、下一节课卡和四个快捷入口占据主要高度，“今天的安排”的第一行也只露出一部分；14:00 和 16:00 的课程以及本机计划要继续向下看。390px 初始画面也呈现类似取舍。
- **用户或视觉影响：**下一节课非常醒目，但一个每天反复打开的工具，不能在第一次扫视时交代当天还有几项安排。当前构图更偏重单条课程展示，全天感较弱。
- **具体修改：**保留红色课程卡的主次关系，压缩卡片及问候区的纵向留白，并在首屏加入紧凑的“今日 3 项课程 · 10:10／14:00／16:00”概览；具体数字仅沿用这份虚构样例。完整课程列表继续保留在下方。
- **如何复查：**以 320×844 和 390×844 初始视口截图检查，无需滚动即可读出下一门课与当天其余课程的数量、时段；不能以缩小正文或遮住地点换取空间。

### 4）P3：提高反复核对动作的视觉可发现性

- **页面／位置：**15 每条约束右侧“修改”，04 展开清单、69／76 每条课程右侧“修正”，尤其是 320px 画面。
- **观察事实：**主要确认按钮有明确的色块和边界，而这些修正动作多为较小的红色文字，和页面其他红色提示、来源链接采用相近的表达。
- **用户或视觉影响：**这些是核对流程中的高频动作，当前视觉分量偏轻；红字既可能是状态、来源，也可能是可修改动作，用户需要额外辨认。截图不能证明实际点击区域大小，本项只指出可见的操作识别风险。
- **具体修改：**统一为带铅笔图标的“修改”轻按钮，保留足够的独立横向空间和清楚的按压区域轮廓；课程信息与按钮保持行对齐。不要把整行正文都染红。
- **如何复查：**对比 320px 的短课名、长课名和已修改状态，确认动作不挤压课程时间地点，且不靠颜色也能看出哪里可以修改；真实触摸区域需在实现后另测。

### 5）P3：给长练习记录增加轮次定位

- **页面／位置：**77“本次练习记录”，尤其 `77-320-record-middle.png` 与 `77-320-confirmation-bottom.png`。
- **观察事实：**记录完整区分问题、原答、材料反馈、复盘和重答，底部复制也一直可见；但内容是长列连续卡片，中部没有快速跳到某一轮或重答的定位方式，第 3 轮原答与重答分隔在不同位置。
- **用户或视觉影响：**带走记录很容易，回看和比较“这次到底改好了什么”仍需要在长页反复寻找。320px 下这一负担比 390px 更明显。
- **具体修改：**在记录开头提供“第 1 轮／第 2 轮／第 3 轮／重答”紧凑定位条，并让重答区提供清楚的“对照第 3 轮原答”入口；保留全部已有正文和固定复制操作。
- **如何复查：**提供轮次定位后的静态落点与重答对照画面，确认标题不被顶部导航遮挡、正文末尾不被复制区永久遮住；定位点击与复制内容完整性仍需实现后验证。

## 4. 总体评分与证据边界

**总体评分：8.5 / 10。**

这是已经成熟、任务边界表达清楚的静态提案：改课范围、核对与最终保存、本机计划、资料不足、体测缺项、三轮练习与一次重答都能在画面中找到清楚的对应表达。它距离更出色的日常工具，主要差在少数恢复路径与手动输入方式的确定性，以及高频页面的信息密度和长记录定位，当前截图范围内未见需要推翻整体方向的构图或任务表达问题。

**置信度：较高，限静态视觉与可见任务表达。**已先看 `review/overview.png` 和 `contact-01.png` 至 `contact-10.png` 覆盖全部 79 画面，再放大 33 张主单图、37 张 320px 单图，并查看本次清单中的 43 张滚动／横移状态图。所有要求重点放大的 02、04、06、09、15–17、26、30、31、39、51、63、68–79 均已查看。
