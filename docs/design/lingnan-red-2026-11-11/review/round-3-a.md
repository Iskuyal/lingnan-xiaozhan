3. 改进建议

- **优先级：P2；页面/位置：69「导入核对已完成」、76「核对 Excel 课程」的固定保存区。** 观察事实：截图用绿色“已核对”反馈和显著红色按钮推进保存，而“将替换整份课表，包含手工修改”只有按钮上方一行小号灰字；列表主要展示新导入内容。用户或视觉影响：用户容易把当前任务理解为保存已核对的9条，低估现有手改内容也会被覆盖的范围。具体修改：将替换后果做成独立、可读的提示块，明确写“本次会替换当前整份课表，已有手动修改也会被替换”；保留按钮中的“替换”，提示不要与页脚的静态稿说明采用近似弱层级；有现存变动摘要时紧邻提示展示。如何复查：在390px和320px的首屏、列表末尾及固定区截图中，检查替换后果是否能在确认前直接读到，并让未看简报的人复述保存影响。

- **优先级：P2；页面/位置：71「我的课表」的保存后网格及 `review/scroll/71-320-changed-friday.png`。** 观察事实：保存后的首屏网格仍显示周一至周三一带，摘要要求用户左右滑动查看周五；周五的新 Java 安排使用浅红底深红字，与普通状态下周一、周三的 Java 课程相同，没有独立的变更标记。用户或视觉影响：读完“已保存”仍需要寻找新位置，且“新安排已标红”不能仅凭网格颜色区别出本次变更。具体修改：保存后的设计状态直接呈现周五列，或呈现已选中周五的每日安排；在改动格上添加“本次调整”短标记或清楚边框，课程配色继续保留原有含义。如何复查：并排看保存前、保存后初始状态和周五截图，不依赖上方说明也能指出哪一格是本次改动，并能看到该格所属日期与节次。

- **优先级：P2；页面/位置：63「已填项目的估算」中“缺少的项目”卡片与补填按钮。** 观察事实：页面前半已经指出1000米跑未填写，但“返回补充1000米跑成绩”的红色主操作放在整张单项成绩表之后；320px完整图中，该按钮位于约1000px以下。用户或视觉影响：用户知道缺什么，却要先滚过已经填写的单项结果才能执行主要恢复动作，页面结构更偏向展示结果而非解决缺项。具体修改：把补填按钮放到“缺少的项目”卡片下方或卡片内，既有单项结果继续放在后面供回看；底部可以保留一个重复入口。如何复查：在320px、844px高的初始视口中，缺项名称与补填动作应同时可见；完整图仍应保留所有已填结果，且不出现不完整总分。

- **优先级：P3；页面/位置：附录47「认领与核验」、50「核验认领申请」的320px图。** 观察事实：390px单图的导航下方有“暂缓模块设计附录·不新增正式入口”灰条，而对应320px截图没有该标识；44的320px图仍有同类灰条。用户或视觉影响：分发单张窄屏稿时，附录状态不如其他尺寸和同组页面清楚，容易被当成当前正式范围。具体修改：统一附录标识在全部尺寸及同组页面的位置和文案，允许换行，不通过窄屏隐藏来节省高度。如何复查：将44–48、50的390px和320px单图成组核对，每张都能独立辨认其暂缓附录身份，不依赖文件名或外部说明。
