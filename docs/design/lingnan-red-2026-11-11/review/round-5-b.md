# 独立产品视觉评审原始报告

评审版本：**LN-194315d53ea8b822**。评审日期：2026-11-13。

评审对象是学生日常使用的原生微信小程序“岭南小栈”的静态设计提案，主色固定为岭南红。本报告依据固定评审提示、最小产品简报及当前版本图片独立形成；未读取实现代码、项目 README、历史评审或其他评审意见。

已查看 `review/overview.png` 与 `contact-01.png` 至 `contact-10.png`，覆盖全部 79 个画面；逐张放大 390px 完整单图 02、04、06、09、15–17、26、30、31、39、50、51、63、68–79，并查看这些页面及入口、错误、练习、附录等共 48 张 320px 单图。另逐张查看 `review/scroll/` 的全部 43 张证据，覆盖主入口底部、确认页末尾、展开课程清单、材料另一选择、日期右侧、变更初始位置、课表左中右、练习记录中部与底部。其余画面在联系表中检查任务衔接、结构与视觉一致性，未声称全部逐像素放大。

课程、成绩、资讯、通知、练习、原文件与裁片按简报作为虚构示例判断；学校、部门及政策的保存日期只作为界面呈现的信息，不代表本轮重新核查。44–48、50 按暂缓模块附录评阅，不视作正式入口。学习/校园聚合页、底部导航及练习复制流程均按交互提案评阅。

## 1. 总体判断

**最强的设计决定：** 把“草稿先核对、本人确认才写入”的过程做成了可见的主线，04 的待核对地点、09 的原新安排与生效周、15 的原话对照、69/76 的整表替换提醒，以及 77/78 的主动复制边界，都让用户知道自己即将确认什么。

**最关键的不足：** 同为“我的课表”，02 保留切周与周/日视图入口，71 的改课结果课表却用较大的成功说明取代了这组操作，任务完成后继续查课的入口和布局失去连续性。

## 3. 改进建议

### 1）P2 — 保留改课完成后的课表操作

- **页面/位置：** 02、71 的课表顶部，尤其是 `png/71-week-eleven.png`、`review/narrow/71-week-eleven.png` 与 `review/scroll/71-390-changed-initial.png`。
- **观察事实：** 02 有左右切周、周课表/每日安排切换和“管理”；71 的已提供画面只保留周次、保存状态与较大的变更说明卡，没有看到相同的切周或周/日视图入口。71 已直接显示变更所在的周五，并以边框和“本次调整”标出课程，这一点有效。
- **用户或视觉影响：** 用户看完修改结果后，下一步通常是查相邻周、核对原日期或继续查看当天课程；同名主页面突然换掉熟悉的操作，增加了重新找入口的负担。这里判断的是截图中的操作连续性，不能据此断言实际路由无法返回。
- **具体修改：** 71 复用 02 的切周与视图切换区，把成功说明压缩为两行以内的可关闭状态条；保留“仅第 11 周”的范围、周五定位与课程强调，避免让结果说明占据整块常用导航的位置。
- **如何复查：** 同时摆放 02/71 的 390px 与 320px 图，确认切周、周/日切换仍处于相同位置，变更课程和“仅第 11 周”仍能立即识别；实际切换与返回能力需另用可操作原型或运行证据验证。

### 2）P2 — 让整表替换前的课程清单获得更多首屏空间

- **页面/位置：** 69、76 的首屏与固定底部区；参照对应的 `*-320-confirmation-bottom.png` 和 `*-390-confirmation-bottom.png`。
- **观察事实：** 76 首屏依次放置步骤、大标题、文件统计、原单元格裁片和说明，课程清单到较低位置才开始；固定区包含替换警示、主按钮、返回动作，约占 190px 高度。320px 首屏主要看见清单的第一条，69 也只能先看到部分条目；末尾截图则证明最后一条确实能够滚动显示，未观察到被固定按钮永久挡住。
- **用户或视觉影响：** “确认替换整份课表”始终非常显著，但用户真正需要逐项确认的九条安排获得的可视空间较少。核对流程因此更接近阅读长说明，容易把主要注意力引向完成动作。
- **具体修改：** 保留醒目的整表替换后果与主按钮，把文件统计收成紧凑摘要；将原单元格裁片与对应课程放在一起，或默认折叠为“查看原单元格”，让课程清单提前出现。减少固定区内的垂直空隙，同时保留至少 48px 的主按钮高度和清楚的返回动作，不靠缩小正文或隐藏替换后果来省空间。
- **如何复查：** 在 320px 首屏中争取同时看到至少三条课程；末尾仍能完整看到最后一条及其“修正”动作。由不了解方案的人只看此页指出“要替换什么、会失去什么、在哪里改某一条”，三件事应能直接说清。

### 3）P2 — 给窄屏周课表增加清楚的日期定位

- **页面/位置：** 02、51 的日期表头与横向课表，67 的日期条；参照 `review/scroll/week-320-left.png`、`week-320-middle.png`、`week-320-right.png`。
- **观察事实：** 320px 下周课表一次完整显示约三天，日期与课程在左右边缘出现部分裁切；51 的长课程名需要截断后进入详情查看。节次轴在左右位置都仍可见，页面也明确提示横向滑动，因此不能把横向浏览本身当成缺失。02 的当周日期表头没有像 67 那样突出当天，用户需要自己从日期中定位。
- **用户或视觉影响：** 日常快速查看“今天、明天、周末有没有课”时，用户需要在多个横向位置记住日期与课程分布；长课名又增加了一次进入详情的成本。
- **具体修改：** 在保持课程可读列宽的前提下，借用 67 的完整日期定位方式，为周课表提供紧凑的七天定位条，标出“今天”与当前显示范围；选择日期后定位对应列。保留节次轴、边缘预露与查看完整课程详情，不强行把七列课程压进 320px。
- **如何复查：** 用同一份七天均有课的样例，分别给出左、中、右位置的 320px 图，检查用户能否在不记忆前一张图的情况下指出当前日期范围与今天的位置；横向定位是否准确、是否可中断，静态证据无法判断。

### 4）P2 — 在附录的窄屏图中保留范围标识

- **页面/位置：** 48、50 的 320px 图；对照 `contact-06.png` 中的 48、`png/50-claim-review.png` 与 `review/narrow/48-mine.png`、`review/narrow/50-claim-review.png`。
- **观察事实：** 390px 画面在导航栏下有“暂缓模块设计附录 · 不新增正式入口”横幅；48、50 的 320px 图中没有这条横幅，正文直接从页面引导或“发布者视角”开始。44–47 的已查看窄屏图仍有横幅，因此这不是所有附录统一采用的窄屏表达。
- **用户或视觉影响：** 单独展示这两张窄屏图时，读者只能看到普通业务页面和操作按钮，无法从图内识别其暂缓和附录身份；评审、沟通或截取复用时容易混淆正式范围。简报已经说明其身份，本报告不会据此认为正式入口已增加。
- **具体修改：** 将相同的范围横幅保留到 48、50 的 320px 版本；允许自然换行，不将其隐藏或缩成难读的小字。若是导出版本不一致，重新生成并替换当前窄屏证据即可，不应先猜测需要改实现。
- **如何复查：** 单独查看 44–48、50 的 320px 与 390px 图，每张都能直接读出暂缓附录身份；核对导出版本后再作跨宽度比较。

### 5）P3 — 统一选择控件，并区分只读上下文

- **页面/位置：** 06 的学期与作息选择、49 的规则选择、79 的上课安排选择，以及 68 的“其他课程信息”。
- **观察事实：** 选择指示以很小的向下符号紧贴当前值，短时间值和长日期值后的指示位置不同；68 的可编辑地点与下方课程上下文都使用相同的白底描边输入框外观，而后一项没有明确的可编辑提示。79 则通过“可修改”标签说明了可改字段。
- **用户或视觉影响：** 用户需要额外靠文字猜测哪些值可以点开、哪些只是供核对；重复填写作息时，选择入口的辨识也不够利落。
- **具体修改：** 所有选择控件的下拉图标统一靠右、垂直居中，与文字保持固定间隔；68 的课程上下文改成普通信息行或明确标为只读，保留地点的输入外观。沿用 79 对可修改内容的清楚标示。
- **如何复查：** 在 320px 与 390px 下分别检查短时间、长日期和多段安排，确认图标位置一致、不贴字；只看截图时应能区分可输入、可选择和只读三类内容。真实焦点、键盘类型和触控命中范围需运行验证。

## 4. 总体评分与证据边界

**总体评分：8.3 / 10。** 当前作品已经形成一套成熟、清楚且有辨识度的学生工具界面，关键状态覆盖完整，特别是草稿核对、单周改课、缺项估算、主动复制与资料不足时的处理有扎实的视觉表达。它与更出色体验的差距主要在日常任务的连续性和核对信息的效率：课表完成态应继续保留常用操作，重要清单应比重复的引导文案和大块固定操作区获得更多注意力。

**置信度：静态视觉判断较高，实际交互判断有限。** 已提供的入口、任务、结果、错误、附录、窄屏和关键滚动位置足以支持本轮静态总体评分；未发现必须依赖动效才能解释的核心任务，因此不因没有动态证据扣分。

**无法判断：** 路由与返回是否真实可用、点击是否正确定位或修改、焦点和读屏顺序、系统字号放大、软键盘遮挡、网络反馈与撤销时序、真实模型输出、计算或保存结果，以及微信端运行表现。所有图片只证明设计提案的可见表达，不能作为这些能力或真实业务已经通过的证据；未提供独立参考作品，本报告也不作与某个参考作品的还原度判断。
