## 为什么这样画

G1 首评给出了三条硬约束，这一版设计是围着它们画的，不是凭空排版：

| G1 实测 | 对设计的要求 |
| --- | --- |
| 单次调用 **12–23 秒**（`completionTokens` 常在 1,700–4,100，思考占大头） | 必须画**等待态与取消出口**（06），并在材料页就预告耗时；不能用「转圈等」打发 |
| 单次可靠性约 **88%**（17 次真实调用里 2 次返回空内容） | 失败态必须**保留已写内容**、允许重试，且**不得**把失败写成「你没讲清楚」（07） |
| 四节结构 + 引用编号 100% 可回核、越界断言 0 | 反馈页的**每条断言都要挂引用徽标**，未保留的待验证项要单独指出（03） |

另外两条是产品约束，不是排版偏好：

- **不输出职业能力等级、官方成绩、录用或面试保证**，也不评价表达能力与学习效果——所以页面上没有任何分数、等级、通过率、雷达图。
- **材料里的「待验证」不会因为练过一次就变成「已完成」**——所以复盘页只列「你说了什么 / 材料写了什么」，不生成结论性评价。

## 状态机（由程序控制，模型只填内容）

```text
materials ── 选材料 ──▶ round(1) ──提交──▶ pending ──成功──▶ feedback(1) ──追问──▶ round(2)
                            ▲                  │                                        │
                            └──── 取消/失败 ────┘                                        ▼
                                                                    …round(3) ──▶ review ──▶ reanswer ──▶ feedback(reanswer) ──▶ done
```

| 状态 | 进入条件 | 允许的动作 | 退出 |
| --- | --- | --- | --- |
| `materials` | 进入页面 | 选材料、看边界 | 选材料 → `round(1)` |
| `round(n)`（n=1..3） | 上一轮反馈完成 / 首次 | 编辑回答（20–500 字）、提交 | 提交 → `pending` |
| `pending` | 已提交 | 取消 | 成功 → `feedback(n)`；失败 → `failure(kind)`；取消 → 回 `round(n)` 保留草稿 |
| `feedback(n)`（n=1..2） | 拿到完整四节 | 读反馈、复制、进入下一轮 | 进下一轮 → `round(n+1)` |
| `feedback(3)` | 拿到完整四节 | 读反馈 | → `review` |
| `review` | 三轮全部有反馈 | 复制复盘、选一处重答 | 重答 → `round(reanswer)`（**仅一次**）；否则 → `done` |
| `reanswer` 后 | 重答反馈完成 | 读对照 | → `done` |
| `failure(kind)` | 任一类失败 | 重试、复制已写内容、回材料页 | 重试 → `pending`（同轮，不进入下一轮） |
| `done` | 会话结束 | 复制复盘、回首页 | —— |

**不变量**：轮次、重答次数、状态转移全部由程序控制；模型不能在正文里推进轮次或要求「再聊下去」；失败不改变轮次计数，也不产生学习结论。

## 业务契约（G3 实现依据）

### 1. 请求契约

| 项 | 取值 | 说明 |
| --- | --- | --- |
| `action` / `feature` | `chat` / `project-defense` | 走既有 `ai` 云函数，不新开通路 |
| `system` | **服务端固定** | 纪律提示不得由客户端传入或覆盖；材料只作为被引用的文本 |
| `messages` | 材料（按条目编号分段）+ 当前维度问题 + 本轮回答 + 固定指令 | 形状与 G1 PoC 一致 |
| 材料正文 | ≤ 2,000 字 | 超出**拒绝**，不静默截断 |
| 单轮回答 | 20–500 字 | 少于 20 字提示补充；超 500 字拒绝并保留草稿 |
| 输入总量 | ≤ 12,000 字符 | 服务端硬限；客户端按更小预算自剪历史 |
| 输出 | ≤ 6,000 字符 | 超限丢弃整条回答而不是显示未检测内容 |

### 2. 输出与引用契约

1. 输出必须是四节：`【引用核对】【是否对应回答】【待验证保留】【追问】`，标题原样。
2. **缺任一节 = 本次不上屏**：按「反馈不完整」处理，保留输入、允许重试，不得把半截内容当反馈展示。
3. 引用只允许指向**当前材料**里的条目编号（`F*`/`D*`/`INV-*`）；编号不存在、跨材料错引、或与材料原文说反，都判引用不成立。
4. 材料性质校验：`FC-2` 是设计情景，把它说成「小程序已有功能 / 已上线」即引用不成立。
5. 材料标明「待验证 / 未测试」的事项，反馈不得写成已完成、已验证、已上线；「部分已确认、部分待验证」的事项必须**分开说明**。
6. 材料与学生说法不一致时，反馈必须**提示核对**（写出材料原文），不得判定学生撒谎、不得作道德评价。
7. **越界断言（把待验证说成已完成）一旦出现，本轮直接不通过**，不因其他部分得分高而抵消。

### 3. 调用与预算

- 完整流程 = 材料后**最多 4 次**模型调用（首题 1 + 两次中间各 1 + 第三轮反馈与复盘 1），**一次重答 +1**，合计 **5 次**；不做无限对话、不自动重试风暴（重试同样计费）。
- 每次请求可能被内容安全拆成多片：按 G1 实测（19 次请求 ≈ 60 次检测）估算，**一次完整会话约 15–20 次检测**；未上架期上限 100 次/天 ⇒ **约 5–6 次完整会话/天**，与升学问答、10-08 演示共用。
- 月度 50 元上限共用，不单独扩额。

### 4. 失败分类与文案

四类必须各自独立，不得合并成一句（文案见 [07-failure](png/07-failure.png)）：

| `failureClass` | 触发 | 页面处置 |
| --- | --- | --- |
| `model_unavailable` | 连接失败、超时、5xx、返回空内容 | 保留输入 + 重试；**不算**学生没讲清楚 |
| `content_rejected` | 输入或输出被判违规 | 指出需要修改再试；不评价回答内容 |
| `quota_exhausted` | 月度上限、402、微信内容安全 `45009` | 说明额度或当日配额用尽；排障**先查 45009** |
| `invalid_request` | 参数不合法、输入超窗 | 指出长度超限；服务端在检测与模型之前拒绝，不消耗配额 |

> **注意**：现有 `AI_MSG_*` 文案是**全局**的（`model_unavailable` 默认文案提到「课表与部门资料」）。本页需要独立文案，而按 feature 覆盖文案目前不支持 ⇒ 见待拍板项 5。

### 5. 时延与降级

- 等待态从提交起立即出现，写明「在等什么」与实测区间（12–23 秒），并提供**取消**；取消必须保留草稿。
- 超过 30 秒未返回，按 `model_unavailable` 结束本次并保留输入。
- 取消 / 失败 / 退出后**不得显示上一轮的旧反馈**；回到该轮时页面只显示草稿与该轮问题。

### 6. 数据与隐私

- 会话只保存在**页面内存**，退出即清空；首段不新增业务数据库、不写云端会话。
- 云端只保留既有脱敏用量元数据（`requestId`/`feature`/token/费用），**不记录材料或回答正文**。
- 页面不展示、不推断真实教师姓名、班级人数与个人课表。

### 7. 明确不做（首段）

语音、TTS、图片/PDF/PPT 解析、代码执行、专业知识正确性评审、教师端、班级成绩、排行榜、分享增长、云端历史库；不因复用而改动课表与资讯。

## 与 G1 PoC 的差异（G3 要按这里改，不要照抄 PoC）

1. **三轮的语义**：G1 的 `R1–R3` 是对**同一个问题**的三段不同回答；本设计要求三轮对应**三个维度各一个问题**（问题与目标 / 方案及取舍 / 验证与限制），并由程序控制。
2. **重答必须新写**：G1 的 `R5` 用的是同一份冻结文本（脚本已注明「不是真实学生重答」）；本设计要求学生新写，否则不算重答。
3. **失败文案**：G1 直接复用了全局默认文案（提到课表/部门资料），本页需要独立文案。
4. **材料来源**：G1 用的是 G0 冻结的两份事实卡；是否允许学生粘贴自己的材料见待拍板项 2。
