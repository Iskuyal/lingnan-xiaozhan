# AI 资讯可行性实测（小样）

实测日期：2026-09-18 ｜ 状态：已完成，**结论为否定**（不建议将「AI 资讯」纳入首版）
对应分支：`docs/ai-news-poc` ｜ 脚本与原始数据：`docs/reference/ai-news-poc/`

---

## 一、为什么做这个实测

`docs/tasks/scenario-comparison.md` 第二节对「候选 A：校园信息整合」的 AI 落点有如下判断：

> 一个只能展示官网文章的资讯页，**AI 贡献接近于零**；把摘要贴上去也**不构成「真实发挥作用」**。
>
> AI 落点：摘要、分类、检索问答（RAG）。**但用户现有流程里 AI 不是必需**：不装 AI 也能看文章。

这是**判断**。本轮把它变成**实测数据**，以便该结论不再依赖推测。

---

## 二、样本与方法

| 项 | 内容 |
|---|---|
| 数据来源 | 学校官网「校园动态」`https://lnc.edu.cn/xyxw/xydt` 第 1 页，**8 篇真实文章** |
| 语料规模 | 10,584 字，平均 1,323 字/篇 |
| 解析逻辑 | **复用项目自身编译产物** `dist/cloudfunctions/newsSync/parse.js`，与本项目生产解析同源 |
| 模型 | `deepseek-flash`（DeepSeek-V4.1-Flash）官方 API |
| 测试项 | 摘要、结构化抽取、分类打标、学生行动项抽取、定点问答（共 5 项 × 8 篇） |
| 附加 | 跨全库问答 3 题，其中 **1 题为防幻觉陷阱题**（问题答案不在资料内） |
| 调用总量 | 43 次 |

**为什么设「防幻觉」为否决条件**：项目对 AI 功能的硬性验收标准是"资料里没有的信息明确答'官网未公布'，绝不编造"。一个会编造的 AI 加入产品是负分而非加分，因此该项若失败即整体否决。

## 三、结果

### 3.1 总体数字

| 指标 | 数值 |
|---|---|
| 总耗时 | 7.0 秒（平均 **164 ms/次**） |
| 输入 token | 52,770 |
| 输出 token | 20,288 |
| 合计 token | 73,058 |
| 本次实际花费 | **约 0.13 元**（DeepSeek 空闲时段） |
| 换算：全站 1252 篇跑全部 5 项 | 约 17.7 元 |
| 换算：全站 1252 篇仅跑结构化抽取 | 约 8.4 元 |

价格依据：DeepSeek 官方定价，`deepseek-flash` 空闲时段 输入 1 元/百万 tok、输出 4 元/百万 tok（高峰时段翻倍）。

### 3.2 通过的

| # | 项目 | 数据 |
|---|---|---|
| 1 | **防幻觉（否决条件）** | **8/8 无编造**：6 篇正确拒答、2 篇有据回答、0 篇编造。跨全库 3 题全对，含陷阱题 |
| 2 | 结构化输出可解析率 | `extract` / `classify` / `actions` 共 **24/24 全部返回合法 JSON**，无需重试或修补 |
| 3 | 响应速度 | 平均 164 ms/次，43 次调用 7 秒完成，满足实时交互 |

陷阱题原文（资料中确无此信息）：

> 问：学校图书馆的开放时间是几点？
> 答：资料未提及学校图书馆的开放时间。第【2】篇仅出现"教学科研处（图书馆）"这一部门名称，未涉及开放时间。

模型不仅拒答，还说明了检索范围。

### 3.3 未通过的

| # | 项目 | 数据 |
|---|---|---|
| 1 | **学生行动项抽取** | **8 篇全部判定为"无行动项"** |
| 2 | 自动分类准确率 | 约 **75%**（8 篇中 2 篇明显错误） |
| 3 | 输出 token 控制 | `extract` 一项占全部 token 的 **35.8%**，输出量为输入量的 **1.6 倍**（单篇最高输出 4,455 tok，而目标仅为 4 字段 JSON） |
| 4 | 字段留空遵从度 | 提示词要求"资料里没有的字段必须留空"，但 8 篇 × 3 字段 = **24 次机会全部填值**，模糊处给出"学校""暑假期间"等含糊填充 |

分类错误实例：

| 文章 | 模型标签 | 问题 |
|---|---|---|
| 长护服务产业园揭牌仪式 | 校企合作、教学科研、**志愿服务** | "志愿服务"无依据 |
| 2026 级新生入学教育 | 校园活动、教学科研、**校企合作** | 与校企合作无关 |

输出 token 失控的原因：`deepseek-flash` **默认开启思考模式**。对结构化抽取类任务，思考属于额外开销，**预计关闭后可显著降低**（未验证）。

## 四、结论

**不建议将「AI 资讯」纳入首版。** 依据：

1. **`actions` 0/8**——"AI 从资讯中提取对学生有用的信息"这一卖点，在当前数据源上无成立基础
2. 分类准确率 75%，达不到自动入库标准
3. 剩余的"摘要"能力即 `scenario-comparison.md` 已判定"贡献接近于零"的那一项，本轮**未能推翻该判断**

## 五、本轮的正面副产品

尽管主结论为否定，本次实测为**两项既有决策**提供了可用证据。

### 5.1 对 P3-2「首批栏目」决策（`CONTEXT.md` 待决定表）

实测证明：**「校园动态」栏目是事后报道性质，不含行动项类内容**（8/8 无）。

因此，若产品需要"与学生有关的时间节点"（报名截止、放假安排、考试周等），**必须将通知公告类栏目纳入首批范围**——教务处、学生工作部、团委等站点，而非现有的五个学院新闻栏目。

这是该决策的**第一条实证依据**，此前只有推测。

### 5.2 对 P5「部门问答」落点（`CONTEXT.md` 已确认的 AI 三落点之一）

"部门问答"的核心验收要求是**答案不编造、资料缺失时如实说明**。本轮实测提供了该类模型的正面证据：

- 防幻觉 8/8，含陷阱题
- 结构化输出 24/24 可解析
- 164 ms 响应，7 秒完成 43 次调用
- 成本量级：全量语料处理约 18 元

即：**为验证「资讯」而做的实测，其最有价值的产出是对「部门问答」的可行性证据。**

## 七、复现方式

脚本位于 `docs/reference/ai-news-poc/`，说明见该目录 `README.md`。

```powershell
cd docs/reference/ai-news-poc
node fetch-news.cjs      # 抓取官网真实资讯（官网限速约 1 请求/秒，脚本内置 1.3 秒间隔）
node smoke-test.cjs      # 冒烟测试：确认 Key / baseUrl / 模型名正确
node poc-ai-news.cjs     # 执行 5 项能力测试
node analyze.cjs         # 汇总统计
```

需要 `docs/reference/ai-news-poc/key.txt` 提供模型 API Key。该文件已被该目录下的 `.gitignore` 忽略，**不会进入版本库**。
