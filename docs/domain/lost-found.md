# 失物招领 · 领域文档

状态：**待评审**。本文件是 `docs/tasks/lost-found-framework.md`（提案）在 LF-1 阶段的落盘产物：
领域词汇、状态机、权限矩阵、威胁清单与校验基线。决策关卡 D1–D3 仍属负责人待拍板项，
实施按框架建议的 **C（独立验证原型）** 推进：只用许可样本、不接真实用户、不上线。

## 1. 领域词汇

| 术语 | 含义 |
| --- | --- |
| 帖子 | 一条丢失（`lost`）或拾获（`found`）信息，含公开特征与私密核验特征 |
| 公开特征 | 类别、标题、公开描述、公开图片、模糊时间范围、模糊地点，任何人可看 |
| 私密核验特征 | 颜色细节、划痕、编号局部、内部物品等用于证明所有权的特征，仅发布者与授权云函数可见，不出现在候选解释里 |
| 模糊化 | 时间只到天/时段、地点只到区域（楼宇/片区），不公开精确时间与精确地点 |
| 候选线索 | 相反类型帖子中与当前帖可能指向同一物品的条目，附相符点、冲突点与不确定性 |
| 相符点 / 冲突点 / 不确定性 | 结构化解释三要素：可核验的相似依据、已发现的矛盾、缺失或无法判断的信息 |
| 认领申请 | 认领人针对一条帖子提交的结构化核验回答与证据，不即时对话 |
| 交接 | 发布者与认领人双方确认的线下归还动作，平台只记录确认，不担保 |
| 结案 | 帖子进入 `resolved`/`closed` 后的终止状态，不再参与匹配 |

## 2. 状态机

### 2.1 帖子（`lost_found_posts.status`）

```
draft ──发布──▶ open ──匹配──▶ matching
draft ──放弃──▶ closed
open ──认领申请──▶ verifying
open/matching/verifying ──发布者关闭──▶ closed
open/matching/verifying ──审核暂停──▶ suspended
suspended ──恢复──▶ open / 关闭──▶ closed
matching ──完成──▶ open
verifying ──全部申请结清──▶ open
verifying ──双方确认交接──▶ resolved ──▶ closed
```

- 状态变更只在服务端校验；前端不得直写状态字段。
- `matching` 表示候选计算中（首版 LF-3 无 AI，规则召回同步完成，该状态仅保留为 LF-4 预留）。
- `suspended` 只由审核动作进入（LF-3 内：举报不自动暂停，留人工；本阶段保留状态枚举与迁移合法性，不开放自动暂停入口）。

### 2.2 认领申请（`lost_found_claims.status`）

```
pending ──需补充──▶ needs_more_info ──补充──▶ pending
pending ──发布者通过──▶ accepted
pending ──发布者拒绝/申请人取消/发布者取消──▶ rejected / cancelled
needs_more_info ──拒绝/取消──▶ rejected / cancelled
accepted ──双方确认──▶ completed
accepted ──取消──▶ cancelled
accepted ──争议──▶ disputed ──▶ completed / cancelled
```

- 终态：`rejected` / `cancelled` / `completed`。
- 同一帖子的多条申请独立流转；帖子只有存在 `accepted` 申请时才可进入交接确认。

## 3. 权限矩阵

openid 一律取自云函数可信上下文（`cloud.getWXContext()`），不信任前端提交的任何身份字段。

| 操作 | 发布者（帖主） | 认领人 | 其他用户 | 系统（云函数内部） |
| --- | --- | --- | --- | --- |
| 创建帖子 | ✅ | ✅ | ✅ | — |
| 编辑/关闭本人帖子 | ✅ | ❌ | ❌ | — |
| 查看公开列表/详情 | ✅ | ✅ | ✅ | — |
| 查看本人完整数据（含私密特征） | ✅ | ❌ | ❌ | ✅（受控） |
| 查看候选（本人帖子） | ✅ | ❌ | ❌ | — |
| 提交认领申请 | ❌（不得认领自己的帖子） | ✅ | ✅ | — |
| 处理认领申请 | ✅（本人帖子） | ❌ | ❌ | — |
| 确认交接 | ✅（本人帖子+accepted 申请） | ✅（本人 accepted 申请） | ❌ | — |
| 举报 | ✅ | ✅ | ✅ | — |
| 请求删除本人数据 | ✅ | ✅ | ✅ | — |
| 审计事件写入 | — | — | — | ✅ |

## 4. 数据隔离

| 集合 | 可见性 | 内容 |
| --- | --- | --- |
| `lost_found_posts` | 公开只读（安全规则待部署时配置） | 帖子公开字段与业务状态，**不含**私密核验特征、精确时间/地点 |
| `lost_found_post_private` | 仅发布者与授权云函数 | `verificationTraits`、精确时间/地点（确有必要时）、授权与删除计划 |
| `lost_found_matches` | 仅相关帖子双方 | 规则过滤版本、候选对、结构化解释、rank、失效时间、反馈 |
| `lost_found_claims` | 仅申请双方与审核 | 结构化核验回答、证据引用、状态、双方确认时间 |
| `lost_found_audit_events` | 仅审核 | 状态变更、敏感数据访问、举报、模型调用元数据；不存完整图片/提示词/密钥 |

小程序端只经云函数访问；私密集合不出现在任何客户端直查路径。

## 5. 威胁清单与防冒领基线

| # | 威胁 | 基线 |
| --- | --- | --- |
| T1 | 冒领：凭公开特征猜测私密特征 | 发布时引导保留至少一个未公开特征；核验回答只与私密特征做服务端受控比较；候选解释不回传私密内容 |
| T2 | 联系方式/定位泄露 | 公开描述过滤手机号、微信号、精确宿舍；默认模糊时间地点 |
| T3 | 越权（改他人帖、读私密表、处理他人申请） | 全部写操作服务端校验 openid；私密集合无客户端路径 |
| T4 | 重放/重复提交 | 幂等键 + 乐观锁版本号；认领防重复（同帖同人仅一条活跃申请） |
| T5 | 提示词注入 / 脚本内容 | 输入白名单与长度上限；描述纯文本渲染；模型输出过 JSON Schema + 候选 ID 白名单 |
| T6 | 高频刷取 | 发布、认领、候选计算设频率限制（云函数内计数） |
| T7 | 删除后残留 | 软删除标记 + 删除计划；候选缓存带失效时间；审计不存大对象 |
| T8 | AI 越权裁定 | AI 只排序与解释；归属由人工核验，文案禁用「已确认是你的物品」 |

## 6. 输入校验基线（LF-3 起执行，先测试后实现）

- 标题：1–30 字符；描述：1–500 字符；核验特征：1–200 字符；枚举（type/category/status）白名单。
- 时间范围：`timeRange` 不晚于今天、起止不倒置；地点只允许「区域」粒度。
- 图片：0–3 张，云存储 fileID 白名单（`lost-found/{ownerHash}/` 前缀），类型 png/jpeg。
- 私密核验特征不进入公开字段；公开描述中的联系方式记号在服务端检测并拒绝（复用联系方式记号规则思路）。
- 分页上限：列表每页 ≤20；候选每帖 ≤10。
