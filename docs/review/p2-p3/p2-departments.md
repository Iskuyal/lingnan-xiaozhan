## 数据来源与核实过程

**主要来源**：官网 [团委概况 → 学生组织](https://lnc.edu.cn/tw/sygk/xszz)。**该页正文只有一张表格图片**（`学生组织_01.jpg`，1984×1887），没有文本、没有日期、没有联系方式列、没有校区列。核查日期 2026-09-17。

转录结果（5 个组织）：

| 组织 | 下设部门（原文） | 页面 id |
| --- | --- | --- |
| 校学生团委 | 秘书处、组织部、宣传部、广播台 | `student-youth-league` |
| 校学生会 | 权益部、文娱部、器材部、体育部、学创部 | `student-union` |
| 校学生社团管理部 | 策划部、秘书部、宣传部 | `student-club-management` |
| 青年志愿者联合会 | 青枢部、青创部、青拓部、青宣部 +「红小荔」志愿服务队 | `young-volunteers` |
| 退役军人事务服务部 | 宣秘团、督勤部（原文即「团」） | `veteran-affairs-service` |

转录时按单元格逐行拆分、统计墨迹起止像素与字符步进核对字符数。**该图片已由项目负责人独立复核过一次，比对结果一致**（含原文不规范的「宣秘团」与「红小荔」）。

**组织动态**共收录 10 条，另有 1 篇未收录：文章必须写明该组织参与或负责才计入。未收录的是一份社团年审通知（正文为图片附件、未写明学生社团管理部）。

### 未采用的来源及原因（记录在来源文档）

- **团委架构页的「二级院团组织」图片**：有校区/办公地点列（10 行），但那是院级**团组织**、且含个人姓名，与学生组织不是同一类别，未录入。若产品想覆盖校区数据，这是一个候选来源，需要你决定。
- **学校行政部门**（学生工作部、教务处、保卫工作部等）：属党政机构，不是学生组织，未录入。
- **社团名单**：官网没有以名册形式公布，未臆造。

### 保留的一处官网矛盾

「我为同学做实事｜"医"心同行，"器材"护航」写作「校学生团委器材部」，而官方表格把器材部列在校学生会下。两种说法都来自官网，**保留矛盾、未擅自取一**，该文章未作为任何组织的动态收录。

## 数据结构

`Department` 含组织名称、所属校区、介绍、下设部门、联系方式、动态、来源；页面视图分两层构造：

- `listDepartments()` / `findDepartmentById(id)`：原始数据访问。
- `buildDepartmentList(source?)` / `buildDepartmentDetail(id)`：构造页面视图，把缺失字段替换为上面那张表里的文案常量（`MISSING_CAMPUS_TEXT`、`MISSING_CONTACT_TEXT`、`MISSING_ACTIVITY_TEXT`、`EMPTY_LIST_TITLE`、`NOT_FOUND_TITLE` 等），使「缺失」在页面上是明确文案而不是空白。

数据随包提供，**不依赖云环境**（这是 P1–P2 的既定策略，见 ADR-0001）。

## 页面行为

- 列表：显示组织名称与所属校区（缺失时显示缺失文案），点击进入详情。
- 详情：介绍、下设部门、职责、联系方式或缺失说明、动态或缺失说明；可返回列表。
- 未知 id：显示「未找到该部门」，可返回列表。
- 空名单：显示「暂无可查看的学生组织」（随包数据不为空，该分支由 `buildDepartmentList([])` 的测试覆盖）。
- 首页「学生部门」卡片文案由「资料整理中」改为「已可查看」，`aria-label` 同步。
